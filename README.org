* org-pwa
:PROPERTIES:
:CUSTOM_ID: org-pwa

A single-file, offline-capable, mobile-first outliner for editing ~.org~ files in the browser. No server, no account required to use it locally — just a static site you can install as a PWA and point at a file.

This document describes what org-pwa actually does today, how to use it, and — since that's usually the more useful question for anyone coming from Emacs — *where it deliberately or incidentally diverges from real org-mode.*

** What org-pwa is (and isn't)
:PROPERTIES:
:CUSTOM_ID: what-org-pwa-is-and-isnt
:END:

org-pwa is a *touch-first outline editor*, not a port of Emacs. It reads and writes real ~.org~ files — round-trip fidelity is a hard requirement, so content it doesn't specifically understand is preserved verbatim rather than mangled or dropped. But the /editing model/ is built from scratch around tapping and gestures, not Emacs keybindings, and it deliberately implements a useful subset of org-mode rather than all of it.

If you're looking for org-mode-in-the-browser with full parity — babel, LaTeX export, real Emacs Lisp — this isn't that (see [[#known-limitations--not-built-yet][Known limitations]]). If you want to open a real org file on your phone, reorganize your outline, check off tasks, edit tables, and get it saved back to disk, GitHub, or a WebDAV server, that's what this is for.

** Getting started
:PROPERTIES:
:CUSTOM_ID: getting-started
:END:

1. Open the app. If no file is open, tap *File → Open*.
2. Choose where to open from:

   - *Local file* — uses the browser's native file picker and keeps a live handle, so Save writes straight back to the same file. Requires a browser with File System Access support (Chrome/Edge on desktop and Android).
   - *GitHub* — browse folders and ~.org~ files in a repo you've configured in Settings, tap one to open it. A "Type a path instead…" option is always available too, for a path that doesn't show up in the listing (e.g. permissions on a specific subfolder) or if listing fails outright.
   - *WebDAV* — same idea, browsing a WebDAV server you've configured in Settings via the standard ~PROPFIND~ directory-listing method. Same "Type a path instead…" fallback available here too.
   - *Import file* (shown instead of "Local file" on platforms without File System Access, i.e. everything on iOS) — picks a file once and reads it; there's no live link back to the original, so Save downloads a new copy you place back manually. See [[#platform-support][Platform support]].

3. Edit. Every edit is applied instantly to an in-memory copy and cached locally in the background — nothing is lost if you close the tab, even before you hit Save.
4. Tap *Save* when you want it written back to wherever it came from. *Save As* lets you choose a different destination or backend.

The modeline (see [[#modeline][Modeline and minibuffer]]) shows the current filename, which backend it came from, and whether there are unsaved edits — the same information the tab bar (see [[#tabs][Tabs]]) also carries once a second tab is open, via a solid dot on any tab with unsaved changes.

** Editing your outline
:PROPERTIES:
:CUSTOM_ID: editing-your-outline
:END:

- *Headings*: tap the title to reveal twelve actions: edit title, edit the heading's body text, edit details (the general editor, below), add a sub-heading, TODO, move up and down, archive, attach (see [[#attachments][Attachments]]), delete, promote and demote. Most actions close the row after running; move up and down and promote and demote leave it open so you can repeat them. Tap elsewhere on the row to close it. *Delete* always confirms, listing what would be lost (dates, tags, properties, state history). Every delete or discard confirmation in the app (heading, table, note, list item, row or column, attachment, the recent-files list) has *Cancel* as the default, focused when the dialog opens, so a stray Enter, an interrupted tap or a tap on the backdrop never deletes.
- *TODO state*: tap the TODO badge to cycle the ~#+TODO:~ sequence (default ~TODO~, ~DONE~) one step at a time. The action menu's *TODO* button (~C-c C-t~) does the same, except that for a heading with no keyword in a file with more than one parallel ~#+TODO:~ workflow it opens a picker of every state of every workflow (see [[#progress-logging][Progress logging]]).
- *Fold and unfold*: tap the chevron to toggle a heading's subtree, or swipe left on a heading to cycle collapsed → children only → fully expanded.
- *Complete or archive*: swipe right. With an active TODO keyword it jumps straight to the sequence's first DONE-type keyword. Without one, including an already-DONE heading, it opens the Archive, Refile or Cancel prompt. An already-archived heading unarchives directly.
- *Archive* (*Unarchive* for an archived heading) moves the subtree to its ~org-archive-location~, or back to where it came from, after confirming the destination (see [[#archiving][Archiving]]). The ~:ARCHIVE:~ tag and ~ARCHIVE_*~ properties are ordinary once the move lands and can be edited or removed in the general editor.
- *Moving headings* (↑ ↓ ← →): ↑ and ↓ reorder a heading among its siblings, taking its subtree with it. ← promotes it one level, as a sibling right after its former parent. → demotes it one level, as the last child of the heading before it. At a boundary (first or last, top level, nothing to demote under) a brief status message says so.
- *The general editor* (📋 *Edit details*) is a popup form with four sections:
  - *SCHEDULED, DEADLINE and a plain timestamp*: date and time pickers, a repeat selector (every N hours, days, weeks, months or years) and an optional warning delay (~-3d~ shows a deadline three days early). The three are independent, each with its own *Clear*. See [[#agenda][Agenda]] for how a plain timestamp differs (it doesn't carry forward, and lives in the title).
  - *Tags*: removable chips (tap to remove) and an input with an *Add* button (Enter also adds). Suggestions appear as you type: every tag used in the open document or a loaded agenda file (most used first) plus tags declared on a ~#+TAGS:~ line, narrowed to what you typed and excluding tags the heading already has. One tap adds one.
  - *Priority*: buttons A, B, C and None. Priorities outside A to C aren't reachable here.
  - *Properties*: an editable key/value row for each, with a remove button and an *Add property* row. The Key field completes from every key used in the open document or a loaded agenda file (most used first) plus ones the app reads or writes (~CUSTOM_ID~, ~EFFORT~, ~Effort_ALL~, ~ID~, the ~ARCHIVE_*~ set); other keys still work. A row with a blank key is dropped on commit. This is also how you set a ~CUSTOM_ID~ for ~[[#id]]~-style links (see [[#links-and-images][Links and images]]).

  Three buttons govern all four sections: *Cancel* discards everything and closes, *Reset* restores every field to how it was when the editor opened, and *OK* commits all four and closes. Nothing is written until *OK*. Above them are three immediate actions. *Add table* inserts a table into the body and closes the editor. *Delete table* removes the heading's most recently added table after a confirmation, and is disabled when there is none. *Attach* closes the editor and opens the attachment picker (see [[#attachments][Attachments]]). If any field has changed, these three first ask *Commit and continue*, *Discard and continue* or *Keep editing*; with no changes they act at once.

  Existing properties also show as a small read-only line under the heading while drawers are visible for it (~#+STARTUP: showeverything~, or manually cycled to fully expanded; see [[#folding-and-startup][Folding and #+STARTUP]]). Tapping it opens the action menu.

- *Block content* (~#+BEGIN_SRC~, ~#+BEGIN_QUOTE~, ~#+BEGIN_EXAMPLE~ and so on) is shown read-only, under the same drawer-visibility rule as properties. Folded, it shows a "collapsed block" label: tap it to reveal the content, and tap it again to re-fold. Edit blocks in [[#the-plain-text-editor][Text view]]. Any ~#+BEGIN_NAME~ and ~#+END_NAME~ pair works, and three names are displayed specially:
  - ~QUOTE~: inline markup is interpreted, and the block is indented on both margins with a left border.
  - ~VERSE~: inline markup is interpreted, and every source line stays its own line.
  - ~CENTER~: inline markup is interpreted, and its paragraphs are centered.

  Everything else (~SRC~, ~EXAMPLE~, ~COMMENT~, custom names) is shown literally.

  On export (see [[#export][Export]]), ~SRC~ becomes a fenced code block with its language kept (~#+BEGIN_SRC python~ gives ```python), ~QUOTE~ becomes a blockquote, and ~COMMENT~ is dropped. Every other name exports as a plain fenced block, without ~VERSE~'s line preserving or ~CENTER~'s centering. A ~SRC~ language is kept only as that export hint: there is no syntax highlighting and no Babel execution (see [[#known-limitations--not-built-yet][Known limitations]]).

*** A heading's "text"
:PROPERTIES:
:CUSTOM_ID: a-headings-text
:END:

Org has no separate description field: everything after a heading, up to the next heading, belongs to it, and can include several paragraphs, lists and tables in any order. *Edit text* opens all of it as one block of raw org syntax in a popup, like Settings' *Menu labels* editor (see [[#menu-customization][Menu customization]]): a large textarea with *Cancel* (discard and close), *Reset* (reload the original text and keep the popup open) and *OK* (save and close). The heading's rendered body is hidden from the outline while the popup is open. Typing ~- [ ]~ at the start of a line becomes a checklist item on save, as in the file.

** Undo/redo and History
:PROPERTIES:
:CUSTOM_ID: undoredo-and-history
:END:

Every edit can be undone and redone: heading, paragraph, list-item and table-cell text, TODO state, priority, tags, properties, moving, promoting, archiving, capturing, all of it. The command palette's *Undo history* opens a panel with quick *‹ Undo* and *Redo ›* buttons for one step at a time, a scrollable list of every step since the file was opened (oldest to newest, current position marked), and a *diff* toggle on each entry showing what that step changed, as added and removed lines diffed against the step before it.

Tap *any* entry to jump straight there, forward or back. Entries past your position (available to redo) are dimmer. A genuinely new edit from an undone point discards what was ahead of it, as in most editors, but browsing the list, including jumping back and forward again, discards nothing.

Each step is a full snapshot of the document's text, one per completed edit action (saving a title, toggling a checkbox, archiving a heading) rather than one per keystroke. An edit that changes nothing, such as toggling something and toggling it back, gets no step.

History is unlimited while a file stays open. It also survives closing and reopening the file, capped at the 200 most recent steps, but only when the text on reopen exactly matches what the app last had: if the file changed in the meantime (edited elsewhere, on another device, or directly on GitHub or WebDAV), the old history is discarded. Undo and redo reapply the file's ~#+STARTUP~ visibility instead of preserving fold state across the jump.

Landing on a step whose text is identical to the last confirmed saved version (what the app last read or wrote) clears the filename's modified indicator. That baseline updates on every successful Save during the session.

*If the filename shows modified (red) and nothing you did explains it*, check the first history entry. If it reads "Opened (resumed unsaved local version)" instead of "Opened", the file had an unsaved edit from an earlier session, and reopening resumed it instead of starting from what is stored. Save to make that version the real one, or jump back in the history list if it wasn't what you wanted.

** Lists, tables, and body text
:PROPERTIES:
:CUSTOM_ID: lists-tables-and-body-text
:END:

- *Lists*: ordered, unordered, checkboxes, description lists (~term :: description~) and nested sub-lists. Tap an item's text for edit, add-below and delete actions.
- *Checkboxes* cycle unchecked → in-progress → done. A progress cookie in a heading's title (~[3/8]~, ~[40%]~, or the blank ~[/]~ and ~[/8]~) is recalculated whenever a checkbox in the heading's subtree changes, counting the heading's own list and every descendant heading's, as org does. A heading's ~:COOKIE_DATA:~ property changes what is counted: ~checkbox~ or ~todo~ picks which kind when a heading has both, both words count both kinds, and ~recursive~ with ~todo~ extends TODO counting to the whole subtree. Without it, only checkboxes are counted, recursively.
- *Tables*: tap a cell to edit it in place. A *⎌* button beside the field discards the edit and restores the cell's text, which is the way out on a phone, where there is no Escape key (~Escape~ also works with a hardware keyboard). Row and column add and remove controls sit below the table. ~#+TBLFM:~ formulas are evaluated (see [[#table-formulas][Table formulas]]). *Header rows* are the rows before the table's first horizontal rule (~|---+---|~) and render bold; a table with no rule has no header, and a later rule is only a group separator.
- *Paragraphs*: tap the text for edit, add-below and delete actions.
- *Captions, names and image sizes*: ~#+CAPTION:~, ~#+NAME:~, ~#+ATTR_HTML:~ (or ~#+ATTR_ORG:~), ~#+HEADER:~ and ~#+RESULTS:~ lines directly above a paragraph, image, table or block describe it. ~#+CAPTION:~ shows as an italic caption, with its inline markup rendered. ~#+ATTR_HTML: :width 300 :align center~ sizes and centers the images in that paragraph (a plain number is pixels; ~%~, ~em~ and similar lengths work). The other lines stay visible as small muted text, and every line is kept exactly as written.

Every delete asks for confirmation, and Undo/redo covers every edit (see [[#undoredo-and-history][Undo/redo and History]]).

*** Table formulas
:PROPERTIES:
:CUSTOM_ID: table-formulas
:END:

~#+TBLFM:~ formulas use a subset of org's formula language. Org hands anything beyond simple arithmetic to Emacs Calc, which is not reproduced here.

| Name | What it does |
|---+---|
| ~+ - * /~ | Arithmetic. Division by zero gives ~#ERROR~ |
| ~^~ | Exponent, right-associative (~2^3^2~ is 512) |
| ~sqrt(x)~ | Square root; a negative input gives ~#ERROR~ (no complex numbers) |
| ~floor(x)~, ~ceil(x)~, ~round(x)~, ~trunc(x)~ | Round toward −∞, toward +∞, to nearest (an exact .5 goes away from zero), toward zero. An optional second argument keeps that many decimals: ~round($1, 2)~ |
| ~sin(x)~, ~cos(x)~, ~tan(x)~ | Degrees by default (see the ~D~ and ~R~ flags) |
| ~arcsin(x)~, ~arccos(x)~, ~arctan(x)~ | Inverse trig, under Calc's names (not ~asin~); out-of-domain input gives ~#ERROR~ |
| ~ln(x)~, ~log10(x)~, ~log(x, base)~ | Logarithms; ~log(x)~ is natural. A non-positive ~x~, or a ~base~ of 0 or below or exactly 1, gives ~#ERROR~ |
| ~exp(x)~, ~exp10(x)~ | e^x and 10^x |
| ~pi~, ~inf~ | Constants, written bare; ~-inf~ works |
| ~$name~ | A constant from a ~#+CONSTANTS:~ line |
| ~vsum~, ~vmean~, ~vcount~, ~vmin~, ~vmax~, ~vmedian~ (~range~) | Sum, mean, count of non-blank cells, minimum, maximum, median |
| ~vvar~, ~vpvar~, ~vsdev~, ~vpsdev~ (~range~) | Sample and population variance and standard deviation. As in Calc, there is no plain ~variance~ or ~stddev~ |
| ~if(c,t,f)~ | ~t~ if ~c~ is true (non-zero or non-empty), else ~f~; only the chosen branch is evaluated |
| ~and(a,b)~, ~or(a,b)~, ~not(a)~ | Function forms of the logical operators; they don't short-circuit |
| ~string(ref)~ | A cell's raw text as a string |
| ~"text"~ | A string literal (~\"~ for a quote inside it) |
| ~date(ref)~, ~date(Y,M,D)~, ~now()~ | Date values (see below) |
| ~deg(x)~ | Turns an HMS duration back into a plain number of days |
| ~date-to-time(ref)~ | A date value from a wider range of date strings |
| ~format-time-string(fmt, time, utc)~ | Formats a time with ~%~ codes (see [[#capture-templates][Capture templates]]) |
| ~uconv(value, "from", "to")~ | Unit conversion (see below) |

*Logic*: comparisons (~==~ or ~=~, ~!=~, ~<~, ~>~, ~<=~, ~>=~) give ~1~ or ~0~. They bind tighter than ~&&~ and ~||~, which bind looser than ~+ - * /~, so ~$1 >= 50 && $2 >= 50~ means ~($1 >= 50) && ($2 >= 50)~. ~!x~ is logical NOT. ~&&~, ~||~ and ~if~ short-circuit, so ~if($1 != 0, 100 / $1, 0)~ never divides by zero. Nested ~if~ calls make an else-if chain: ~if($1 >= 90, "A", if($1 >= 80, "B", "C"))~. A string literal is text and ~string(ref)~ reads a cell as text, so ~string($1) == "Sales"~ compares text, where a bare ~$1 == "Sales"~ would try to read the cell as a number.

*Named constants*: a ~#+CONSTANTS:~ line anywhere in the file defines constants, used as ~$name~: ~#+CONSTANTS: c=299792458 g=9.81~. Names are space-separated, several lines combine, and a later value wins. An undefined ~$name~ gives ~#ERROR~. There is no built-in physical-constants library (org's optional ~constants.el~); only ~pi~ and ~inf~ are built in.

*Dates and times*: a cell holding an org timestamp (~[YYYY-MM-DD]~ or ~<YYYY-MM-DD>~, with an optional time and day name) is read as a date as soon as it is referenced, so ~$3 = $1 - $2~ subtracts two timestamp cells. Every component is range-checked (month 1 to 12, a day within that month's length with leap years, hour 0 to 23, minute 0 to 59), so ~<2026-06-34>~ gives ~#ERROR~. ~date(ref)~ differs from a bare reference only for a cell that isn't a timestamp: bare, it reads as an ordinary number; wrapped, it gives ~#ERROR~, which is useful when a formula should fail loudly. ~date(Y, M, D)~ builds a date from three numbers (~date(2028, 2, 29)~ is valid, ~date(2026, 2, 29)~ is not).

- Subtracting two dates gives days as an integer, or, if either has a time of day, a duration in Calc's HMS form (~8@ 30' 0"~ for 8.5 hours).
- Adding or subtracting a number shifts a date by that many days and writes it back as a timestamp: ~date($1) + 14~ gives ~<2026-09-08>~.
- ~deg()~ turns an HMS duration back into days for further arithmetic: ~deg(date($2) - date($1)) * 24;%.2f~ gives ~8.50~ hours.
- ~now()~ is the current date and time.
- ~date-to-time(ref)~, spelled as in Emacs, accepts every timestamp ~date()~ does, plus ISO 8601 (~2026-01-15T10:30:00Z~), RFC 822 (~Mon, 15 Jan 2026 10:30:00 GMT~) and US (~01/15/2026~) strings, parsed by the browser. An unparseable string gives ~#ERROR~.
- ~format-time-string(fmt, time, utc)~ uses the same ~%~ codes as capture templates: ~format-time-string("%Y-%m-%d", $1)~ gives ~2026-01-15~. ~time~ defaults to now and accepts a date value or a number of seconds since the Unix epoch. A non-zero ~utc~ formats in UTC (~%Z~ and ~%z~ then say UTC and +0000); otherwise the device's time zone is used.

*References*: ~$N~ is column N of the current row, ~@N$M~ is row N, column M, ~@-N~ and ~@+N~ are rows relative to the target, ~@<~, ~@>~, ~$<~ and ~$>~ are the first and last row or column, and a range such as ~$1..$3~ or ~@1$1..@3$2~ is an aggregate function's argument. A range may omit the column (~@2..@6~) to mean those rows in the formula's own column. Rows count every actual row, including the header; a horizontal rule has no row number. The column shorthand ~$M=~ (no ~@~, applied to every row) skips rows before the first horizontal rule, while an explicit ~@1$2=~ still changes that row. A table with no rule has no header, so nothing is skipped.

~@I~, ~@II~, ~@III~ refer to horizontal rules by repeated "I" characters, not Roman numerals (~@IIII~ is the fourth). An offset such as ~@III+2~ is the data row that many rows after (or, with ~-~, before) the rule. A range between two rules, ~vsum(@I..@II)~, covers the data rows strictly between them. A count past the last rule clamps to the end of the table.

*Targets*: a formula's target is one cell (~@N$M=~), a range (~@N$M..@N$M=~, applied to each cell; each end needs an explicit row) or a whole column (~$M=~). Several formulas in one ~#+TBLFM:~ line are separated by ~::~ and run in order, each seeing the earlier results. Only the first ~#+TBLFM:~ line directly below a table counts.

*Recalculating* is explicit. A *🔢 Calc* button below a table with a ~#+TBLFM:~ line recalculates that table. *Recalculate all tables* in the command palette (~org-table-recalculate-buffer-tables~, also usable in an Extras entry) recalculates every table as one undo step. A malformed formula is reported, and only its own table is skipped.

*Blank and non-numeric cells*: by default a blank cell in a direct reference (~$1+$2~) reads as 0 but is left out of a range, so ~vmean~ averages only the non-blank cells and ~vcount~ skips it. Text that isn't a number reads as ~nan~ and propagates, so a stray label shows a problem instead of a plausible wrong number (the ~N~ flag below reads it as 0).

*Mode flags*: a trailing ~;flags~ string after the expression:

| Flag | Effect |
|---+---|
| ~%.Nf~, ~fN~ | Fixed, N decimals (~%0.Nf~ also works): ~4.85;f2~ gives ~4.85~ |
| ~%d~ | Truncates toward zero: ~4.85~ gives ~4~ |
| ~nN~ | Normal notation, N significant figures: ~3.14159265;n5~ gives ~3.1416~ |
| ~sN~ | Scientific notation, N figures: ~123456.789;s3~ gives ~1.23e5~ |
| ~eN~ | Engineering notation (exponent a multiple of 3): ~123456.789;e3~ gives ~123e3~ |
| ~pN~ | Computes at N significant digits, in arbitrary precision (see [[#development][Development]]). Degree-mode trig is limited to about double precision, and sqrt of a negative still errors |
| ~E~ | Keeps a blank cell in a range (as ~nan~) and reads a blank direct reference as ~nan~ |
| ~N~ | Non-numeric text (with ~E~, blanks too) reads as 0 instead of ~nan~ |
| ~D~, ~R~ | Angle mode for the trig functions: degrees or radians. Degrees is the default, so ~D~ changes nothing |
| ~T~, ~U~, ~t~ | Duration mode. Cells matching ~HH:MM[:SS]~ (or a bare integer, in seconds) are read as durations, and the result is ~HH:MM:SS~ (~T~), ~HH:MM~ (~U~) or decimal hours to two places (~t~). Without a flag, ~HH:MM~ text isn't a duration. Negative durations work, and ~org-table-duration-hour-zero-padding~ (see [[#local-variables][Local Variables]], default on) pads the hours |
| ~F~ | Fraction mode: exact rational results (~1/3;F~ is exactly ~1/3~, and ~$1/$2;F~ on 3 and 6 is ~1/2~; a whole result shows without ~/1~). A function with a rational result stays exact (~sqrt(4);F~ is ~2~); otherwise a short approximation (denominator under 1,000,000) is shown |
| ~FS~ | Fraction mode as a mixed number: ~14/4;FS~ is ~3 + 1/2~. ~S~ alone does nothing, since general Symbolic mode isn't implemented |

An unrecognized flag is ignored. Examples:

#+begin_example
|  Task 1 |   Task 2 |    Total |
|---------+----------+----------|
|    2:12 |     1:47 | 03:59:00 |
|    2:12 |     1:47 |    03:59 |
| 3:02:20 | -2:07:00 |     0.92 |
#+TBLFM: @2$3=$1+$2;T::@3$3=$1+$2;U::@4$3=$1+$2;t
#+end_example

#+begin_example
| Top | Bottom | Fraction | Mixed number |
|-----+--------+----------+--------------|
|   3 |      6 | 1/2      | 1/2          |
|  12 |      9 | 4/3      | 1 + 1/3      |
|  14 |      4 | 7/2      | 3 + 1/2      |
#+TBLFM: $3=$1/$2;F::$4=$1/$2;FS
#+end_example

*Errors*: a formula that fails when evaluated (an out-of-range reference, a range where one value is expected) writes ~#ERROR~ into that one cell, and the rest of the table still updates. A formula that can't be parsed (bad syntax, an unknown function) is reported for the whole recalculation.

*Raw Elisp*: a formula starting with a quote, like org's ~'(function-name arg ...)~, bypasses the grammar above. One function is supported, ~orgtbl-ascii-draw(value, min, max, width)~, which draws a bar in the cell using org's 11-character gradient. A ~value~ outside ~[min, max]~ shows ~too small~ or ~too large~, and ~width~ defaults to 12. Each argument may be a number, a ~$N~ reference or a parenthesized expression such as ~($2 * 2)~.

*Unit conversion*: ~uconv(value, "from", "to")~, such as ~uconv($1, "mi/hr", "m/s")~, uses the mathjs unit library (see Development). It handles compound units (~kg/m^3~) and converts temperature as an absolute reading (~0 degC~ is ~32 degF~, like Calc's ~u t~ command rather than the relative change of ~u c~). Unlike Calc's two-argument form, the source unit is explicit. An incompatible pair (~m~ to ~kg~) or an unknown unit gives ~#ERROR~. Common units: length (~m~, ~ft~, ~km~, ~mi~, ~in~, ~cm~), mass (~kg~, ~lb~, ~g~, ~oz~), temperature (~degC~, ~degF~, ~K~), volume (~L~, ~gal~, ~mL~), time (~s~, ~min~, ~hr~, ~day~), speed (~mi/hr~, ~m/s~), data (~MB~, ~GB~), pressure (~bar~, ~psi~, ~atm~), energy (~J~, ~kWh~) and area (~m^2~, ~acre~). Names mostly match Calc's; ~tsp~ and ~tbsp~ are aliases for mathjs's ~teaspoon~ and ~tablespoon~. The full list is at https://mathjs.org/docs/datatypes/units.html.

Out of scope: Emacs Calc beyond the above (complex numbers, matrices, symbolic algebra), named-field references, and recalculation on every keystroke.

*** Plots
:PROPERTIES:
:CUSTOM_ID: plots
:END:

A ~#+PLOT:~ line directly above a table (several stacked lines combine their options) graphs the table's data. A *📊 Plot* button below the table, beside *🔢 Calc* when present, shows the graph inline, and tapping it again hides it. This is a subset of org-plot: it reads org-plot's own ~#+PLOT:~ options, so an unmodified line works, but it renders inline SVG instead of calling gnuplot.

~type:2d~ (the default) and ~type:radar~ are supported; ~type:3d~ and ~type:grid~ are refused with an error. For 2d, ~with:~ picks ~lines~ (the default), ~points~, ~boxes~ (~histograms~ renders the same) or ~impulses~.

| Option | Meaning |
|---+---|
| ~title~ | A quoted string |
| ~ind~ | The 1-based column giving the x position (2d) or the axis label (radar); default 1 |
| ~deps~ | A parenthesized list of 1-based columns to plot; default every column except ~ind~ |
| ~labels~ | A parenthesized list of quoted series names; default the header row |
| ~transpose~, ~trans~ | ~yes~, ~y~ or ~t~ swaps rows and columns first, which is how a radar chart gets its axes from columns |
| ~min~, ~max~ | The y range (2d), or the shared range of every radar axis |
| ~xmin~, ~xmax~ | The x range (2d, when ~ind~ is numeric) |
| ~ticks~ | The number of y gridlines; default 5 |

org-plot's gnuplot scripting options (~set~, ~line~, ~script~, ~file~, ~map~, ~timefmt~) are accepted but have no effect, so a copied line never errors.

The graph is cached for each ~#+PLOT:~ line and its table data, so showing it again is instant, and editing the table re-renders it the next time it is shown. It follows the heading's fold state: collapsing the heading hides the graph, and after expanding it the *Plot* button needs a fresh tap, as with contact photos (see [[#local-variables][~org-xx-startup-with-show-photos~]]).

** Inline text markup
:PROPERTIES:
:CUSTOM_ID: inline-text-markup
:END:

All six of org's emphasis markers work in headings, paragraphs and list items:

| Markup | Syntax | Renders as |
|---+---+---|
| Bold | ~*bold text*~ | *bold text* |
| Italic | ~/italic text/~ | /italic text/ |
| Underline | ~_underline text_~ | underlined |
| Strikethrough | ~+strikethrough text+~ | +strikethrough text+ |
| Verbatim | ~=verbatim text=~ | ~verbatim text~ (literal, not further parsed) |
| Code | =~code text~= | ~code text~ (literal, not further parsed) |

A marker opens where it follows the start of a line, whitespace or one of ~-({'"~ and isn't followed by whitespace. It closes where it isn't preceded by whitespace and is followed by the end of the line, whitespace or closing punctuation. These are org's border rules for the common cases, not its full border-character tables. Bold, italic, underline and strikethrough nest (~*bold /italic/ bold*~); verbatim and code never do, and their content is literal.

*Horizontal rule*: a line of only dashes, at least five (~-----~), is a horizontal rule. Whitespace around the dashes is fine; any other character on the line makes it a paragraph.

*Hard line break*: a line ending in two backslashes (~\\~) is org's explicit line break. Source lines in an ordinary paragraph or list item otherwise reflow together with a space (org's ~org-export-preserve-breaks~ is ~nil~ by default). The marker forces a break exactly where it is written, in paragraphs, [[#editing-your-outline][QUOTE or CENTER blocks]] and all four document export formats (HTML, Markdown, ASCII, ODT).

*Subscript and superscript*: ~_~ and ~^~ mark them. ~x_i~ and ~x^2~ work without braces, and braces (~x_{alpha}~, ~10^{100}~) are always accepted, mainly for readability. ~org-use-sub-superscripts~ (see [[#local-variables][Local Variables]]) controls them:

| Value | Behavior |
|---+---|
| ~t~ (default) | Both ~x_i~ and ~x_{i}~ are interpreted |
| ~{}~ | Only the braced form ~x_{i}~ is interpreted; a bare ~x_i~ stays literal text |
| ~nil~ | Disabled entirely; ~_~ / ~^~ are always literal characters |

~_~ also marks underline, as in org. The two are told apart by what precedes it: underline needs whitespace, a line start or certain punctuation before it (~_underlined_~), and subscript needs a non-space character (~a_b~). Script content is literal: ~x_{*bold*}~ doesn't interpret the ~*bold*~.

*Footnotes*: ~[fn:label]~ is a reference, shown as a small tappable superscript that jumps to, and briefly highlights, the definition anywhere in the document, even under a folded heading. A definition can be inline at the reference, ~[fn:label:the note text]~, or anonymous, ~[fn::an anonymous note]~, and inline text renders in place, smaller and in italics. A separate line starting ~[fn:label]~ (like ~[fn:1] The actual definition.~) is also a definition, shown with a small label. Markdown export uses GFM's ~[^label]~ and ~[^label]: text~, and HTML export uses a jump-linked superscript with a back-linked Footnotes section.

Table cells render inline markup too. Tap a cell to see and edit its raw text, and tap away or tap another cell to commit (see [[#editing-your-outline][Editing your outline]]).

*** LaTeX math fragments
:PROPERTIES:
:CUSTOM_ID: latex-fragments
:END:

Math in a heading, paragraph or list item renders as typeset math with [[https://katex.org][KaTeX]], vendored locally (no CDN). It is display-only: the ~.org~ file's text is untouched, and editing shows the raw source.

| Delimiter | Kind | Restrictions |
|---+---+---|
| ~\(...\)~ | Inline | None — org's own recommended form |
| ~\[...\]~ | Display | None |
| ~$$...$$~ | Display | None |
| ~$...$~ | Inline | No whitespace directly inside the delimiters; the closing ~$~ must be followed by whitespace or punctuation, but never a dash (avoiding ~$5-10~ reading as math) |
| ~\begin{env}...\end{env}~ | Display | ~\begin~ must start a line, preceded by nothing but whitespace |

~$...$~ avoids misreading currency: ~costs $5 and $10 total~ stays plain text. The opening ~$~ may follow any character except another ~$~ (or the start of the line). The first content character can't be a space, tab, newline, comma, semicolon or period, and the character before the closing ~$~ can't be a space, tab, newline, comma or period (a semicolon is allowed). It needs at least two characters of content, so ~$x$~ doesn't match; use ~\(x\)~ for a single character.

~\(...\)~, ~\[...\]~, ~$$...$$~ and ~\begin{env}...\end{env}~ can span any number of lines, even across a blank line (an ~align~ environment with a blank line between rows). ~$...$~ allows at most two embedded newlines. KaTeX doesn't treat ~%~ as a comment, so text after it renders literally. A fragment KaTeX can't render (an unsupported command, a syntax error) shows its raw source with a dashed border, without breaking the paragraph. KaTeX supports a large subset of LaTeX, not all of it.

Math renders wherever inline markup does: the outline, the read-only Docs viewer and HTML export (KaTeX's CSS is inlined only into an export that contains math). Markdown, ASCII and ODT export pass the raw LaTeX through as text.

*Examples*: the source ~The quadratic formula is \(x = \frac{-b \pm \sqrt{b^2-4ac}}{2a}\).~ renders inline with a proper fraction bar and a square-root radical. This ~align~ environment:

#+BEGIN_SRC
\begin{align}
E &= mc^2 \\
F &= ma \\
a^2 + b^2 &= c^2
\end{align}
#+END_SRC

renders three right-aligned equations, lined up at the ~&~ marks and automatically numbered (1) to (3), which is KaTeX's own behavior for ~align~. The ~\\~ ending a line there ends an equation; it is unrelated to org's hard line break above.

** Searching
:PROPERTIES:
:CUSTOM_ID: searching
:END:

Open the command palette's *Search* (or god-mode's ~s~, see [[#keybindings][Keybindings]]) to search the open document, case-insensitively: headings, tags, TODO keyword, priority, properties (key or value), SCHEDULED and DEADLINE timestamps, paragraphs, list items, table cells and block content. When any are configured it also searches every file in ~org-agenda-files~.

Results appear at once from what is already loaded and fill in as each agenda file finishes loading; a file that fails to fetch is left out. The query box and its options live in the minibuffer at the bottom of the screen (see [[#modeline][Modeline and minibuffer]]). Results update as you type, grouped under the heading each belongs to, with a snippet that highlights the matched keyword. A result from another file shows that file's name.

Search covers the whole document whatever the fold state: a match inside a collapsed heading, hidden body text, a folded drawer or a block still shows up. Tapping a result expands what is needed to reveal it (the heading's body, and its drawers for a property or block match), scrolls to it with a brief highlight, and switches to that file first when the result came from another one.

*** Filter tokens

Tokens in the query box combine as an implicit AND:

- ~word~ or ~+word~: the entry (title, tags, TODO state, priority, properties, planning and body text) must contain it. ~-word~ excludes entries that contain it. ~+computer +wifi -ethernet~, or just ~computer wifi -ethernet~, finds entries with "computer" and "wifi" but not "ethernet", as in org's ~org-search-view~. So a query like ~-5~ means "exclude entries containing 5", not the literal text; use Regex mode for that.
- ~tag:urgent~: the heading must have this tag, inherited tags included. ~-tag:urgent~ excludes it.
- ~todo:KEYWORD~: the TODO state must equal this (case-insensitive), as in ~todo:WAITING~. ~-todo:KEYWORD~ excludes it; a heading with no keyword passes an exclude.
- ~priority:X~: the priority must equal this, as in ~priority:A~. ~-priority:X~ excludes it.
- ~key:value~: any other ~key:value~ matches a property ~key~ whose value contains ~value~ (substring, case-insensitive), such as ~spouse:Mary~. ~-key:value~ excludes it.
- ~|~ inside ~tag:~, ~todo:~, ~priority:~ or ~key:value~ means "any of these": ~tag:urgent|blocked~, ~todo:TODO|WAITING~, ~assignee:Bob|Alice~. Negated, it means "none of these". It combines alternatives only within one filter. There is no OR between filters and no grouping; Match mode has both.

A word starting with ~+~ or ~-~ (a negative number, a hyphenated word) or shaped ~word:word~ (such as a ~mailto:~ link) can be read as a filter instead of text. ~http://~ and ~https://~ URLs are not. Tag inheritance is on by default and property inheritance off, as in org (see [[#differences-from-emacs-org-mode][Differences from Emacs org-mode]] and the ~org-use-tag-inheritance~ and ~org-use-property-inheritance~ variables). A query with only excludes or filters and no keyword (~tag:work -someday~) returns the matching headings directly. The box's placeholder, ~Search, +word -word, or [tag|todo|priority|key]:value…~, is a reminder of the pattern.

Example: ~+work todo:WAITING budget~ finds entries tagged ~work~, in WAITING state, containing "budget".

*** Regex mode

The *Regex* toggle in the minibuffer switches from plain substring matching to a regular expression, case-insensitive either way, in Emacs's syntax rather than JavaScript's. The biggest difference: an unescaped ~(~, ~)~, ~{~, ~}~ or ~|~ is literal, and grouping needs ~\(~ and ~\)~, alternation ~\|~, and an interval ~\{n,m\}~. With Regex off, a ~.~ or ~(~ in the query simply matches that character.

Supported: backreferences (~\1~ to ~\9~), word and symbol boundaries (~\<~, ~\>~, ~\_<~, ~\_>~, ~\b~, ~\B~), POSIX classes in brackets (~[[:digit:]]~, ~[[:alpha:]]~) and whole-string anchors (~\`~ and ~\'~, distinct from the line anchors ~^~ and ~$~). Constructs that depend on a buffer's syntax table (~\s<~, ~\s>~, ~\sc~, ~\S-~ and similar) aren't supported and show an error naming the construct. An invalid pattern shows a clear error, so it is never mistaken for "no matches".

Example: ~^\(Buy\|Fix\)~ finds headings whose title starts with "Buy" or "Fix".

*** Match mode

*Match*, beside *Regex* in the options popover (the ~⋯~ button at the search bar's right edge, which shows a check mark by the active one and a dot when either is on), uses org's tag and property match grammar, the one behind ~C-c / m~. Match and Regex are mutually exclusive.

~|~ is the lowest-precedence operator and splits the query into OR'd groups. Within a group, ~+family~ (or a bare ~family~) and ~-work~ combine as AND, so ~family+work|urgent~ means "(family AND work) OR urgent". A condition can also compare a property, ~PROPERTY="value"~ with ~=~, ~<>~, ~<~, ~>~, ~<=~ or ~>=~, combined freely with tags (~work+PRIORITY_TEST="B"~). ~TODO~, ~LEVEL~, ~PRIORITY~ and ~CATEGORY~ work as pseudo-properties, as in org. An empty query, an empty group beside a stray ~|~, or an unparseable condition gives a clear error. Replace is disabled in this mode.

Example: ~work+urgent|blocked~ finds headings tagged both ~work~ and ~urgent~, or tagged ~blocked~.

*** Search and replace

The options button (~⋯~) also shows *Replace*, which starts an Emacs-style ~query-replace~ (or ~query-replace-regexp~, following the Regex toggle) with the search text as the pattern. It walks every [[#agenda-files][Agenda Files]] file that has a match, starting with the open one, and a file it enters opens as its own tab. It asks for the replacement text, then offers each match:

| Key | Action |
|---+---|
| ~y~ or Space | Replace this one and go on |
| ~n~ or Delete | Skip it |
| ~q~ or Return | Stop the walk (replacements already made stay; the rest is untouched) |
| ~.~ | Replace this one and stop |
| ~!~ | Replace all remaining matches in the current file, then go on to the next file with a match |

Buttons for all five sit beside the prompt for devices without a keyboard. ~$1~ to ~$9~ in the replacement text are filled from the match's capture groups. As in Emacs, nothing is saved automatically: each touched file is changed but unsaved, shown by its tab's modified indicator. A configured agenda file that can't be reached (a local file not already open) is left out; only open files and GitHub or WebDAV files can be walked.

Replace works on heading titles, paragraphs, list items and table cells. Tags, TODO state, priority, properties, planning timestamps and block content (~#+BEGIN_VERSE~, ~#+BEGIN_QUOTE~ and the like) are never replaced, because that could corrupt the document's syntax. Search still finds text inside blocks, and when all of a query's matches are inside block content, Replace says so ("N matches found only inside block content... not editable here; use Text view instead"). [[#the-plain-text-editor][Text view]]'s own search and replace has no such restriction and stays within that one document.

*** Narrow

When at least one match is in the open document, the results show *Narrow* with a count of those matches (cross-file results aren't counted). It works with any search mode. Tapping it restricts the outline to the matching headings plus their ancestors, so each match keeps its context, and a banner shows the count with a *Widen* button. It composes with [[#narrowing][subtree narrowing]]: narrow to a subtree, then to matches within it. Like subtree narrowing it survives a reload, and a heading renamed or removed in the meantime simply drops out.

Org's own search is several separate tools: sparse trees (~C-c /~), a match grammar, and ~org-search-view~. Here one box covers tags, TODO state, priority, properties and free text together, with Match mode for the fuller boolean grammar. Not included: sparse-tree-style in-place refolding; Narrow is the nearest equivalent.

** Modeline and minibuffer
:PROPERTIES:
:CUSTOM_ID: modeline
:END:

A fixed two-row bar at the bottom of the screen, laid out like Emacs's frame: a dense modeline above a minibuffer.

*The modeline* is read-only, monospace and terse:

- *Modified indicator*: ~--~ unmodified, ~**~ modified, ~%%~ read-only, ~%*~ read-only and modified, Emacs's four states. Emacs's coding-system and line-ending segment is omitted, since the app always writes UTF-8 with Unix line endings.
- *Buffer name*: the document's name plus a suffix, ~(GitHub)~, ~(WebDAV)~, ~(Local)~ or ~(Imported)~.
- *Position*: ~Top~, ~Bot~, ~All~ or a percentage for how far down the visible area is, plus ~L~ and the line number when a heading is focused, and ~C~ and the column only while a text field is being edited. The app has no persistent cursor between edits, so otherwise there is no real column to show.
- *Date and time*, when ~display-time-mode~ is on (the default): formatted by ~display-time-format~ (default ~"%H:%M"~), using the same ~%<FORMAT>~ subset as [[#capture-templates][Capture templates]]. It updates at least every 30 seconds.
- *Clock*, when a clock is running anywhere in the document: the elapsed time of this clock-in in brackets, then the heading's title, like ~[⏱ 0:35] Write the quarterly report~. It shows the current session, not the task's lifetime total.

*The minibuffer*, below it, is the one strip for the status line, god-mode's chord echo and the search box (see [[#searching][Searching]]). Only one shows at a time: the search box while search is open, then the god-mode echo while a chord is in progress or has just completed (the chord and its command's name; see [[#god-mode][God-mode]]), and otherwise the last status message. A status message clears at your next keypress or tap, as Emacs's echo area clears at each new command.

Two variables control it, set in Global or Local Variables or in Settings → Quick Settings → *Modeline*:

| Variable | Default | Effect |
|---+---+---|
| ~display-time-mode~ | ~1~ (on) | Emacs's minor-mode toggle, with its ~1~ and ~0~ convention instead of ~t~ and ~nil~. ~0~ hides the date and time. |
| ~display-time-format~ | ~"%H:%M"~ | Emacs's variable and default. Any ~%<FORMAT>~ token that [[#capture-templates][Capture templates]] support works. |

** Links and images
:PROPERTIES:
:CUSTOM_ID: links-and-images
:END:

- ~[[target][description]]~ links render as tappable text.
- *Bare URLs* link too: ~https://example.com~ typed in a sentence, or wrapped as ~<https://example.com>~. The recognized schemes are ~http~, ~https~, ~ftp~, ~mailto~, ~doi~, ~file~, ~github~ and ~webdav~, so a time like ~10:30~ or a ratio like ~3:4~ is never read as a link. Trailing sentence punctuation (~.~, ~,~, ~)~) is left out: ~see https://example.com/page.~ links the URL without the period. Wrap a URL in ~<...>~ or ~[[...]]~ if it must end in one of those characters.
- ~doi:10.1145/1327452.1327492~ resolves to ~https://doi.org/...~ and opens like any external link, bracketed or bare.
- *Internal links* resolve by heading title (~[[*Some Heading]]~), by ~CUSTOM_ID~ (~[[#my-id]]~), or by a title search for bare text. Tapping one expands the ancestors and scrolls to the target. Set a ~CUSTOM_ID~ in the general editor (see [[#editing-your-outline][Editing your outline]]).
- *The ⏎ button*: after you follow a link, a floating ⏎ button appears at bottom-left to go back, so a document with a table of contents (Docs' own included) is navigable on a touch device without a browser Back. Chained links unwind one hop at a time, and the button disappears when there is nowhere left to go back to. It is low-opacity at rest and uses the theme's text colours.
- *Image links*: ~http://~ and ~https://~ image links render inline when ~#+STARTUP: inlineimages~ is set (off by default).
- *Local and relative image paths* on GitHub and WebDAV render too: ~[[photo.png]]~, ~[[images/photo.png]]~, ~[[file:photo.png]]~ and ~[[github:images/photo.png]]~ resolve relative to the document's path (a bare filename lands beside it), under the same ~#+STARTUP: inlineimages~ gate, and are cached for the session. Local files (File System Access) and iOS imports show an ~[image: path]~ placeholder instead, because reading a sibling file needs browser permission that can't be granted mid-render.
- *~file:~, ~github:~ and ~webdav:~ links* parse into a scheme, a path and an optional in-file target, using org's ~::~ convention: an absolute path (~file:/home/user/documents/notes.org~), a relative one (~file:projects/todo.org~), a headline (=file:~/notes.org::*Project Alpha=) or a text search (=file:~/notes.org::exact phrase=). Tapping one opens the document, as File → Open does (with its unsaved-changes handling), and jumps to the headline or match. A path with no scheme uses the backend the current document came from; an explicit ~github:~ or ~webdav:~ always uses that backend.

  The back button follows these links across documents: it returns to the heading the link was in, with its ancestors and body expanded, found by the heading's title path (a scroll offset wouldn't survive a re-parse). It falls back to the remembered scroll position when the link had no heading (it was in the preamble) or the heading has since been renamed or removed. This works only when both documents are on GitHub or WebDAV. A local file or iOS import can't be reopened from a link tap or the back button, because opening a path needs a file-picker gesture the browser requires for each file, so a clear message is shown instead.
- *~attachment:~ links* are org-attach's link type, produced by *Attach* (see [[#attachments][Attachments]]). They are bracketed only (~[[attachment:photo.jpg]]~); a bare ~attachment:photo.jpg~ in text is not a link.

** Configuration
:PROPERTIES:
:CUSTOM_ID: configuration
:END:

Three layers set variables (Emacs Lisp variables or org directives), resolved in org's own precedence: *Local Variables beats #+STARTUP beats Global Variables*. A variable set at a higher layer wins for that file, and one left unset falls through to the next layer down.

1. *Global Variables* ([[#global-variables][below]]): an app-wide baseline, set in Settings.
2. *~#+STARTUP:~* ([[#folding-and-startup][below]]): a file's own directive. Only three variables have a ~#+STARTUP:~ shorthand, as in real org:

| Variable | ~#+STARTUP:~ keyword(s) |
|---+---|
| ~org-log-done~ | ~logdone~ (→ ~time~), ~lognotedone~ (→ ~note~) |
| ~org-startup-folded~ | ~overview~, ~content~, ~showall~, ~showeverything~, ~show2levels~, ~show3levels~, ~show4levels~, ~show5levels~ |
| ~org-startup-with-inline-images~ | ~inlineimages~ (→ ~t~), ~noinlineimages~ (→ ~nil~) |

3. *Local Variables* ([[#local-variables][below]]): a file's own ~# Local Variables:~ block, a general Emacs mechanism processed last.

-----

*** Global Variables
:PROPERTIES:
:CUSTOM_ID: global-variables
:END:

Set in *Settings → Global Variables*. This is the lowest layer, and the only one not stored in a ~.org~ file. The format is one ~name: value~ per line, like a [[#local-variables][Local Variables]] block without its wrapper:

#+BEGIN_SRC
org-log-done: 'time
org-agenda-start-on-weekday: 1
#+END_SRC

Every Local Variables variable works here too, at app-wide precedence. Changes take effect on *Save*, with no reload, and they are part of *Export Settings* and *Import Settings…* (see [[#file-management][File management]]).

*Smart quotes are normalized*: iOS and many Android keyboards replace a typed straight quote with a curly one, but quote-delimited values here (~org-xx-extra-menu~, ~org-xx-menu-aliases~ and the [[#capture-templates][Capture Templates]] JSON) need the ASCII character. Quick Settings, this text box and Capture Templates convert curly quotes back to straight ones on save. Quotes in ordinary prose elsewhere are untouched.

*** Folding and ~#+STARTUP~
:PROPERTIES:
:CUSTOM_ID: folding-and-startup
:END:

org-pwa applies ~#+STARTUP:~ directives, typically on the first line. They can share a line or be spread across several, and the last matching keyword wins.

| Category | Keywords | Default |
|---+---+---|
| Heading visibility | ~overview~, ~content~, ~showall~, ~showeverything~, ~show2levels~, ~show3levels~, ~show4levels~, ~show5levels~ | ~showeverything~ |
| Inline images | ~inlineimages~, ~noinlineimages~ | ~noinlineimages~ |
| Progress logging on DONE | ~logdone~, ~lognotedone~ | neither (no logging) |

- ~overview~: only top-level headings, everything else folded.
- ~show2levels~ to ~show5levels~: like ~overview~ with that cutoff depth. Headings are shown through that level with no body text at any visible level, and deeper levels are folded.
- ~content~: every heading line shown, but body text (paragraphs, lists, tables) and properties hidden until you open a heading.
- ~showall~: body text, lists and tables shown. Property drawers (~:PROPERTIES:~) and blocks (~#+BEGIN_SRC~, ~#+BEGIN_QUOTE~ and the like) stay folded, one line each.
- ~showeverything~: ~showall~ plus drawers and blocks fully expanded.
- ~logdone~, ~lognotedone~: set ~org-log-done~ to ~time~ or ~note~ (see [[#progress-logging][Progress logging]]).

Cycling a heading to fully expanded (slide-left, or tapping through the fold states) always reveals its properties and blocks, whatever ~#+STARTUP:~ says, and collapsing it hides them again. The defaults match org's own: with no ~#+STARTUP~ line, everything is shown. Archived-heading cycling is a separate mechanism (see [[#local-variables][Local Variables]]).

*** Local Variables
:PROPERTIES:
:CUSTOM_ID: local-variables
:END:

Two forms, both general Emacs mechanisms: a first-line ~-*- var: val; -*-~ cookie, and a ~# Local Variables: ... # End:~ block, conventionally at the end of the file. Both can appear in one file, and the block wins a conflict. Most variables below also have a labeled control in Settings → *Quick Settings* (see [[#settings][Settings]]) for the app-wide baseline.

#+BEGIN_SRC
# -*- buffer-read-only: t; -*-
#+END_SRC

#+BEGIN_SRC
# Local Variables:
# org-agenda-start-on-weekday: 1
# org-cycle-open-archived-trees: nil
# org-agenda-skip-comment-trees: t
# org-agenda-skip-archived-trees: t
# End:
#+END_SRC

The recognized variables, alphabetically. Those marked "(own)" are this app's extensions, not real org variables. Booleans are Lisp ~t~ or ~nil~, not JavaScript truthiness: the string ~"true"~ is not ~t~.

| Variable | Default | What it does |
|---+---+---|
| ~buffer-read-only~ | ~nil~ | Whether the buffer is read-only (see [[#keybindings][Keybindings]]: ~C-x C-q~, or *Toggle read-only* in the command palette) |
| ~calendar-latitude~ | ~35.994~ | Latitude for the solar forms and ~org-weather~ (Durham, NC) |
| ~calendar-longitude~ | ~-78.8986~ | Longitude for the same (Durham, NC) |
| ~org-agenda-files~ | unset (current file only) | Semicolon-separated ~scheme:path~ entries: more files for the Agenda and TODO views (see [[#agenda-files][Agenda Files]]) |
| ~org-agenda-skip-archived-trees~ | ~t~ | Exclude archived headings (tagged ~:ARCHIVE:~) from the agenda; ~nil~ includes them |
| ~org-agenda-skip-comment-trees~ | ~t~ | Exclude commented headings (a title starting ~#~ and a space, like ~** # draft~) from the agenda. They stay visible in the outline; ~nil~ includes them |
| ~org-agenda-start-on-weekday~ | ~1~ (Monday) | The Week view's first day: ~0~ is Sunday through ~6~ Saturday. An out-of-range value falls back to Monday |
| ~org-ascii-text-width~ | ~72~ | Wrap width, in characters, for ASCII export |
| ~org-closed-keep-when-no-todo~ | ~nil~ | ~t~ keeps a CLOSED timestamp when a DONE heading is cycled back to no keyword. Cycling to another keyword always removes it (see [[#progress-logging][Progress logging]]) |
| ~org-contacts-birthday-property~ | ~BIRTHDAY~ | The property ~org-contacts-anniversaries~ reads, as a plain string (~# org-contacts-birthday-property: EVENT~) |

** Progress logging
:PROPERTIES:
:CUSTOM_ID: progress-logging
:END:

Two related mechanisms write into the same place: a heading's ~:LOGBOOK:~ drawer, org's running history of state changes and notes, kept apart from the body.

*** ~org-log-done~

Set by ~#+STARTUP: logdone~ or ~#+STARTUP: lognotedone~ (see [[#folding-and-startup][Folding and #+STARTUP]]), it controls what happens when a heading enters a DONE-type state (tapping the TODO badge to cycle there, or the action menu toggle). The two modes are mutually exclusive:

- ~logdone~ (~time~) inserts a ~CLOSED: [timestamp]~ planning line when a heading becomes DONE. Cycling it to a non-done keyword removes the timestamp, and cycling it back to no keyword also removes it unless ~org-closed-keep-when-no-todo~ is set (see [[#local-variables][Local Variables]]). Re-marking a done heading with a *different* done keyword (DONE to KILL) doesn't add or disturb a timestamp.
- ~lognotedone~ (~note~) prompts for a note in a small panel when a heading becomes DONE. The badge flips at once and never waits for the note, so *Skip* only declines to add one. A saved note becomes a timestamped ~:LOGBOOK:~ entry.

They apply to a plain DONE-type keyword with no logging spec of its own, and a file has one or the other as its default. With neither, which is the default as in org, entering DONE inserts nothing extra.

*** The per-keyword logging spec

The more general mechanism applies to any keyword, not only done ones, and overrides ~org-log-done~ for that keyword. It uses the parenthesized fast-key syntax in ~#+TODO:~:

#+BEGIN_SRC
#+TODO: TODO(t) WAIT(w@/!) | DONE(d!) KILL(k@)
#+END_SRC

Four markers, each optional, as in org:

| Marker | Meaning |
|---+---|
| ~!~ | Log a timestamp when *entering* this state |
| ~@~ | Log a note (prompted for, same panel as ~org-log-done~'s own) when *entering* this state |
| ~@/!~ | Log a note when entering, /and/ a timestamp when *leaving* — conditionally, see below |
| ~/!~ | Log a timestamp only when *leaving* this state — no logging on entering it at all |

A leaving-log (~@/!~ or ~/!~) fires only if the target state doesn't already log something on entry. In the example, WAIT to DONE fires nothing extra from WAIT's ~/!~, because DONE already logs a timestamp on entry (~d!~). WAIT to TODO does fire it, since TODO logs nothing of its own and the move would otherwise go unrecorded.

An explicit per-keyword spec always beats ~org-log-done~, which only fills in for a done-type keyword with no spec. Both can fire for one transition (a ~CLOSED~ timestamp and a ~:LOGBOOK:~ entry), which can look redundant but is org's behavior.

*Fast-access keys* (the letter before any ~@~ or ~!~, as in ~TODO(t)~) are parsed, so a ~#+TODO:~ line using them doesn't break TODO recognition. A ~#+TODO:~ line with no ~|~ treats its last keyword as the only done state, as in org.

*Parallel workflows*: several ~#+TODO:~ lines in one file (~#+TODO: TODO(t) | DONE(d)~ then ~#+TODO: REPORT(r) BUG(b) KNOWNCAUSE(k) | FIXED(f)~) define coexisting workflows, as in org. Tapping the badge cycles within the sequence a heading's keyword already belongs to. For a heading with no TODO state, the badge, the action menu's *TODO* button and ~C-c C-t~ all behave alike: with one workflow they cycle as usual, and with more than one they open a picker showing every state of every workflow, one row per sequence, so you can jump to any state. Each sequence's first state (where a fresh heading starts) is green and its done-type states are red, since a workflow can wrap onto several lines and the last button isn't always its end. *Clear* resets the heading to blank, and *Cancel* dismisses the picker unchanged. ~#+SEQ_TODO:~ and ~#+TYP_TODO:~ are read the same way as ~#+TODO:~.

*** The ~:LOGBOOK:~ drawer

Shown under a heading like ~:PROPERTIES:~, with the same visibility rule (hidden by default unless ~#+STARTUP: showeverything~ or the heading is swiped fully open) and the same read-only, tap-for-the-action-menu treatment. A state change shows the transition and timestamp (~WAIT → DONE   [timestamp]~), and a note appears indented in italics beneath it. Entries follow org's default log format, including leaving out the "from" clause when there was no previous state and continuing multi-line notes with a trailing backslash. ~CLOCK:~ lines display the same way (see [[#clocking][Clocking]]): ~Clock: start–end ⇒ duration~ once closed, and ~Clock: start (running)~ while open.

*** Agenda: Log

The Agenda's date-range line has a *Log* checkbox, off by default, like org's ~org-agenda-log-mode~. On, every ~:LOGBOOK:~ entry across the aggregated files appears as its own dated item, interleaved by timestamp with SCHEDULED, DEADLINE and anniversaries, with a 📝 icon and any note beneath. It shows a DONE heading's history even though the Agenda normally excludes DONE headings, since seeing what got done is the point of Log mode.

** Archiving
:PROPERTIES:
:CUSTOM_ID: archiving
:END:

Tap a heading's title, then *Archive*, to move its subtree to the archive location (real org's ~org-archive-subtree~, ~C-c C-x C-s~ or ~C-c $~). A prompt names the destination and offers *OK*, *Cancel* or *Refile…* (see [[#refile][Refile]]).

The moved heading gets an ~:ARCHIVE:~ tag and properties recording where it came from: ~ARCHIVE_TIME~, ~ARCHIVE_FILE~, ~ARCHIVE_OLPATH~, ~ARCHIVE_CATEGORY~, ~ARCHIVE_TODO~ and ~ARCHIVE_ITAGS~, as in org's ~org-archive-save-context-info~. The original is removed only after the copy is safely written, so a failure leaves it where it was.

The location is ~org-archive-location~: the heading's own ~ARCHIVE~ property, else the file's ~#+ARCHIVE:~ keyword, else the default ~%s_archive::~. It has two parts joined by ~::~: a file (~%s~ is the current file's name; empty means the current file) and an optional heading to file entries under, where the stars give its level (~* Archived Tasks~).

| Location | Behavior |
|---+---|
| ~%s_archive::~ (default) | Sibling file ~notes.org_archive~, top-level entries |
| ~::* Archived Tasks~ | Same file, filed under a top-level ~* Archived Tasks~ heading (created if it doesn't exist yet) |
| ~~/org/archive.org::~ | One central file, top-level entries |
| ~~/org/archive.org::* %s~ | One central file, filed under a heading named after the source file |

Archiving to a different file works on GitHub and WebDAV only; a local or iOS-imported file needs a file picker that the browser won't show mid-archive, and the app says so. Archiving within the current file works everywhere. Not supported: ~datetree/~ targets and multi-level heading paths.

*** Restoring (unarchive)
:PROPERTIES:
:CUSTOM_ID: restoring-unarchive
:END:

Open the archive file (*File → Open* lists ~_archive~ files), tap the archived heading, then *Unarchive*. After a confirmation naming the destination, the heading moves back to its original file and place, loses ~:ARCHIVE:~ and the ~ARCHIVE_*~ properties, and gets its TODO state back from ~ARCHIVE_TODO~. As with archiving, it leaves the archive only after the write succeeds.

A heading tagged ~:ARCHIVE:~ by hand, with no recorded ~ARCHIVE_FILE~, just has the tag and properties stripped in place. In the command palette it is *Unarchive (restore)* (~org-unarchive-subtree~). There is no separate list for browsing the archive.

*** Refile
:PROPERTIES:
:CUSTOM_ID: refile
:END:

Tap a heading's title, then *Archive*, then *Refile…* on the prompt, to move the subtree elsewhere in the outline or into another file (real org's ~org-refile~, also in the command palette). The picker lists each target by its full outline path, with your last five destinations under *RECENT* and the rest under *ALL TARGETS*. The subtree becomes the target's last child, with its levels adjusted. A subtree is never offered as its own destination.

Targets come from ~org-refile-targets~ (see [[#local-variables][Local Variables]] and [[#configuration][Configuration]]). The default is the current file, top-level headings only. Entries are separated by ~;~, each a file followed by criteria:

#+BEGIN_SRC
org-refile-targets: current maxlevel=3; notes.org tag=work level=2; agenda-files todo=NEXT
#+END_SRC

- *File*: ~current~, ~agenda-files~, or a file name (a bare name is a sibling of the current file).
- *Criteria*: ~level=N~, ~maxlevel=N~, ~tag=NAME~ (the heading's own tag; inheritance is not considered), ~todo=KEYWORD~, and ~regexp=PATTERN~ (matched against the whole heading line, so it must come last; write a literal ~;~ as ~\;~). Several criteria on one entry must all match, which goes beyond real org.

An entry the app can't understand is skipped and listed with the reason at the top of the picker. Refiling to another file works on GitHub and WebDAV; a local file must have been opened once. Not built: creating a new heading as the destination.

** Attachments
:PROPERTIES:
:CUSTOM_ID: attachments
:END:

This app's own feature, inspired by org's ~org-attach~. The [[#editing-your-outline][general editor]] (📋 Edit details) has an *Attach* action that offers five choices:

- *📎 Attach a file* (org's ~org-attach-attach~): pick any file, including gallery media or the camera (the browser's picker usually offers the camera too). The first attachment on a heading generates a random ~:ID:~ property, reused for later ones, and uploads the file to ~<document's directory>/data/<first 2 characters of the ID>/<rest of the ID>/<filename>~. A document at ~org-pwa/foo.org~ keeps its attachments under ~org-pwa/data/~, and one at the root under ~data/~. An ~attachment:~ link, org's own link type, is appended to the heading's body.
- *🎤 Record audio* (this app's own): records from the microphone with a live timer, then plays the recording back so you can re-record before saving. Saving uploads it like any attachment. The format depends on the browser (~audio/webm~ in Chrome, Firefox and Edge, ~audio/mp4~ in Safari), and the file is named ~recording-YYYY-MM-DD-HHMMSS.<ext>~. It needs HTTPS and microphone permission.
- *📂 Open*: views the heading's attachment in a new tab with the browser's native viewer (PDF, video, plain text, images, audio), and downloads it with a status message when there is no viewer. HTML and SVG are never opened this way, because navigating to them would run any script inside. A ~.webm~ file is checked by its content to tell audio from video, defaulting to audio, and ~.mp4~ is always video (recordings are named ~.m4a~). With no attachments a message says so; with one it opens directly; with several it asks which.
- *💾 Save*: downloads the attachment, whatever its type (the same picker if there are several).
- *🗑️ Delete* (org's ~org-attach-delete-one~): pick one if there are several, confirm, and both the file on GitHub or WebDAV and its ~[[attachment:...]]~ link are removed. The file goes first; if that fails, the link stays.

Tapping an ~attachment:~ link in a body does the same as *Open*.

*Display*: a bare ~[[attachment:photo.jpg]]~ with no description shows as an inline image, as in org (a description turns any image link into a plain link); see [[#links-and-images][Links and images]]. Image extensions include ~.heic~ and ~.heif~ (iPhone photos) as well as ~.png~, ~.jpg~, ~.gif~, ~.svg~, ~.webp~ and ~.bmp~. HEIC renders only in browsers that support it: Safari and iOS do, desktop Chrome and Firefox generally don't. An audio file shows a compact "▶️ filename" button; tapping it fetches the audio and expands a native player with play, pause and a scrubber. Audio extensions include ~.webm~, ~.m4a~, ~.mp3~, ~.wav~ and ~.ogg~. Any other attachment keeps its filename as visible text, like ~[[attachment:notes.pdf][notes.pdf]]~, and opens as *Open* does.

*Resolving links*: an ~attachment:~ link resolves against the ~:ID:~ of the heading it is written in, else the nearest ancestor's, as in org. With no ~:ID:~ in that chain it shows as an unresolved link.

*Requirements*: GitHub or WebDAV must be connected, since writing, reading and deleting files needs a backend that can do that without a fresh file picker; a local or iOS-imported file can't. *Attach* is always visible, and explains the limitation if tapped without one.

- *GitHub*: files over 1MB (an ordinary camera photo) are read back through GitHub's Blobs API, which allows 100MB.
- *WebDAV*: every folder in the path is created first, as the server requires.

A just-attached image is shown from the bytes already uploaded, not fetched again.

*Filenames*: a picked name has path separators and other path-unsafe characters replaced with ~_~ and is otherwise kept, spaces included; a name that ends up empty becomes ~attachment~. A name that collides with an existing attachment on the same heading gets ~-1~, ~-2~ and so on before the extension. That matters because many camera apps return the same name (often ~image.jpg~) for every capture, and the storage path comes only from the ID and the name: two captures become ~[[attachment:image.jpg]]~ and ~[[attachment:image-1.jpg]]~, each with its own file.

*Not built*: bulk operations like ~org-attach-dired~ (Delete handles one at a time), and a view of every attachment in the file. Only the *Open* and *Delete* pickers for the heading you are acting on list attachments.

** Clocking
:PROPERTIES:
:CUSTOM_ID: clocking
:END:

Every clocking action is a [[#command-palette][command palette]] command: *Clock in*, *Clock out*, *Cancel clock*, *Continue last clock*, *Go to clocked task* and *Set effort estimate*, found by name or by their real Org name (~org-clock-in~ and so on). The app runs one clock at a time, though a hand-edited file with several running ~CLOCK:~ lines round-trips fine.

- *org-clock-in* inserts a bare ~CLOCK: [timestamp]~ line on the heading whose action menu is open, else the keyboard-focused one (a status message says so when there is neither). On the heading already clocked it does nothing. On a different heading it clocks the running one out at the same moment, with no gap.
- *org-clock-out* turns the line into ~CLOCK: [start]--[end] =>  H:MM~, with the duration computed. *org-clock-cancel* removes the running ~CLOCK:~ line entirely and records no duration, for a clock started by mistake. Both act on whichever clock is running anywhere in the document; with none running they do nothing and say so.
- *org-clock-in-last* (~C-c C-x C-x~; the palette's *Continue last clock*, ~c x x~ in god-mode) resumes clocking on the most recently clocked heading, anywhere in the document. A status message covers "a clock is already running" and "nothing has been clocked yet". In an Extras entry it is ~'org-clock-in-last~ (see [[#extras-menu][Extras Menu]]).
- *org-clock-goto* (~C-c C-x C-j~; the palette's *Go to clocked task*, ~c x j~) jumps to the clocked-in heading. There is one clock across all open tabs, so it works from anywhere: it switches to the clock's tab, unfolds whatever hides the task, and leaves the floating back button behind. With no clock running the palette shows it dimmed ("no clock is running"). With ~C-u~ (~u c x j~ in god-mode, or the palette's *Go to a recently clocked task*, named ~org-clock-select-task~) it lists recently clocked tasks from every open tab, most recent first, and jumps to the one you choose.

Clock lines live in a ~:LOGBOOK:~ drawer from the first one. Org itself keeps the first one bare (see [[#progress-logging][Progress logging]]).

*Showing clocked time*:

- *org-clock-display*: a *Clock* checkbox on *View → TODO* (like Agenda's *Log*; see [[#agenda][Agenda]]) shows each item's total clocked time beside its title: all time ever clocked on the task and its descendants, including a running clock's elapsed time. It is off by default and is a session toggle, not a variable.
- *org-clock-report*: a ~#+BEGIN: clocktable ... #+END:~ block, computed for a date range and shown read-only under *View → TODO*'s *Clock report* (see [[#the-todo-view][The TODO view]]).
- While a clock runs, the modeline (see [[#modeline][Modeline and minibuffer]]) shows ~[⏱ H:MM] Heading title~, refreshed every 30 seconds.

*Effort estimates*: *Set effort estimate* in the command palette (~C-c C-x e~, ~org-set-effort~) prompts for the ~EFFORT~ of the heading whose action menu is open, else the focused one. Any ~org-duration~ form is accepted and stored as typed: ~1:30~ or ~1:23:45~; units like ~2h~, ~45min~, ~1d 3h~ or ~1y 3d 3h 4min~ (spaces optional); a mix like ~3d 13:35~; decimals like ~2.35h~; or a bare number, which is minutes. The units are Emacs's defaults: ~min~, ~h~, ~d~ (24 hours), ~w~ (7 days), ~m~ (a *month* of 30 days, not minutes: write ~30min~ for half an hour) and ~y~ (365.25 days). A blank value clears the estimate, and an invalid one is refused with a status message and the old value kept. You can also type it into *Edit details → Properties*.

An ~EFFORT~ shows beside the title as a ~⏱~ badge, as typed, and tapping the badge opens the same prompt. While that heading is clocked in, the modeline shows the running time against it, ~[⏱ 0:45 / 2:00] Heading title~ (the estimate as ~H:MM~), with a trailing ~!~ once the time passes the estimate.

Not built: custom duration units (~org-duration-units~), the ~Effort_ALL+~ append form, and a reminder tied to the estimate beyond the modeline's ~!~. See [[#differences-from-emacs-org-mode][Differences from Emacs org-mode]].

*** Effort_ALL: allowed effort values
:PROPERTIES:
:CUSTOM_ID: effort-all
:END:

Org's effort prompt completes against a list of allowed values, ~Effort_ALL~. It looks in this order, and the first source that gives at least one usable value wins:

1. an ~Effort_ALL~ property on the heading itself, or on the nearest ancestor that has one;
2. the file's ~#+PROPERTY: Effort_ALL 0 0:10 0:30 1:00 2:00~ line;
3. the *Global properties* setting (~org-global-properties~, in Settings → Advanced or a file's Local Variables): semicolon-separated ~NAME: value~ entries, such as ~Effort_ALL: 0:15 0:30 1:00 2:00 4:00~. Only ~Effort_ALL~ is used.

Values are space-separated, and each must be a valid ~org-duration~ (see [[#clocking][Clocking]]); anything else is skipped. When a list applies, *Set effort estimate* shows its values as buttons above the text box: one tap saves that value, and the box still takes any other duration. With no list the prompt is plain free text. The same list supplies the Agenda's effort filter (see [[#agenda][Agenda]]); with none defined, the filter uses org's own fallback set (~0 0:10 0:30 1:00 2:00 3:00 4:00 5:00 6:00 7:00~).

Not supported: ~Effort_ALL+~, and quoted values containing spaces.


** Narrowing
:PROPERTIES:
:CUSTOM_ID: narrowing
:END:

A heading's action menu has a *🔽 Narrow* action that restricts the outline to that heading and its subtree: every sibling, ancestor and unrelated heading disappears from view. On the narrowed heading it becomes *🔼 Widen*, while every other heading still shows Narrow, and tapping it re-narrows to that heading instead. A banner at the top, *Narrowed to: TITLE — Widen*, stays while narrowing is active. Tapping *Widen* there, or on the heading's own action menu, shows the whole file again. These are org's ~C-x n s~ and ~C-x n w~, also available in [[#god-mode][god-mode]] as ~x SPC n s~ and ~x SPC n w~.

Narrowing only restricts what is displayed; the file is untouched. *Save, Export, Agenda and Search all still work on the whole document.* Narrowing follows the heading it points at: promote, demote, move or rename it and the narrowed view updates, and if it is deleted the view widens automatically. Narrowing to another heading replaces the restriction, with no stack of levels to pop, as in org. Folding is independent of narrowing.

*Narrowing persists* across switching tabs and across closing and reopening the app: a file you left narrowed reopens narrowed to the same heading.

*Text view while narrowed* shows only the narrowed subtree's raw text, so you can edit one section as plain org syntax (see [[#the-plain-text-editor][The plain-text editor]]). You reach it only by being narrowed in the outline first; switching to Text without narrowing shows the whole file.

** The plain-text editor
:PROPERTIES:
:CUSTOM_ID: the-plain-text-editor
:END:

Tap *View → Text* to replace the outline with one full-width textarea holding the whole document as raw org text: everything, including ~#+STARTUP:~, ~#+TODO:~, a [[#local-variables][Local Variables]] block, and syntax the structured view has no UI for (editing block content, changing the ~#+TODO:~ sequence itself). Tap *View → Org* to switch back. The text is reparsed at that point, so changes (to ~#+STARTUP~, ~#+TODO~ or Local Variables, say) take effect at once, mark the document modified, and persist like any other edit. This is the escape hatch for what the tap-driven UI doesn't cover.

*Position*: switching in lands near where you last navigated, not always at the top. After a search result, an internal link or an agenda item, the cursor and scroll position land at that heading's line. Manual scrolling isn't tracked, so scrolling around and then switching opens at the top. The scroll position is proportional to the line's place in the file, so it is near the line, not exact. While [[#narrowing][narrowed]], the textarea starts at the top of the narrowed text.

*Narrowed*: only the narrowed subtree's text is editable. Switching back to Org splices the box into its original place in the full document. The lines it replaces are fixed when you enter narrowed Text view, so retyping the heading's asterisks to promote or demote it, renaming it, or adding a new heading inside the fragment are ordinary edits that can't touch anything outside the region. Narrowing follows a level or title change made this way: rename or re-level the heading you're narrowed to, and the narrowed view updates to match.

*Select All* and *Copy All* buttons sit above the textarea, because selecting a long document with the phone's drag handles is painful. *Select All* selects the full text, and the device's own Copy still works from there. *Copy All* writes it straight to the clipboard, and if the clipboard API is unavailable or denied it selects the text instead. ~Ctrl-A~ or ~Cmd-A~ works natively inside the textarea, so the buttons are for devices without a keyboard. While narrowed, both act on just the narrowed text.

*Search works here without leaving Text view*, searching and replacing the textarea's live raw text. It is a separate implementation from Org view's structured [[#searching][Searching]], which reads a parsed document and so can never safely edit property drawers, tags, block content and the like. Text view has no such restriction: a value inside a ~#+BEGIN_VERSE~ or ~#+BEGIN_QUOTE~ block (an imported contact's note, say) can be found and replaced here. *Regex* and *Replace* work as in Org view, including the interactive ~y~, ~n~, ~q~, ~.~ and ~!~ walk. *Match* mode isn't offered, since it needs a parsed document. A replacement stays in the textarea until you leave (switch views, or Save), like every edit made here.

** Agenda
:PROPERTIES:
:CUSTOM_ID: agenda
:END:

Tap *View → Agenda* for everything with a date, in Day, Week or Month view. One button cycles the three views. *‹* and *›* step back or forward by the current unit, *Today* jumps to today, and a horizontal swipe does the same as ‹ and ›. Tapping an item returns to the Org view at that item.

*Empty days*: every day shows by default, even when nothing is on it. The *g* button toggles ~org-agenda-show-all-dates~ for the session; it is bold while empty days are hidden. The starting value comes from ~org-agenda-show-all-dates~ in [[#local-variables][Local Variables]] or the *Show empty days in Agenda* Quick Setting.

*Weeks*: Week view always shows a full calendar week, Monday to Sunday by default (~org-agenda-start-on-weekday~), whichever day you opened it on. Day headers show the ISO week number on the first day of each week (always in Day view), and the range label shows the week numbers, like ~(W36)~ or ~(W31-W36)~.

*Categories*: every item shows a category prefix: the file's ~#+CATEGORY:~ keyword, else its file name without directory or ~.org~. Put the keyword at the top of the file:

#+BEGIN_SRC org
  ,#+CATEGORY: Projects
  * TODO Review weekly goals
    SCHEDULED: <2026-09-07 Mon>
#+END_SRC

*Times*: a timestamp can carry a range, like ~SCHEDULED: <2026-08-31 Mon 08:00-09:00>~. Week and Month views show ~08:00-09:00~; a single time shows as ~08:00 ……~; an untimed SCHEDULED or DEADLINE shows its ~Scheduled:~ or ~Deadline:~ label instead.

*Time grid*: Day view adds an hour-by-hour grid (org's ~org-agenda-time-grid~ default: dashed lines every two hours, 8am to 8pm). Untimed items come first; timed items sit between the lines at their time. Week and Month views have no grid.

*Effort*: an item with an ~EFFORT~ property (any ~org-duration~ form, see [[#clocking][Clocking]]) shows it after its title, as typed: ~⏱ 1:30~. Each day header shows the day's total on the right (~⏱ 3:30~), with a trailing ~+2?~ for TODOs that have no estimate yet. The [[#the-todo-view][TODO view]] shows ~⏱~ too. How it counts:

- A heading shown twice in one day (scheduled and deadline) counts once. An overdue task carried forward counts toward today.
- An appointment counts when it has an effort. One with neither a TODO keyword nor an effort is not counted in ~+N?~.
- An explicit ~0:00~ is an estimate. An invalid effort counts as missing.
- Logged entries, diary lines and sunrise/sunset lines never count. A day with no estimates shows no total.

*Sorting, filtering and limiting by effort*: the ~⏱~ button in the toolbar opens a panel, the touch version of org's ~effort-up~ and ~effort-down~, ~org-agenda-filter-by-effort~ and ~org-agenda-max-effort~:

- *Sort*: least or most effort first within each day.
- *Filter*: tasks with effort *at most*, *at least* or *exactly* a value from the [[#effort-all][Effort_ALL]] list (or org's default set).
- *Max per day*: keep tasks while the running total stays within, say, ~4:00~.
- *Reset* clears all three.

The rules are org's own: *at most* and *at least* are inclusive; a task with no effort counts as high effort (it sorts last, is dropped by *at most* and *exactly*, and kept by *at least*); the limit keeps a prefix of the sorted day, so once the total passes the maximum everything after it is dropped, and an unestimated task ends the list; entries with no heading behind them (sunrise lines, anniversaries) are never filtered or counted; and the order is sort, limit, filter. These are session settings, not remembered after a reload.

*** Dated entry sources
:PROPERTIES:
:CUSTOM_ID: agenda-dated-entries
:END:

Five kinds of entry show up. They differ in whether they carry forward, as in real org:

- ~SCHEDULED:~ shows on its date and, until the heading is done, on every day after it as overdue ("3 days overdue"). A delay suffix (~SCHEDULED: <2026-01-10 Sat -2d>~) hides it until the delay has passed, even on its own date.
- ~DEADLINE:~ carries forward the same way. A warning suffix (~DEADLINE: <2026-01-10 Sat -3d>~) shows it early, counting down ("due in 3 days") and then up once overdue. With no suffix it starts showing ~org-deadline-warning-days~ before its date (default 14; see [[#local-variables][Local Variables]]). An explicit suffix overrides that.
- A *plain active timestamp in a heading's title*, such as ~**** Jane Doe <2000-01-01 Sat +1y>~, never carries forward. It counts only when the heading has no SCHEDULED or DEADLINE. Inactive ~[...]~ timestamps and body text are ignored.
- A *general sexp timestamp* ~<%%(sexp)>~ in the title follows the same rules; see [[#agenda-sexp-timestamps][General sexp timestamps]].
- ~org-contacts-anniversaries~ reads yearly events (birthdays, anniversaries) from a contact heading's property: ~BIRTHDAY~ by default (configurable in Local Variables), written ~YYYY-MM-DD Description~.

#+BEGIN_SRC org
  * John Doe
  :PROPERTIES:
  :BIRTHDAY: 2000-01-01 Birthday
  :END:

  * Mary & John Doe
  :PROPERTIES:
  :BIRTHDAY: 2000-06-15 Wedding Anniversary
  :END:
#+END_SRC

  Put the trigger line ~%%(org-contacts-anniversaries)~ anywhere in the file; it is a switch, not an event, and usually sits under its own heading. Every heading with the property then shows a 🎂 line like ~John Doe: Birthday (26)~, with the age worked out for each year shown. ~YYYY~ may be ~nil~ when the year is unknown, shown as ~(??)~. A bare ~YYYY-MM-DD~ takes the property name as its description ("Birthday"). A value that can't be parsed is skipped. No ~:EMAIL:~ is required.

  This works with [[#import][vCard import]]. In Flat style the property is a bare date. In Tree style the birthday is a descendant heading (~:FIELDTYPE: birthday~), found anywhere in the contact's subtree unless the contact has its own property.

*** Diary-sexp forms
:PROPERTIES:
:CUSTOM_ID: agenda-diary-sexp
:END:

These are self-contained lines anywhere in a heading's body, with no switch line needed. They show with a 🔁 icon (☀️ for the solar ones).

- ~%%(org-anniversary YEAR MONTH DAY) text~: applies only to years after YEAR. In the text, ~%d~ becomes the elapsed years and ~%s~ its ordinal suffix, so ~%%(org-anniversary 2001 6 12) %d%s wedding anniversary~ shows "25th wedding anniversary" in 2026. February 29 counts as March 1 in non-leap years.
- ~%%(org-cyclic N YEAR MONTH DAY) text~: every N days from that date, never before it.
- ~%%(diary-float MONTH DAYNAME N [DAY] [YEAR]) text~: the Nth weekday of a month. MONTH is 1 to 12, a list like ~(1 4 7 10)~ (a quoted ~'(1 4 7 10)~ also works), or ~t~ for every month. DAYNAME is 0 (Sunday) to 6. N counts from the start of the month when positive and from the end when negative (~-1~ is the last). ~%%(diary-float 11 4 4) Thanksgiving~ is the 4th Thursday of November. An optional DAY moves where scanning starts (~%%(diary-float 11 2 1 2) US Election Day~ starts at the 2nd, skipping a Tuesday on the 1st), and an optional YEAR limits the entry to that year.
- ~%%(org-block Y1 M1 D1 Y2 M2 D2) text~: every day in an inclusive range, in either order.
- Lines built from ~and~, ~or~, ~not~, ~when~, ~org-class~ or ~org-date~, such as ~%%(and (org-block 2026 9 1 2026 12 18) (org-class 2026 9 1 2026 12 18 1)) Seminar~, use the evaluator described under [[#agenda-sexp-timestamps][General sexp timestamps]]. The text after the closing parenthesis is the entry, and a string result replaces it.
- ~%%(diary-sunrise)~, ~diary-sunset~, ~diary-civil-dawn~, ~diary-civil-dusk~, ~diary-nautical-dawn~, ~diary-nautical-dusk~, ~diary-astronomical-dawn~ and ~diary-astronomical-dusk~ are this app's own. They use ~calendar-latitude~ and ~calendar-longitude~ (default Durham, NC; set them in Local Variables or with the device-location button in Quick Settings) and show, for example, "06:30 Sunrise", "20:15 Sunset", "06:02 Dawn", "20:43 Dusk" in 24-hour time. Civil, nautical and astronomical twilight are the sun 6°, 12° and 18° below the horizon; ~n/a~ replaces the time on a day when it doesn't occur. ~solar-ampm~ (default ~nil~) switches to 12-hour ("6:30am Sunrise") and ~solar-hide-label~ (default ~nil~) drops the label ("06:30"); set them in Local Variables or Quick Settings ([[#settings][Settings]]).
- ~%%(diary-day-length)~ shows the day's daylight as "13:32 daylight". ~solar-hide-label~ applies and ~solar-ampm~ doesn't. Polar day and night show "24:00" and "00:00".
- ~%%(org-weather)~ shows current conditions and today's forecast from [[https://open-meteo.com/][Open-Meteo]] (free, no key), for the same coordinates. It is one entry, on today only, showing the last-fetched snapshot, and nothing until the first refresh.

~org-weather-format~ controls the text. The default is ~"Weather: %desc, %tcur(%tmin-%tmax)%tu, %p%pu, %h%hu, %s%su, %a%au"~, which gives "Weather: Overcast, 86.3(75.5-91.8)°F, 1002.8hPa, 49%, 5.1mph, 12m". An unrecognized ~%~ sequence is left as is.

| Placeholder | Meaning |
|---+---|
| ~%desc~, ~%icon~ | Description and emoji for the current weather code |
| ~%tcur~, ~%tmin~, ~%tmax~ | Current temperature, today's low and high |
| ~%tamin~, ~%tamax~ | Today's "feels like" low and high |
| ~%tu~ | Temperature unit (~org-weather-temperature-unit~, default ~°F~) |
| ~%h~, ~%hu~ | Humidity and its unit |
| ~%p~, ~%pu~ | Surface pressure and its unit (~hPa~) |
| ~%s~, ~%su~ | Wind speed and unit (~org-weather-speed-unit~: ~mph~ by default, ~km/h~, ~m/s~ or ~Knots~) |
| ~%a~, ~%au~ | Age of the snapshot, in ~m~, ~h~ or ~d~ |

All three variables can be edited in Quick Settings, with a reset to default.

*Refreshing*: *Settings → Weather* shows the last refresh time and a *Refresh weather now* button, and says whether ~%%(org-weather)~ is used in the open document, only through ~org-agenda-files~, or nowhere. ~org-weather-refresh-interval~ also refreshes automatically: ~never~ (the default) or every ~1~, ~2~, ~4~, ~6~, ~12~ or ~24~ hours, checked at open and periodically, and only while ~%%(org-weather)~ is in use. A failed refresh keeps the cached data, which persists across restarts.

*Not supported on purpose*: ~diary-anniversary~, ~diary-cyclic~, ~diary-block~ and ~diary-date~. They read dates in an order set by ~calendar-date-style~, while here a date is always year month day, as in their ~org-*~ twins. To use a line from an Emacs diary, rename it and put the year first: ~%%(diary-anniversary 10 31 1948)~ becomes ~%%(org-anniversary 1948 10 31)~. A line using the diary names matches nothing.

*** General ~<%%(sexp)>~ timestamps
:PROPERTIES:
:CUSTOM_ID: agenda-sexp-timestamps
:END:

A ~<%%(expression)>~ goes where a plain timestamp would, in a heading's title. The expression is evaluated for each day shown, and every day it is non-nil is an occurrence. It is a matcher, not a repeater: marking the heading DONE has no effect, and it can't carry a repeater suffix. It is skipped when the heading has SCHEDULED or DEADLINE, and it never carries forward.

#+BEGIN_SRC
* Weekly Sunrise <%%(when (org-cyclic 7 2026 8 9) (diary-sunrise))>
* TODO Team Sync <%%(diary-float t 6 1)>
* Water the plants <%%(org-cyclic 3 2026 1 1)>
* Company Anniversary <%%(org-anniversary 2018 5 14)>
#+END_SRC

The evaluator is small, not a Lisp interpreter:

- ~(when CONDITION EXPR)~: the result of EXPR if CONDITION is non-nil, otherwise no match.
- ~(and EXPR...)~, ~(or EXPR...)~, ~(not EXPR)~: as in Lisp. ~and~ yields its last value, so a string survives; ~or~ yields the first that matches. ~t~ and ~nil~ work as values, and list arguments may be quoted (~'(10 11 12)~). ~<%%(and (org-block 2026 9 1 2026 12 18) (diary-float t 1 1))>~ is the first Monday of each month, within that range.
- ~(today-p)~: this app's shorthand for ~(equal date (calendar-current-date))~. ~<%%(when (today-p) (diary-sunrise))>~ shows sunrise only today.
- ~(org-block Y M D Y M D)~ is an inclusive range, in either order. ~(org-date Y M D)~ takes, for each field, an integer, a list or ~t~: ~(org-date t '(10 11 12) 22)~ is the 22nd of October, November and December every year. Every date is year month day, and impossible dates match nothing.
- ~(org-class Y1 M1 D1 Y2 M2 D2 DAYNAME [SKIP-WEEK...])~: DAYNAME (0 Sunday to 6) every week between the two dates, except the listed ISO week numbers. Skipping holidays isn't supported; an expression that asks for it matches nothing.
- ~(org-cyclic ...)~, ~(org-anniversary ...)~ and ~(diary-float ...)~, as above, work as sub-expressions. So do the solar functions, ~(diary-day-length)~ and ~(org-weather)~, which return a formatted string; a string result becomes the displayed text ("Weekly Sunrise: 06:30 Sunrise"). ~org-contacts-anniversaries~ isn't recognized inside a sexp timestamp.
- ~(format FORMAT-STRING ARG...)~ combines string-returning functions into one line: ~<%%(when (today-p) (format "Rise %s (%s)" (diary-sunrise) (diary-civil-dawn)))>~ shows "Rise 06:30 Sunrise (06:02 Dawn)", or "Rise 06:30 (06:02)" with ~solar-hide-label~. Only ~%s~ and ~%%~ are recognized, and each ~%s~ evaluates its argument, including a nested ~format~. Extra arguments are ignored; too few give no match. A title that is only the timestamp shows the result exactly as built, with no title prefix.
- Anything else (an unknown function, a malformed expression, a bare value) is no match, never an error.

*Not included*: ~let~, a ~date~ variable, arithmetic and comparison, and ~calendar-*~ helpers, so the Emacs manual's "pay check" example can't run. Also not implemented: ~diary-remind~; the display-only ~diary-day-of-year~, ~diary-iso-date~, ~diary-julian-date~, ~diary-astro-day-number~ and ~diary-lunar-phases~; alternate calendars and Hebrew observances (~diary-yahrzeit~, ~diary-rosh-hodesh~ and the rest); and ~calendar-date-style~.

*** Other agenda behavior
:PROPERTIES:
:CUSTOM_ID: agenda-behavior
:END:

- *Completed items are excluded*, using the done keywords of the file's own ~#+TODO:~ sequence.
- *Repeating timestamps expand* for SCHEDULED, DEADLINE and title timestamps: ~<2000-01-01 Sat +1y>~ shows every year within the range displayed. A repeating SCHEDULED or DEADLINE shows only on its repeat dates, with no carry-forward or early warning between them.
- *Marking a repeating task done shifts it*, as in org: its date moves forward, ~LAST_REPEAT~ is stamped, and the TODO state returns to the first keyword. ~+N~ adds one interval to the previous date, even if that is still in the past. ~++N~ adds intervals until the date is in the future, keeping the weekday and time. ~.+N~ counts from today. The DONE transition is logged normally; the bounce-back is not, and the ~CLOSED~ timestamp is removed again.
- *Archived and commented headings are excluded*. A commented heading starts with ~#~ and a space (~** # draft, not ready yet~). The settings are ~org-agenda-skip-archived-trees~ and ~org-agenda-skip-comment-trees~ in [[#local-variables][Local Variables]].

A trailing tag needs a space before it (~<2000-01-01 Sat +1y> :BDAY:~), as in org. Without the space the tag stays as title text, but the timestamp still shows.

*** Agenda Files
:PROPERTIES:
:CUSTOM_ID: agenda-files
:END:

Add files in *Settings → Quick Settings → Agenda files*, or in a document's own ~# Local Variables:~ block to override that for the one file (see [[#local-variables][Local Variables]]). Entries are semicolon-separated ~scheme:path~ pairs, like ~github:journal.org;webdav:notes/todo.org~, the same syntax as ~org-refile-targets~ (see [[#refile][Refile]]). The Agenda and TODO views then scan all of them. ~github~ and ~webdav~ files are fetched; ~local:name.org~ reads a file you have already opened on this device (*File → Open → Local file*). A malformed entry is skipped. If the open file is in the list, its live in-memory version is used.

Files are fetched once per session. Once any are configured, a *↻* button in the agenda controls refetches them, and a file that fails to load is reported above the list. A local file is read-only here: Agenda, TODO, Search and Export use it, but Refile, Replace and Capture never write into it. It loads only if the browser already allows access; otherwise the agenda says it "needs permission", and the *↻* button, being a tap, is what asks. Export's *This file + Agenda Files* scope always fetches fresh (see [[#export][Export]]). Two entries with the same file name, such as ~github:notes.org~ and ~local:notes.org~, can't both be used: the first is, and the agenda says so for the second.

[[#export][Contacts (.vcf)]] export's *This file + Contacts Files* scope scans them. The list is independent of Agenda Files, because the two commonly differ.

** The TODO view
:PROPERTIES:
:CUSTOM_ID: the-todo-view
:END:

Tap *View → TODO* for every active TODO-state heading in the file, independent of any date, like org's global TODO list (~C-c a t~, as distinct from the calendar-style agenda, ~C-c a a~). A TODO with no SCHEDULED, DEADLINE or timestamp never shows in Agenda, so this is where it lives.

It is a flat list in document order, each item showing its TODO keyword and title. Tap one to jump to it in the outline. It has the same exclusions as Agenda (completed items, by the file's ~#+TODO:~ sequence, archived headings and commented headings, with the same [[#local-variables][Local Variables]] overrides).

*Clock report*: a checkbox on the same row as *Clock* (a rule separates the clock controls from the task list) shows org's ~org-clock-report~, a ~#+BEGIN: clocktable ... #+END:~ block, rendered read-only instead of written into the document. Checking it shows a start and end date picker (the last 7 days including today the first time, then whatever you pick) and a ~maxlevel~ selector (1 to 10, default 2, as in org). The table lists every heading with clocked time in the range, down to ~maxlevel~, and each row's total includes all its descendants. A deeper heading still adds its time to the ancestor shown, without a row of its own, and a heading with no clocked time in its subtree is omitted. A clock that is still running is excluded, because its duration would change with every view. A *Copy* button, on the same row as the *Clock* and *Clock report* checkboxes, copies the rendered text as valid org dynamic-block syntax, ready to paste into a file as a permanent record.

** Capture Templates
:PROPERTIES:
:CUSTOM_ID: capture-templates
:END:

The command palette's *Capture* command (or ~C-c c~, see [[#god-mode][God-mode]]) opens a panel for org's ~org-capture-templates~: filing a note, task or table row into a specific place in the outline without navigating there. Each template is listed by its description. Tap one; if it has ~%^{Prompt}~ or ~%?~ fields, a form asks for each, with a *live preview* of the expanded result above the fields and the first field focused with the keyboard up. A template with no prompts captures at once.

After a capture the form returns to the template list, so you can capture again straight away. If a capture fails (a network error, a sync conflict) the form stays as you left it, with your text intact. Every template is also a palette command, *Capture: <description>*, that captures with that template directly, and the Extras menu (see [[#extras-menu][Extras Menu]]) can jump to one template by its key.

A capture into a different file refuses if that file has unsaved local changes from an earlier session. Open the file, resolve its pending changes, then retry.

Four templates are the default: ~b~ (Bullet List), ~c~ (Check List), ~m~ (Meeting) and ~t~ (Table Row). Edit or replace them in *Settings → Capture Templates*, as a JSON array of template objects.

*Template shape:*

#+BEGIN_SRC json
{
  "key": "b",
  "description": "Bullet List",
  "type": "item",
  "olp": ["heading 1", "heading n"],
  "template": "%? [The captured text or note]",
  "file": "journal.org",
  "prepend": true,
  "prependHeading": true
}
#+END_SRC

- ~key~: must be unique. It is the hotkey in a god-mode picker and shows beside the description on the capture form.
- ~type~: ~item~ (a bullet), ~checkitem~ (a checkbox item), ~plain~ (raw text parsed as an org fragment; the only type that can contain headings, drawers or TODO keywords) or ~table-line~ (a row added to the nearest table under the target, or a new table).
- ~olp~: the outline path to insert into, found or created heading by heading. A segment wrapped in ~%<FORMAT>~ (like ~"%<%Y-%m>"~) expands dynamically, so a monthly table can target "2026-07" without creating that heading by hand. Other segments are literal.
- ~file~ (optional): capture into a different file (org's ~file+olp~). A bare name is a sibling of the open file, a path containing ~/~ is used as is, and an optional ~github:~ or ~webdav:~ prefix names the backend; a prefix that doesn't match the open document's backend is refused. If it resolves to the open file, the capture lands in that live document. Otherwise the other file is read, changed and written back without being opened, and nothing changes if the write fails. Omit it to capture into the open file. GitHub and WebDAV targets work automatically; a local or iOS-imported target must have been opened or saved once first.
- ~template~: the text inserted, after %-expansion. A JSON ~\n~ is a newline; a blank line after the entry is ~"...%?\n"~.
- ~prepend~ (default ~false~): put the new entry at the top instead of the bottom. A new list item goes before the first item, and a new table row goes right after the header row and rule. For ~item~, ~checkitem~ and ~plain~ it also puts any auto-created ~olp~ heading first among its siblings.
- ~prependHeading~ (default ~false~; ~table-line~ only): put newly created ~olp~ headings first among their siblings, independently of ~prepend~. That keeps the newest month's heading on top while its rows still append in order. It applies at every level that has to be created; existing segments are reused as they are.
- ~omitEmptyEntries~ (default ~false~; ~plain~ only): remove entries whose expanded value is empty because a ~%^{Prompt}~ was left blank. That covers ~:KEY:~ drawer entries and body lines shaped ~KEY:value~, such as raw vCard lines (for ~N~ and ~ADR~, a value of only whitespace and semicolons counts as empty). It also removes an empty trailing tag (a blank ~:%^{Tag}:~ would show as ~::~), in every sub-heading the capture defines.
- ~preText~, ~postText~ (optional, default empty): template text, in the same %-language, added around the output. For ~item~, ~checkitem~ and ~plain~ it wraps every capture, with no automatic spacing. For ~table-line~ it is added once, when the target has no table yet: ~preText~, the new table with this first row, then ~postText~; later captures only add rows. No blank line separates them from the table, so a header row and rule in ~preText~ join the table, and a ~#+TBLFM:~ or ~#+PLOT:~ line is picked up (see [[#table-formulas][Table formulas]] and [[#plots][Plots]]). A ~%^{Prompt}~ in them still appears on the form even when the capture won't use it, unless the target is the open document, a loaded Agenda File or a local file, where the form can check first.

*Template text, the %-escape language* (local time):

- ~%<FORMAT>~ is a ~format-time-string~ subset. The examples use Wednesday, March 5, 2025, 14:30:07:

| Specifier | Meaning | Example output |
|---+---+---|
| ~%a~ | Abbreviated weekday name | ~Wed~ |
| ~%A~ | Full weekday name | ~Wednesday~ |
| ~%b~ | Abbreviated month name | ~Mar~ |
| ~%B~ | Full month name | ~March~ |
| ~%d~ | Day of month, zero-padded (01–31) | ~05~ |
| ~%e~ | Day of month, space-padded ( 1–31) | ~␣5~ |
| ~%F~ | ISO date (~%Y-%m-%d~ combined) | ~2025-03-05~ |
| ~%H~ | Hour, 24-hour, zero-padded (00–23) | ~14~ |
| ~%I~ | Hour, 12-hour, zero-padded (01–12) | ~02~ |
| ~%j~ | Day of year, zero-padded to 3 digits (001–366) | ~064~ |
| ~%m~ | Month, zero-padded (01–12) | ~03~ |
| ~%M~ | Minute, zero-padded (00–59) | ~30~ |
| ~%p~ | ~AM~ or ~PM~ | ~PM~ |
| ~%R~ | Hour:minute (~%H:%M~ combined) | ~14:30~ |
| ~%S~ | Second, zero-padded (00–59) | ~07~ |
| ~%T~ | Hour:minute:second (~%H:%M:%S~ combined) | ~14:30:07~ |
| ~%y~ | 2-digit year | ~25~ |
| ~%Y~ | 4-digit year | ~2025~ |
| ~%z~ | Numeric UTC offset (±HHMM); depends on the device's time zone (shown for US Eastern summer time) | ~-0400~ |
| ~%Z~ | Time zone abbreviation; device-dependent like ~%z~ | ~EDT~ |
| ~%%~ | A literal percent sign | ~%~ |

  An unrecognized specifier is left visible (~%Q~ stays ~%Q~).

- ~%t~, ~%T~: an active timestamp, date only or date and time. ~%u~, ~%U~: the same, inactive (~[...]~ instead of ~<...>~).
- ~%i~ is content shared in from another app (see [[#capture-from-other-apps][Capturing from other apps]]), and ~%a~ is a link to the shared page, ~[[url][title]]~. Text before ~%i~ on its line is added before every later line, so a ~%i~ that follows indentation keeps every line indented. A shared line that would start a heading or a ~#+~ line gets a leading comma, so shared text can never change the document's structure, and only web and mail addresses become links. Both are empty when nothing was shared.
- ~%x~ is the clipboard. It is read only for a template that uses it, the browser may ask permission (iOS shows a Paste confirmation), and a refusal leaves it empty while the capture still goes ahead.
- ~%^{Prompt}~ asks a question on the in-app form. ~%^{Prompt|default}~ pre-fills an answer, and ~%^{Prompt|default|choice1|choice2}~ also lists the choices as a hint under the field (there is no dropdown). Several prompts share one form, and cancelling discards the whole capture.
- ~%^t~, ~%^T~, ~%^u~, ~%^U~ are interactive timestamps: active date (~<2026-09-22 Tue>~), active date and time, inactive date (~[2026-09-22 Tue]~), inactive date and time. Active timestamps show in the [[#agenda][Agenda]]; inactive ones don't. Each is a text field with a *📅 Pick date* (or *📅 Pick date & time*) button. In the popup, *OK* writes the timestamp into the field, where it stays editable, and *Cancel* leaves the field as it was. They count as prompts, in reading order, for ~%\N~ and the live preview.
- ~%\N~ (~%\1~, ~%\2~, ...) re-inserts the answer already given to the Nth ~%^{Prompt}~ or ~%?~ (1-based) instead of asking again. Out of range gives empty text. In the JSON text the backslash must be doubled: ~%\\1~.
- ~@#~ is the table-formula row number, for ~table-line~ captures only (empty otherwise). It takes an offset, ~@# + n~ or ~@# - n~, with n a non-negative integer.
- ~%?~ is org's cursor marker, treated as one more prompt: labeled "Text", asked on the form, and focused with the keyboard up when it is the first or only field.

*Two worked examples:*

#+BEGIN_SRC json
{
  "key": "t",
  "description": "Tracking",
  "type": "table-line",
  "olp": ["🛍️ Bag - lists and notes", "❤️ Health", "🏩 Tracking", "%<%Y-%m>"],
  "preText": "#+PLOT: title:\"Tracking\" ind:4 deps:1 with:points ticks:6",
  "postText": "#+TBLFM: $4=round(trunc($3/100) + 100*($3/100 - trunc($3/100)) / 60)",
  "template": "| @# | %<%Y-%m-%d> | %<%H%M> ||",
  "prependHeading": true,
  "file": "github:home.org"
}
#+END_SRC

*Tracking* logs a value with its date and time into a table, and plots it:

- ~olp~ is four segments deep. The last, ~"%<%Y-%m>"~, creates the current month's heading the first time anything is captured that month.
- ~preText~ sets up the chart once, when the month's table is created: ~ind:4~ and ~deps:1~ plot the 4th column against the 1st (the row number) as points.
- ~postText~ sets up the formula once. It converts a raw ~HHMM~ value (~$3~, such as ~1830~) to the nearest whole hour in ~$4~: ~trunc($3/100)~ is the hour, the rest turns the minutes into a fraction, and ~round()~ rounds the sum, so 1830 gives 19, not 18.5.
- ~template~ is the one row: ~@#~, a date, an ~HHMM~ time, and a trailing ~||~ that leaves the 4th cell for the formula.
- ~prependHeading: true~ keeps the newest month's heading on top, while its rows append in order.
- ~file: "github:home.org"~ captures into that file on GitHub, whatever is open.

#+BEGIN_SRC json
{
  "key": "v",
  "description": "vCard Contact",
  "type": "plain",
  "olp": ["New"],
  "file": "github:contacts.org",
  "omitEmptyEntries": true,
  "template": "* %^{First Name} %^{Last Name} :%^{Category/Tag}:\nBEGIN:VCARD\nVERSION:3.0\nFN:%\\1 %\\2\nN:%\\2;%\\1;;;\nEMAIL:%^{Email}\nTEL;TYPE=voice:%^{Phone Number}\nTEL;TYPE=cell:%^{Mobile Number}\nADR;TYPE=home:;;%^{Street};%^{City};%^{State};%^{Postal Code};%^{Country}\nBDAY:%^{Birthday (YYYY-MM-DD)}\nNOTE:%^{Note}\nORG:%^{Company/Organization}\nTITLE:%^{Job Title}\nEND:VCARD\n\n%?"
}
#+END_SRC

*vCard Contact* builds a whole heading with a ~plain~ capture: a title with an inline tag prompt, and a raw multi-line body. ~FN:%\1 %\2~ and ~N:%\2;%\1;;;~ reuse the two name answers through backreferences instead of asking twice. The body has the shape the vCard export produces for its *new buffer* destination (see [[#export][Contacts (.vcf) export]]), which Import reads back (see [[#import][Import]]). ~omitEmptyEntries: true~ drops every blank field, and the trailing ~%?~ leaves the cursor below the vCard for a free-form note.

*** Capturing from other apps
:PROPERTIES:
:CUSTOM_ID: capture-from-other-apps
:END:

On Android, the installed app is a share target: choose *org-pwa* in another app's Share sheet and the shared title, text and link open Capture. Pick a template, and its ~%i~ and ~%a~ take the content. Long-press the app icon for a *Capture* shortcut.

Any link or bookmark can do the same. ~index.html?capture=KEY~ runs the template with that key, a bare ~?capture~ shows the list, and ~&text=~, ~&title=~ and ~&url=~ carry content. The address is cleaned afterwards, so reloading never captures twice, and it works offline.

Example: ~index.html?capture=n&text=Buy%20milk~ with this template files the text under *Inbox*:

#+BEGIN_SRC json
{ "key": "n", "description": "Shared note", "type": "entry", "olp": ["Inbox"], "template": "* Note\n  %i\n  %a" }
#+END_SRC

A template that files into another file (~file:~) needs a document from the same backend open; the app restores your tabs when it starts.

*iPhone*: iOS lists neither installed web apps in the Share sheet nor opens them from a link, so none of this reaches it. Copy the text instead (a Shortcut can do it), open the app and run a template that contains ~%x~.

** Extras menu
:PROPERTIES:
:CUSTOM_ID: extras-menu
:END:

A floating ☰ button at bottom-right opens a configurable popup of quick actions, a vertical list next to the button and extending to its left. It is this app's own feature, set with ~org-xx-extra-menu~ (Global or Local Variables; see [[#local-variables][Local Variables]]). The button is hidden whenever the variable is unset or resolves to nothing selectable. The sibling variable ~org-xx-menu-aliases~ relabels or hides buttons in the existing File, More, Export and View menus; see [[#menu-customization][Menu customization]].

*Syntax*: a sequence of double-quoted ~"SPEC;LABEL"~ entries, spread over several lines with a trailing ~\~ (see [[#configuration][Configuration]] for line continuation). Settings → Quick Settings shows and edits it in this one-entry-per-line form (see [[#settings][Settings]]):

#+BEGIN_SRC
org-xx-extra-menu: "j;📔 Journal" \
                   "c;✅ Checklist" \
                   "m;👥 Meeting" \
                   "-----" \
                   "t;⭐ Tracking" \
                   "["🛍️ Bag - lists and notes", "❤️ Health", "🏩 Tracking", "%<%Y-%m>"];👁 Current" \
                   "-----" \
                   "'calendar;📅 Calendar"
#+END_SRC

*LABEL* is the text shown, exactly as written (icon and all). *SPEC* is one of three shapes:

- A bare *capture-template key* (~t~, ~j~, ~c~, ~m~ above) runs that template, as if picked from the Capture menu (see [[#capture-templates][Capture Templates]]). A key with no template shows a status message.
- A bracketed *OLP path*: an array of double-quoted heading titles, as in a capture template's ~olp:~, each segment expanded for ~%<FORMAT>~ when the item is tapped (~"%<%Y-%m>"~ gives the current year and month). It navigates to that heading. Unlike a capture template, it never creates a missing heading, because browsing a menu shouldn't write to the file: a path that doesn't fully exist creates nothing and says so.
- A *quoted function reference* (~'calendar~ above) runs the command palette command with that real Emacs or Org function name, as if chosen from the palette. It acts on the heading whose action menu is open, else the keyboard-focused one. A command that can't run says why in the status line (~Clock out: no clock is running.~), and no confirmation is asked, since choosing the item is the confirmation. The names are the ones the palette shows and searches (~org-clock-out~, ~org-clock-in~, ~org-refile~, ~org-todo~, ~org-agenda~, ~save-buffer~, ~isearch-forward~, ~calendar~, ~org-html-export-to-html~ and the rest), so type a function name into the palette to find the command, and quote the same name here.

  *Exceptions*: *New document* and *Undo history* have no Emacs function to name. Emacs has no dedicated new-buffer command (~switch-to-buffer~ with an unused name is the usual way, and ~scratch-buffer~ only returns to the one ~*scratch*~ buffer), and its undo history is a variable, ~buffer-undo-list~, not a command. A name that no command has shows ~'name is not a recognized function.~ when tapped; the entry stays in the menu, so a typo is visible.

  *Recalculate all tables* (~org-table-recalculate-buffer-tables~) recalculates every ~#+TBLFM:~ formula in the document as one undo step, where org's ~C-c C-c~ recalculates one table (see [[#table-formulas][Table formulas]]). *Export as an Org buffer* is ~org-org-export-as-org~ (see [[#export][Export]]).

  *The calendar* (~'calendar~, the palette's *Calendar*) is named after Emacs's command but is this app's own single-month overview, with year and month navigation and a Today jump. Today is bold with a two-colour halo ring that stays visible on any background. Each day is colour-coded by what is on it, from the same agenda pipeline the Agenda uses: green for a contact's birthday (~org-contacts-anniversaries~, see [[#agenda][Agenda]]), blue for any other event (SCHEDULED, DEADLINE, a plain timestamp or a diary-sexp entry), and burnt orange when both. Ambient daily diary entries (sunrise, sunset, weather) and logbook entries don't count, since they would colour nearly every day. Tapping a date closes the calendar and opens Agenda's Day view on that date, whatever is open or connected. The displayed month is remembered for the rest of the session.

Five hyphens (~"-----"~) on their own are a visual separator rather than an item, for grouping related actions.

A malformed entry (bad JSON in an OLP array, a function symbol that isn't a valid name, a spec matching none of the three shapes, a missing label) is skipped without breaking the rest of the menu.

** Menu customization
:PROPERTIES:
:CUSTOM_ID: menu-customization
:END:

~org-xx-menu-aliases~ (a Global or Local Variable; this app's own, not an org variable) relabels or hides buttons across the File, More, Export and View menus at once. Its sibling ~org-xx-extra-menu~ adds a new quick-access menu instead (see [[#extras-menu][Extras menu]]).

*Syntax*: double-quoted ~"menu:Label;alias"~ entries, space-separated and spread over several lines with a trailing ~\~. ~menu~ is ~file~, ~more~, ~export~ or ~view~. Settings → Quick Settings shows and edits it one entry per line (see [[#settings][Settings]]):

#+BEGIN_SRC
org-xx-menu-aliases: "more:Commands;💲 Commands" \
                     "more:Export;📤 Export" \
                     "more:Import;📥 Import" \
                     "more:Settings;⚙️ Settings"
#+END_SRC

Export is a step within the More menu and has its own namespace, ~export:~. A form like ~"more:export:HTML;📄"~ isn't valid: the colon splits only once, so it is read as the label ~export:HTML~ in the ~more~ namespace, which matches nothing and has no effect, without an error.

~Label~ is one of the menu's built-in button labels (the table below). A label that matches no button, or a ~menu~ other than the four, is skipped without an error. A label never mentioned keeps its default text: this is an override list, not a full redefinition.

*~alias~*, after the semicolon:

- *Non-empty*: replaces the button's visible text. The button does the same thing, and the original label becomes its accessible name (for screen readers and tooltips).
- *Empty* (~"menu:Label;"~): the button is omitted entirely. ~"export:Markdown;"~ hides the Markdown button from the Export menu. *~more:Settings~ is the exception*: it can never be hidden, because GitHub and WebDAV setup and Global Variables are reachable only from there, so an empty alias keeps the label ~Settings~.

*Order*: buttons can be reordered, but only once every one of a menu's labels is listed (the table has the complete sets). A partial list leaves that menu's order untouched, so setting one alias never reorders the rest. Once all are listed, the buttons appear in the order the entries are written. An empty alias counts as listed but also hides the button (except ~more:Settings~), so to keep a button visible with its default text, repeat that text as the alias: ~"more:Settings;Settings"~. For example, to show the More menu as Settings, Commands, Import, then Export, list all four:

#+BEGIN_SRC
org-xx-menu-aliases: "more:Settings;Settings" "more:Commands;Commands" \
                     "more:Import;Import" "more:Export;Export"
#+END_SRC

*Popup menus*: File, View, More and Extras open as small bordered popups next to their trigger button, below it if there is room and above it otherwise (the Extras button is near the bottom, so its popup opens upward). Each is sized to its widest row, with one full-width row per button, and on a mouse a row highlights as the pointer passes over it. Tapping outside closes a menu, and selecting an action closes it at once, with the result reported on the status line. Every popup (File, View, More, Export, the Open and Save As backend picker, and Extras) shares one size setting, Settings → Appearance → *Menu Size* (Regular or Small). Export is a step within the More popup, and a *‹ Back* button returns to the More list without closing anything.

The real labels of each menu, as used in ~"menu:Label;alias"~:

| ~menu~ | Labels |
|----------+--------|
| ~file~ | ~Export~, ~New~, ~Open~, ~Save~, ~Save As~ |
| ~more~ | ~Commands~, ~Export~, ~Import~, ~Settings~ |
| ~export~ | ~ASCII~, ~As-org~, ~Calendar (.ics)~, ~Contacts (.vcf)~, ~HTML~, ~Markdown~, ~ODT~ |
| ~view~ | ~Agenda~, ~Org~, ~Text~, ~TODO~ |

** File management
:PROPERTIES:
:CUSTOM_ID: file-management
:END:

*File menu*: New, Open, Save, Save As. A 💾 button beside the File menu icon does what *File → Save* does, in one tap. It is disabled under the same conditions as Save: no document open, or a new unsaved document with nowhere to save to yet.

- *New* creates a document in memory, with no file picker, name or backend to choose. You can edit it at once, and its edits are cached locally like any open document's, so a crash or an accidentally closed tab can be resumed with the usual "resume unsaved local version" prompt. Nothing is written to a backend until you choose to keep it. The tab bar and modeline show ~*scratch*~, Emacs's name for a fresh unnamed buffer, in the same red-with-a-dot style as unsaved edits, until the first heading gets a title, which then becomes the label. *Save* stays disabled, and *Save As* picks a destination and makes it a persisted file. It opens in its own tab (see [[#tabs][Tabs]]), and is handy as a scratch pad for trying a capture template, testing a table formula, or drafting something that may be thrown away.
- *Open* asks for a backend: Local/Import, GitHub or WebDAV.
- *GitHub and WebDAV show a real folder listing.* Tap a folder (📁) to enter it. Files shown are ~.org~ files (📄) and ~_archive~ files (🗄️, org's archive-file naming; see [[#archiving][Archiving]]), and other files are hidden. An *↑ Up* button appears below the root. GitHub uses its Contents API, and WebDAV uses ~PROPFIND~, which Nextcloud, ownCloud and Apache ~mod_dav~ support. If listing fails (a server without good ~PROPFIND~, a token without list permission on a folder), *Type a path instead…* is always available.
- *Save* writes back to the backend the file came from, without asking again.
- *Line endings* are kept. A Windows-style (CRLF) file is edited as ordinary text and saved back with CRLF, and a Unix-style one stays Unix-style, so a save changes only the lines you edited.
- *Save As* picks a new destination, possibly on a different backend, or the first destination of a new unsaved document.
- If a file has unsaved local edits when you open it, you are asked whether to *resume* them or *discard* them and load the current version; either way the file opens. The prompt shows when the edit was made, and discarding clears it. *Settings → Pending Local Changes* lists every file with unsynced edits, with a Discard button for each and *Discard all* when there is more than one.
- *Conflicts*: if the stored version changed since the last sync, Save merges the two where it safely can and asks only about the parts that clash (see [[#offline-behavior-and-sync][Offline behavior and sync]]).
- *Recently opened*, below a double separator, lists files you have opened or saved as, never the file that is currently open. It persists across sessions, is sorted alphabetically and capped at a handful. Long-press its label to clear the whole list; there is no per-item removal. Tapping an entry opens it directly, with no path or picker prompt, except for a file brought in with *Import* (the read-once fallback for browsers without File System Access, like iOS Safari), which can't be reopened without selecting it again.

** Tabs
:PROPERTIES:
:CUSTOM_ID: tabs
:END:

*Several documents can be open at once.* Opening a file (New, Open, a Recently opened entry, a ~file:~, ~github:~ or ~webdav:~ link, or a result from Agenda or Search) adds it as a tab rather than replacing what is open, and all of these use the same open logic. Opening a file that is already open in another tab switches to that tab. Each tab keeps its own content, cursor and keyboard focus, mid-edit fields, scroll position, view mode and undo/redo history (which persists across a reopen; see [[#undoredo-and-history][Undo/redo and History]]).

The tab bar is always visible, even with one document. Each tab shows a short label (the filename, or the first heading's title for an unsaved document; several unsaved drafts can be open at once, each with its own local cache) and a solid dot when it has unsaved changes, the same red "modified" convention used elsewhere. Tap a tab to switch to it. The small × closes it, after asking first if it has unsaved changes (~"X" has unsaved changes. Close it anyway?~), as Emacs's ~kill-buffer~ does; a clean tab closes at once. Closing the last tab opens a fresh empty unsaved document in its place, so there is always a tab to work in.

The full set of open tabs persists across closing and reopening the app, each restored as it was left, with the previously active one active again.

*Help* has its own tab (see [[#docs][Help]]), always last and styled distinctly (green background, gold underline when active). Switching to a document tab leaves it open but inactive, and unlike document tabs it doesn't survive closing and reopening the app.

** Export
:PROPERTIES:
:CUSTOM_ID: export
:END:

*More → Export* gets a document out as ASCII, Markdown, HTML, ODT, As-org, a calendar file (.ics) or contacts (.vcf). File keywords such as ~#+TITLE~ and ~#+OPTIONS:~ match case-insensitively, as in org.

*Scope*: *Choose a heading…* exports just that heading and its descendants, and every heading is listed, even folded ones. The chosen heading becomes the top level of the output. *This file* exports everything. Calendar and Contacts also offer *This file + Agenda Files* or *This file + Contacts Files* once those are configured, fetched fresh at export time. In Tree style, Contacts lists only contacts (headings with ~:KIND:~).

*** Document settings

~#+TITLE~, ~#+AUTHOR~ and ~#+DATE~ appear at the top of a whole-document export in ASCII, HTML and ODT: a visible title with the author and date beneath it, and the format's own metadata where it has some. Markdown has none of them, as in org's ~ox-md~. A subtree export starts at its heading instead.

~#+OPTIONS:~ takes these keys, chained on one line or split across several (a later value wins):

| Key | Effect |
|---+---|
| ~toc:~ | An integer depth limit, or ~nil~ for no table of contents. Independent of ~num:~ |
| ~num:~ | Heading numbers on or off. In Markdown it switches the table of contents between an ordered and an unordered list |
| ~^:~ | Sub/superscript strictness, as ~org-use-sub-superscripts~ (see [[#local-variables][Local Variables]]); overrides it for this export |
| ~author:~, ~date:~ | Show each field or not |
| ~creator:~ | A "Generated by org-pwa" notice, off by default |

Markdown supports only ~toc:~ and ~num:~.

~#+INCLUDE: "path" [block-type] [language] [:lines "N-M"] [:minlevel N]~ splices another document in at export time, before the first heading or in a heading's body. In a body it nests as children of that heading, one level deeper by default; at document level it keeps its own levels. The path is read from an explicit ~github:~ or ~webdav:~ prefix, or else relative to the open file.

- With no block type, the file is parsed as org and its headings are spliced in (its own ~#+TITLE~ and similar keywords are not). ~:minlevel N~ shifts its top level to N.
- With a block type (~src~, ~example~, ~quote~ or ~export~, optionally with a language or backend, as in ~#+INCLUDE: "path" export html~), the raw text is wrapped in that block and placed in the body.
- ~:lines "N-M"~, ~"-M"~ or ~"N-"~ filters the text first. The end line is exclusive, as in org, despite the manual's wording.

A file that can't be found is skipped silently.

~#+HTML_HEAD:~ inserts raw HTML before ~</head>~, in HTML export only and for subtree exports too; several lines are joined in order. ~#+BEGIN_EXPORT <backend>~ ... ~#+END_EXPORT~ passes its content through unescaped when the backend matches the current format (~html~, ~ascii~, ~md~ or ~markdown~, ~odt~, where the content must already be ODF XML) and is omitted otherwise.

*Page numbers*: CSS ~@page~ takes effect only when printing or using *Print → Save as PDF*:

#+BEGIN_SRC
#+HTML_HEAD: <style>@page { @bottom-center { content: counter(page); } }</style>
#+END_SRC

Use ~@bottom-right~ (with ~margin: 2cm~ for room) to put it at the right. For "Page 3 of 12", use ~content: counter(page) " of " counter(pages)~, which works in Chrome and less reliably elsewhere. For a fixed header or footer, pin ~header~ and ~footer~ with ~@media print~ rules in ~#+HTML_HEAD:~ and put their markup in a ~#+BEGIN_EXPORT html~ block.

*** ASCII

Plain text, org's ~ox-ascii~ for the core cases. Level-1 headings are underlined with ~=~ and deeper ones indented. Paragraphs wrap at ~org-ascii-text-width~ (default 72; see Local Variables), never mid-word. A link becomes ~description (target)~. Bold, italic, underline and strikethrough are stripped, and ~code~ and =verbatim= become ~`text'~. Footnote references become ~[1]~, with their definitions under "Footnotes". Headings are numbered (1, 1.1, 2) and, with more than one heading, a "Table of Contents" comes first; ~toc:~ and ~num:~ control both.

Tables are typeset: each column is padded to its widest cell, and mostly-numeric columns are right-aligned. A row of ~<N>~ cells, like ~| <30> | <10> | <24> |~ (usually above the header), fixes each column to N characters; wider content wraps within the row, breaking at hyphens when needed. That cookie row never appears in any format's output, and only ASCII uses the widths.

Not implemented: Latin-1 and UTF-8 substitutions, ~:width~ rules and justification blocks (see [[#differences-from-emacs-org-mode][Differences from Emacs org-mode]]).

*** Markdown

GFM. Checkboxes become task-list items (~- [ ]~, ~- [x]~), tables become pipe tables, code fences keep their language, and footnotes become ~[^label]~. TODO keyword, priority and tags stay as text on the heading (~# TODO [#A] Buy milk~). Underline and sub/superscript use raw ~<u>~, ~<sub>~ and ~<sup>~.

Internal links (~[[#custom-id]]~, ~[[*Heading]]~, fuzzy titles) become GitHub-style ~#slug~ anchors: lowercase, punctuation stripped, spaces to hyphens, duplicates suffixed ~-1~, ~-2~. A link outside the exported scope, or one that doesn't resolve, stays as its literal text.

*** HTML

A complete standalone document. TODO keywords and priorities get small badges (done keywords from the file's ~#+TODO:~, like ~DONE~ or ~KILL~, are green). Checkboxes are disabled ~<input type="checkbox">~ elements, and footnotes are linked superscripts with a Footnotes section. Every heading gets an ~id~ (its ~:CUSTOM_ID:~ or a slug), and internal links resolve to them, with the same fallback as Markdown.

The CSS is print-aware (headings and tables don't split across pages), so the browser's *Print → Save as PDF* is the route to PDF.

*** ODT

A standalone ~.odt~ that opens in LibreOffice, Word (with the ODF filter) and Google Docs. Headings are outline levels; bold, italic, underline, strikethrough and code use named character styles; checkboxes show as ☐ and ☑; footnotes are real, editable ODF footnotes; and internal links are bookmark references. Images are referenced by path, not embedded.

*** As-org

Org's ~org-org-export-as-org~: a fully processed copy of the document in a new unsaved buffer, ~*Org ORG Export*~, leaving the original untouched. Whole document only. It:

- resolves ~#+INCLUDE:~ lines;
- expands ~{{{macro}}}~ references: ~#+MACRO: name text~ with ~$1~, ~$2~ arguments, written ~{{{name(arg1,arg2)}}}~ with ~\,~ for a literal comma, plus ~{{{title}}}~, ~{{{author}}}~, ~{{{email}}}~, ~{{{date}}}~ and ~{{{date(FORMAT)}}}~ (FORMAT applies only when ~#+DATE:~ is a single well-formed timestamp), ~{{{time(FORMAT)}}}~ and ~{{{keyword(NAME)}}}~;
- drops ~:noexport:~ headings with their subtrees, and strips ~#+BEGIN_COMMENT~ blocks and comment lines (those starting with ~#~ and a space);
- shifts the top level to 1.

Not implemented: running source blocks, and macros whose text starts with ~(eval~. Both are left as written (see Differences from Emacs org-mode). In an Extras entry it is ~'org-org-export-as-org~.

*** Calendar (.ics)

Every dated item as an iCalendar file for any calendar app: SCHEDULED, DEADLINE, plain active title timestamps and [[#agenda][org-contacts-anniversaries]]. It follows the Agenda's exclusions (archived, commented and completed headings). Re-exporting gives the same event IDs, so a calendar app updates events instead of duplicating them.

| Org source | vCalendar field | Notes |
|---+---+---|
| SCHEDULED | ~DTSTART~, ~SUMMARY~ (~DESCRIPTION~ "Scheduled") | |
| DEADLINE | ~DTSTART~, ~SUMMARY~ (~DESCRIPTION~ "Deadline") | A warning suffix (~-3d~) also becomes a ~VALARM~ reminder |
| Plain active title timestamp | ~DTSTART~, ~SUMMARY~ | Only when the heading has no SCHEDULED or DEADLINE |
| A repeater (~+1w~, ~++3d~, ~.+1m~) on any of these | ~RRULE~ | The calendar app expands the recurrence |
| org-contacts-anniversaries | ~DTSTART~ with a yearly ~RRULE~, ~SUMMARY~ ("Title: Description") | |

*** Contacts (.vcf)

vCard 3.0 for any contacts app, modeled on [[https://github.com/pinoaffe/org-vcard][org-vcard]] (compatible with org-contacts.el). [[https://www.rfc-editor.org/rfc/rfc6350][RFC 6350]] requires only ~FN~, so no email address is needed. There are two styles, and *Tree* is the default:

- *Flat*: every heading with at least one recognized contact property (~:EMAIL:~, ~:PHONE:~, ~:CELL:~, ~:WORK_PHONE:~, ~:ADDRESS:~, ~:ADR:~, ~:NICKNAME:~, ~:NOTE:~ or the birthday property). ~:IGNORE: t~ excludes one. A heading with none is skipped.
- *Tree*: a contact heading (~:KIND: individual~, ~:FIELDTYPE: name~) with each field as a descendant heading carrying its own ~:FIELDTYPE:~, at any depth. A contact with no fields still exports a minimal vCard (~FN~, ~N~).

The *To: new buffer* checkbox sends the vCard text to a new unsaved document (a ~vCard(s)~ heading, titled ~*scratch*~) instead of downloading a file; Import reads that shape back.

There are no name, tag or property filters. *This file* respects an active narrow restriction ([[#narrowing][subtree narrowing]] or [[#searching][Search's Narrow]]), and the screen says so; narrow first, then export. A narrow applies only to the open document, never to Contacts Files.

| Org source (flat) | vCard field | Notes |
|---+---+---|
| Heading title | ~FN~ | |
| ~:N:~ | ~N~ | Used as given; if absent, split from the title (last word as family name) |
| ~:EMAIL:~ | ~EMAIL~ | |
| ~:EMAIL_LABEL:~ | ~LABEL="..."~ on the ~EMAIL~ line | When present |
| ~:PHONE:~, ~:CELL:~ | ~TEL~ | |
| ~:PHONE_LABEL:~ | ~LABEL="..."~ on the ~TEL~ line | |
| ~:WORK_PHONE:~ | ~TEL;TYPE=WORK~ | |

** Import
:PROPERTIES:
:CUSTOM_ID: import
:END:

*More → Import* currently reads vCard (.vcf) only, the reverse of [[#export][Contacts (.vcf) export]]. A ~.vcf~ file can hold one contact or many, and each becomes a new heading appended to the end of the open document. Nothing already in the file is touched.

*Style*: *Flat* or *Tree*, the two structures Export supports, independent of the style you last exported. Tree is the default, because Flat keeps only one value per field type (see below). Exporting a contact, importing that file and exporting again gives an equivalent vCard.

*Sources*: *Choose vCard file…*, *Choose a heading…* and *This file*. A document can hold headings whose body is vCard text, such as Export's *To: new buffer* output or text you paste in. *Choose a heading…* scans that heading and its descendants for bodies starting with ~BEGIN:VCARD~, and *This file* scans the whole document. Both say plainly when there is nothing to import ("No vCard data found in this file"). The *To: new buffer* checkbox sends the imported contacts to a new unsaved ~*scratch*~ document instead of appending to the open one.

*What is read*: ~FN~ is the only required property, as in [[https://www.rfc-editor.org/rfc/rfc6350][RFC 6350]]; a vCard block without one is skipped. ~N~, ~EMAIL~, ~TEL~, ~ADR~, ~URL~, ~NICKNAME~, ~ORG~, ~TITLE~, ~PHOTO~, ~NOTE~, ~BDAY~ and ~CATEGORIES~ are mapped when present, the reverse of Export's tables.

- ~N~ is kept exactly as given, never recomputed from ~FN~ (which would mangle a business name or a single name).
- ~ADR~'s components (PO Box, street, city, region, postal code, country) are joined into one comma-separated string.
- A value with embedded newlines (a multi-line ~NOTE~ or ~ADR~) becomes one line, with a space-semicolon-space separator, wherever it lands in a single-line Flat property.
- ~CATEGORIES~ become org tags on the heading, and export writes them back as ~CATEGORIES:~.
- Folded (continued) lines are unfolded, and escapes (~\,~, ~\;~, ~\\~, ~\n~) are reversed, the inverse of Export's escaping.

*Apple and Google ~itemN.~ grouping*: these contacts tie a label to a property with a group prefix, such as ~item1.TEL~ with ~item1.X-ABLabel~ (standard vCard 3.0). This is always recognized, because otherwise the prefixed properties would be dropped. The label becomes ~:EMAIL_LABEL:~, ~:PHONE_LABEL:~ or ~:URL_LABEL:~ (Flat), or a ~:LABEL:~ property on the field heading (Tree), like ~:ADDRESS_LABEL:~ for addresses. A label you assigned ("Landline") is kept as is. Apple's placeholder form (~"_$!<HomePage>!$_"~) is reduced to its inner name ("HomePage"), and an empty label or Apple's "no label" placeholder (~"_$!!$_"~) gives no label. ~URL~ can have several values. Apple's ~X-ABADR~ country-code companion is ignored.

*Clean data (Google, Apple)* is a checkbox, on by default, for non-standard quirks of those exports:

1. Google appends an eighth component to ~ADR~: the address again, as a multi-line label. On, it is kept alongside the seven structured components, so a later export can rebuild the original. Off, it is ignored, as RFC 6350's seven-component ~ADR~ requires. The standard ~ADR;LABEL="..."~ parameter is recognized either way.
2. Google escapes colons as ~\:~, which isn't a real vCard escape. On, it is turned back into ~:~ everywhere; off, it is left as written.
3. Apple's ~X-ABLabel~ placeholders are interpreted as described above; off, they are stored as written.

*Flat style keeps one value per type*: one ~:EMAIL:~, ~:PHONE:~ or ~:WORK_PHONE:~, ~:URL:~ and ~:ADDRESS:~. When a vCard has several of one type, the first is kept and the rest are dropped, so use Tree style to keep them all (org-vcard lists multiple ~EMAIL~ as an open item too). Labels survive as ~:ADDRESS_LABEL:~, ~:EMAIL_LABEL:~, ~:PHONE_LABEL:~ and ~:URL_LABEL:~.

*Tree style has no such limit*: each value becomes its own descendant heading. The ~address-work~ and ~address-home~ fieldtypes (like ~email-work~ and ~phone-home~ in Export's table) round-trip a ~TYPE=WORK~ or ~TYPE=HOME~ address. A field whose value contains a newline (a note, always, or a Google address whose label spans lines) gets a fixed title ("Note", "Home Address") with its text as a ~#+BEGIN_VERSE~ block in the body. Verse keeps every line break, so separate facts (old phone numbers, street and city) don't blur together, and a body can hold newlines that Flat must flatten. Export reads ~#+BEGIN_VERSE~ or ~#+BEGIN_QUOTE~ and falls back to the heading's title when there is neither. A short single-line label is a plain ~:LABEL:~ property on the field heading.

*Warnings*: properties the parser doesn't know are collected, listed once by name in the status message after the import ("Imported 3 contacts from vCard. 2 unrecognized properties were skipped: X-SOCIALPROFILE, X-YAHOO."). ~VERSION~, ~PRODID~, ~REV~, ~UID~ and ~X-ABADR~ are known and deliberately unmapped, so they aren't reported. A base64 ~PHOTO~ gets its own count in the same message, since it is kept as a ~data:~ URI (see Export's ~:PHOTO:~ row).

A ~.vcf~ file with no valid (~FN~) contacts gives a clear status message. A malformed line inside an otherwise valid contact is skipped without aborting the import.

** Settings
:PROPERTIES:
:CUSTOM_ID: settings
:END:

Reached via *More (⋮) → Settings*, which replaces the outline until you navigate away, like switching views.

** Offline behavior and sync
:PROPERTIES:
:CUSTOM_ID: offline-behavior-and-sync
:END:

Edits are cached locally at once; writing to disk, GitHub or WebDAV happens only on an explicit Save.

*Conflict detection*: Save compares the file's current state with what the app last knew, so one version never silently overwrites the other. The app also checks for external changes when a file is opened, when the tab regains focus, and when you switch into a tab with real backing storage. A banner then appears with *Merge*, *Reload* and *Dismiss*. For a local file this background check never asks the browser for permission: it runs only if access is already granted, so the banner may not appear until you have saved or reloaded the file in the session. Save, Reload and Merge still ask when they need to.

*Resolving a conflict*: the app keeps the full text of the file as of the last successful open or save, the common ancestor a three-way merge needs. When Save finds the file changed elsewhere under your unsaved edits, it compares the ancestor, your version and the other one line by line:

- *The other version has no real change, or matches yours*: Save just proceeds. A server that changes a file's ETag without changing its content isn't a conflict.
- *Your changes and theirs are in different places*: they are combined automatically and Save completes with a status message (~Saved — merged with the changes made elsewhere~). The merge is its own undo step (*Merged with changes from elsewhere*), so Undo returns to your text from just before it.
- *Both sides changed the same lines*, or adjacent lines with no unchanged line between them (the same place, as in git and GNU diff3): a dialog lists each such region with your version and the other one. Choose *Yours*, *Other* or *Both* (yours, then theirs) for each, or *All yours* or *All other* for every region at once. *Apply* stays disabled until every region has a decision, and everything outside the regions is already combined. *Cancel*, Escape or tapping outside changes nothing: the other version is untouched, your edits stay unsaved, and the next Save raises the same conflict.
- *No common ancestor is known* (a file last synced by a version that didn't keep one, until its next open or save), or the two versions are too different to compare by lines: every difference, or the whole file as one choice, is shown for you to decide.

*The banner's Merge* does the same without waiting for Save. It combines your unsaved edits with the version now stored, asks about clashing regions in the same dialog, and applies the result as an ordinary, undoable, still-unsaved edit. The other version becomes the new baseline, so the Save that follows is a plain write. With no unsaved changes Merge just reloads, and a read-only buffer can't be merged into (make it writable first).

*What this isn't*: the merge works on lines, not org structure. A subtree moved on one side and edited on the other is an ordinary clash, and two sides that each add the same new heading in different places keep both. A clean automatic merge is still worth a glance; that is what the undo step is for.

** Command palette
:PROPERTIES:
:CUSTOM_ID: command-palette
:END:

A searchable list of what the app can do, the touch counterpart of Emacs's ~M-x~. Open it from *More → Commands* (first by default) or, from a keyboard, in [[#god-mode][god-mode]] with ~g x~ (which is ~M-x~).

*Searching*: type a few letters or words. Each word must match the command's name, the real Org or Emacs command it corresponds to, or one of a few extra keywords (so ~deadline~ finds *Edit details*). Case doesn't matter. Real names work as you'd type them in ~M-x~: ~org-clock-in~ finds *Clock in* but not *Clock out*, because a hyphenated word is matched as that exact phrase, while ~clock in~ typed with a space is two words that can match anywhere. A category name (*Clocking*, *Heading*, *Export*) also matches at the start of its words. There is no fuzzy or skip-letter matching.

*Order*: commands that can run now come first, then the rest, dimmed, each saying why it can't (*nothing is narrowed*, *no clock is running*, *the buffer is read-only*, *tap a heading first*). A command is never mysteriously absent, and choosing a dimmed one repeats the reason as a status message. With nothing typed, your most recently used commands come first (marked ~↺~), remembered across sessions. ↑ and ↓ move the highlight, Enter or a tap runs it, and Escape or a tap outside closes it.

*What it acts on*: heading commands work on the heading whose action menu is open (tap a heading's title first), else the keyboard-focused heading. A command that needs a heading and can't find one says so, except *Add heading after* and *Add TODO heading after*, which also work with nothing selected (see the table in [[#keybindings][Keybindings]] for where the new heading lands).

*Names*: a command's real Emacs or Org function name is shown beside it and is searchable. The same name, quoted, names the command in an Extras-menu entry (see [[#extras-menu][Extras menu]]), so the palette, the god-mode chords and Extras share one vocabulary. The commands with no real name are this app's own: *New document* and *Undo history*. A command with a [[#god-mode][god-mode]] key runs the same code as that key and shows it.

*What's in it*, by group:

| Group | Commands |
|---+---|
| *Heading* | cycle TODO state, set priority, set effort estimate, edit details (schedule, deadline, timestamps, tags, properties), add heading or TODO heading after, promote, demote, move up, move down, cut, paste, archive, unarchive, refile, attachments, narrow, widen |
| *Clocking* | clock in, clock out, cancel clock, continue last clock, go to clocked task, go to a recently clocked task |
| *Document* | save, save as, open, new, undo, redo, undo history, toggle read-only, capture, recalculate all tables |
| *View* | agenda, TODO list, outline view, text view, cycle visibility of the whole document, calendar, search |
| *Export* | the Export menu; this file as HTML, Markdown, ASCII, ODT or an Org buffer |
| *App* | settings, help |

*Also in it*: your own capture templates and [[#extras-menu][Extras menu]] entries, one command each. *Capture: <description>* (such as *Capture: Meeting*) runs that template directly, and *Extras: <label>* runs that Extras entry as tapping it would. Both are read fresh each time the palette opens, so an edited template list or a document's own Extras menu (set in its Local Variables) is current. The plain *Capture* command still opens the template picker.

*Commands*, like the other More entries, can be renamed, hidden or reordered with [[#menu-customization][menu customization]] (~org-xx-menu-aliases~). It is the ordinary ~more:~ label ~Commands~, which renders first by default.


** Keybindings
:PROPERTIES:
:CUSTOM_ID: keybindings
:END:

A practical subset for a keyboard or mouse. On a phone or tablet it applies only to a paired Bluetooth keyboard.

These are *not org's own bindings*, on purpose. Org leans on the ~C-c~ prefix, and ~C-c~, ~C-v~, ~C-a~ and ~C-f~ are reserved by browsers for copy, paste, select-all and find, so a page can't reliably take them; org's ~M-←~ and ~M-→~ collide with the browser's back and forward. Where org's key is safe it is used as is; otherwise a safe key stands in. god-mode (below) reaches org's fuller set.

| Key | Action | Matches real org? |
|---+---+---|
| ~↓~, ~↑~ | Move keyboard focus to the next or previous visible line: any row (heading, paragraph, table, list item, block). Moving down into a folded heading reveals its first body row. A status message reports the first or last line | No equivalent |
| ~S-↓~, ~S-↑~, ~S-←~, ~S-→~ | Only with focus on a table: move cell by cell (the header row counts; a rule between rows doesn't). Outside a table they aren't intercepted. After you edit a cell by tap, ~Enter~ commits and ~Escape~ cancels (the *⎌* button does the same by tap), and the cell stays highlighted for more Shift+arrow navigation. Clicking anything that isn't a table cell clears it | No equivalent |
| ~i~ | Edit the current line (heading title, paragraph, table cell or list item), cursor at the start | Like vim's ~i~ |
| ~j~, ~k~ | Move focus to the next or previous visible heading, faster than ~↓~ and ~↑~. A status message reports the first or last heading | Vim-style |
| ~Tab~ | Cycle the focused heading's fold state | Yes, ~org-cycle~ |
| ~Enter~ | Open or close the focused heading's action row | No equivalent |
| ~/~ | Focus the search box | A web convention |
| ~Escape~ | The first that applies: cancel a god-mode sequence, exit god-mode, clear keyboard focus, enter god-mode | A web convention, extended for god-mode |

Keyboard focus, a thin highlight around the focused row, is separate from tapping a heading open. It starts unset; the first arrow, ~j~ or ~k~ picks the first or last visible heading, and shortcuts that need the focused heading do nothing until one exists. ~Tab~ follows the same archived-heading rule as the swipe gesture (see [[#local-variables][Local Variables]]). Shortcuts never fire while you are typing in a text field, and Ctrl and Cmd combinations are never intercepted, so the browser's copy, paste and find stay safe.

Cycling TODO state, moving a heading, promoting and demoting, and inserting a heading are available by tap, in god-mode (~c t~, ~g↑~ and ~g↓~, ~g←~ and ~g→~, ~gRET~), and from the command palette (*Add heading after*).

*** god-mode
:PROPERTIES:
:CUSTOM_ID: god-mode
:END:

An alternate input mode that reaches org's fuller keybinding set (~C-c C-t~, ~M-RET~ and the rest) without the browser ever seeing a held Ctrl or Alt. ~Escape~ turns it on (see the priority order above), or on a phone the *[g]* button does ([[#god-mode-mobile][below]]). While it is on, every key is part of a sequence instead of a plain shortcut, and the minibuffer (see [[#modeline][Modeline and minibuffer]]) echoes the sequence.

When a sequence completes, the minibuffer names what ran, using the command palette's own label: ~God-mode · C-c C-x C-j → Go to clocked task~. A chord with no palette command (~Tab~, the arrows, ~C-f~) shows just the chord. The name stays until the next keystroke. Entering god-mode focuses the first visible heading if none is focused, since its actions need one.

While a sequence is in progress, a card under the top bar lists the keys that would continue it and what each does, as Emacs's which-key does. Each entry is a button: tap it to send that key, so a whole chord can be completed by tapping, with no device keyboard. A key that leads on to more is marked ~…~. ~Escape~ cancels the sequence and the card goes away.

Opening an overlay panel (the Extras menu, Settings, Docs, Capture, Search, the File, View and More menus, the History panel or the Calendar) exits god-mode, and the plain shortcuts don't act while a panel is open; ~Escape~ closes the open panel first. Help opened with ~h SPC m~ is the exception (see below).

The translation rules follow real god-mode.el (github.com/emacsorphanage/god-mode), plus the ~c~ rule, which is this app's own:

- A plain key means Control: ~t~ is ~C-t~.
- ~g~ prefixes the next key with Meta (~g↑~ is ~M-↑~), so a bare ~C-g~ can't be typed. ~G~ (Shift+g) prefixes Control+Meta (~Gn~ is ~C-M-n~).
- ~SPC~ toggles literal mode: following keys are typed with no modifier until ~SPC~ is pressed again. ~c SPC g~ is ~C-c g~, not ~C-c C-g~.
- A named key (arrow, Tab, Return) typed bare is never controlled, so ordinary movement keeps working.
- ~c~ as the first key gives ~C-c~ and starts an org-style chain: further letters are controlled too (~c t~ is ~C-c C-t~, ~c c~ is ~C-c C-c~) while punctuation stays literal (~C-c .~, ~C-c |~). One ~c~ is enough for any ~C-c C-<letter>~ command.

| ~c x o~ | ~C-c C-x C-o~ | Clock out (~org-clock-out~) |
| ~c x q~ | ~C-c C-x C-q~ | Cancel the running clock without recording its time (~org-clock-cancel~) |
| ~c x x~ | ~C-c C-x C-x~ | Resume the most recently clocked heading (~org-clock-in-last~) |
| ~c x j~ | ~C-c C-x C-j~ | Jump to the clocked-in heading, in whichever tab it runs (~org-clock-goto~) |
| ~u c x j~ | ~C-u C-c C-x C-j~ | Choose from recently clocked tasks and jump to it (~org-clock-select-task~) |
| ~c e~ | ~C-c C-e~ | Open the export dispatcher (~org-export-dispatch~, see [[#export][Export]]) |
| ~f~ | ~C-f~ | Arm the next ~/~ to redo instead of undo |
| ~/~ | ~C-/~ | Undo, or redo if armed |
| ~g x~ | ~M-x~ | Open the [[#command-palette][command palette]] |

Some valid sequences have no equivalent yet and say so instead of doing nothing: ~c c~ (toggling a checkbox or running a code block needs finer focus than a heading), ~c |~ and the table row and column inserts (use the +row and +col controls under any table), and ~c SPC l~, ~c l~ and ~c o~ (there is no link insertion or cursor-based link opening).

*Pickers*: ~c SPC c~, and ~c t~ on a heading with no TODO state and several workflows, exit god-mode and show a picker. Its options are tappable buttons, each also labelled with a one-character hotkey you can type at once. A hotkey is shown and accepted only when no other option shares it; those options are tap-only. Opened any other way (a tap, the ⋮ Capture button, a TODO-less heading's badge), the pickers show no hotkeys. ~Escape~ cancels either.

*Help*: ~h SPC m~ doesn't exit god-mode. While Help is the only thing open, god-mode keeps working underneath it, and ~Escape~ cancels a sequence and then exits god-mode instead of closing Help. Opening any other panel, or leaving god-mode, restores the ordinary rule.

*Redo*: Emacs has no redo command; it undoes the undo, after something breaks the chain (god-mode users conventionally press ~C-f~). Here ~f~ just arms the next ~/~ to redo. ~/~ keeps redoing while armed, any other key disarms it, and with nothing left to redo ~/~ falls back to undo. The palette's *Undo* and *Redo* are unaffected.

*~i~, ~a~ and ~e~* aren't chords; they are loosely modeled on vim and act only as the first key of a fresh sequence (~g i~ is still ~M-i~ and ~c i~ still ~C-c C-i~). ~a~ and ~e~ set where the cursor lands the next time ~i~ opens the editor, and say so in the minibuffer (~C-a → edit at start (press i)~). Once editing, every key is ordinary text-field input.

*** God-mode without a hardware keyboard
:PROPERTIES:
:CUSTOM_ID: god-mode-mobile
:END:

A phone has no ~Escape~ key, so a floating *[g]* button, the third floating button, stacked above Extras or in its place when there is no Extras menu, does three things together: it enters god-mode, shows a floating keyboard and brings up the device's keyboard. Tapping it again ends all three, and it is drawn solid while the keyboard is showing. It rides above the mode line and the device keyboard, and nothing already on screen moves for it. Settings → Quick Settings → *Keyboard* has a *Show the floating [g] god-mode button* checkbox (~org-xx-god-mode-button~, on by default) for devices with a real ~Escape~ key. A document's Local Variables line overrides it, and turning it off while the keyboard is showing ends god-mode.

The floating keyboard has the keys a phone keyboard can't type, in one row: *⌨*, ~Tab~, ~←~, ~→~, ~↑~, ~↓~, ~S~ and ~g~. Its thick accent-coloured border makes it easy to spot, and the keys are 34px wide and 44px tall so the row fits a 360px screen.

- *S* is one-shot: tap it, and the next key is shifted (~Tab~ becomes ~S-Tab~, the arrows their table-navigation forms, ~g~ becomes ~G~, the Control+Meta prefix). It also shifts the next key typed on the phone keyboard, so ~gS-RET~ (~M-S-RET~, a TODO heading) is: tap ~g~, tap *S*, tap Return. A letter typed after *S* becomes its capital. Tapping *S* again disarms it.
- *⌨* hides or shows the device keyboard and changes nothing else. It is lit while the keyboard is up. After a popup closes, the keyboard doesn't return by itself; tap ⌨.
- The move area (⠿) drags the panel, and its position is remembered. Tap it without dragging to minimize the panel to its handle, and tap the handle to restore it.

*Placement*: the panel sits above the mode line and the floating buttons, so the device keyboard never hides it and it never covers the mode line or *[g]*. By default it sits just above the floating buttons. If the keyboard comes up under it, it is pushed up and stays there when the keyboard goes away; only dragging lowers it.

*Lifetime*: god-mode and the panel end through *[g]*, ~Escape~ or another panel opening, never because the device keyboard went away. Hide the keyboard however you like and god-mode, the panel and its keys carry on, leaving the whole screen to read the outline. Entering god-mode with a real ~Escape~ never shows the panel.

If a letter doesn't register on your keyboard app, the command palette reaches the same commands by name.


** Differences from Emacs org-mode
:PROPERTIES:
:CUSTOM_ID: differences-from-emacs-org-mode
:END:

Read this if you know org-mode well and want to know where org-pwa is a subset, a simplification or just different. It lists only the deltas: a topic not mentioned here matches org's behavior.

*Interaction model* (see [[#keybindings][Keybindings]]): touch-first, not keyboard-driven. The [[#command-palette][command palette]] is ~M-x~ only in spirit: a fixed, curated list that you can't add to, not every Emacs command. god-mode's table doesn't cover table cells, per-list-item checkboxes or link insertion.

*Folding* (see [[#editing-your-outline][Editing your outline]]): no equivalent of Emacs's richer visibility state machine, but three flags per heading, on top of which ~overview~, ~content~, ~showall~, ~showeverything~ and ~show2levels~ to ~show5levels~ are implemented.

*Priority, tags, properties* (see [[#editing-your-outline][Editing your outline]]): tags and property keys complete from what is used in the open document and loaded agenda files (tags also from a ~#+TAGS:~ line). Priority is a fixed A/B/C/None row with nothing to complete, and nothing is treated specially beyond ~CUSTOM_ID~ and the ~ARCHIVE_*~ set.

*Inheritance* (see [[#local-variables][Local Variables]]): a simple boolean for each kind, not org's list-of-tags or regexp values. It applies at search time only, and inherited tags aren't shown on a heading.

*Tables* (see [[#table-formulas][Table formulas]]): ~#+TBLFM:~ covers arithmetic, conditionals, named constants, scalar and aggregate functions, date and time arithmetic and formatting, and unit conversion. Not reproduced: the rest of Emacs Calc (complex numbers, matrices, symbolic algebra), named-field references, and recalculation on every keystroke.

*Footnotes*: no ~org-footnote-new~ or ~org-footnote-normalize~ (no insert at point, renumbering, sorting or inline/separate-line conversion; edit the raw text), and no ~org-ref~ or ~org-cite~ integration.

*Clocking* (see [[#clocking][Clocking]]): no custom ~org-duration-units~, no ~Effort_ALL+~, and no clock-in reminder beyond the modeline's over-estimate marker.

*Agenda* (see [[#agenda][Agenda]]): effort sorting, filtering and the per-day limit are session settings in the ⏱ panel, not ~org-agenda-sorting-strategy~ or ~org-agenda-max-effort~. There is no negated (~-<~) filter, no effort column format (~%e~) and no effort sort in the TODO view. The sexp evaluator supports a closed, documented set of functions (including ~org-class~, ~org-date~ and ~and~, ~or~, ~not~), not a Lisp interpreter: no ~let~, ~date~ variable or ~calendar-*~ helpers, no ~diary-remind~, and no holiday-skipping in ~org-class~. ~diary-anniversary~, ~diary-cyclic~, ~diary-block~ and ~diary-date~ are left out on purpose, since their ~org-*~ twins take unambiguous year-month-day dates (see [[#agenda-sexp-timestamps][General sexp timestamps]]). A ~local:~ agenda file is read-only, and only a file already opened on this device can be named.

*Babel*: not built.

*Links and structure*: no ~[[id:...]]~ links, ~<<targets>>~, habits (~:STYLE: habit~), ~#+SETUPFILE:~ or ~org-cite~ citations. They are kept exactly as written, and never altered by a save.

*Undo/redo* (see [[#undoredo-and-history][Undo/redo and History]]): no undo tree, and fold state isn't preserved across an undo or redo jump (the file's ~#+STARTUP~ visibility is reapplied). There is no per-keystroke granularity; the browser's field-level undo covers that, much as Emacs batches consecutive typing.

*Search* (see [[#searching][Searching]]): Search and Replace both reach every file in ~org-agenda-files~, as org's ~org-search-view~ and ~tags-query-replace~ do. Both subtree narrowing (see [[#narrowing][Narrowing]]) and Search's Narrow survive a reload.

*Export* (see [[#export][Export]]): no LaTeX export, and ASCII export lacks ~ox-ascii~'s fuller features (Latin-1 and UTF-8 substitutions, ~:width~ rules, justification blocks).

*Refile* (see [[#refile][Refile]]): you can't create a new destination heading by typing a name that doesn't exist yet.

*Attachments* (see [[#attachments][Attachments]]): this app's own feature, not an ~org-attach~ port. There is no document-wide attachment browser (Open, Save and Delete work one heading at a time) and no ~org-attach-dired~ bulk operations, and it requires GitHub or WebDAV.

*Conflict resolution* (see [[#offline-behavior-and-sync][Offline behavior and sync]]): a line-based three-way merge with a region-by-region resolver. It merges lines, not org structure, so a subtree moved on one side and edited on the other is an ordinary clash, and a region has no side-by-side or word-level diff.

** Known limitations / not built yet
:PROPERTIES:
:CUSTOM_ID: known-limitations--not-built-yet
:END:

Gaps against org-mode itself are in [[#differences-from-emacs-org-mode][Differences from Emacs org-mode]]. This section covers app-specific and platform limits:

- No drag-to-reorder; buttons move, promote and demote instead (see [[#editing-your-outline][Editing your outline]]).
- Local and relative images show a placeholder on local files (File System Access) and iOS imports, the same picker-permission limit as archiving and capture to a file. GitHub and WebDAV documents are unaffected.
- No File System Access on iOS, a platform limit rather than a bug (see [[#platform-support][Platform support]]).
- god-mode's table doesn't cover table cells, per-list-item checkboxes, code-block execution or link insertion (see [[#god-mode][god-mode]]).
- A read-only buffer accepts no edit anywhere in the document, though Save and Save As still work, as in Emacs (see [[#keybindings][Keybindings]]).

** Development
:PROPERTIES:
:CUSTOM_ID: development
:END:

A static site: ~index.html~ and ES modules, with no build step to run or deploy it. Serve it any way you like, including ~python3 -m http.server~ or GitHub Pages.

The one exception is ~src/vendor/mathjs/mathjs-custom.min.js~, a tree-shaken custom mathjs build (Unit, BigNumber and Fraction, used by [[#table-formulas][Table formulas]]'s ~uconv()~, ~F~ and ~pN~). It is regenerated occasionally with ~tools/build-mathjs-vendor.sh~, a dev-only step; the committed output is what ships, as with the vendored KaTeX files.

*Tests*: the engine (~src/~) and the browser adapters (~src-browser/~) use Node's built-in test runner, with no external dependencies:

#+BEGIN_SRC
node --test
#+END_SRC

~node tools/roundtrip-corpus.mjs DIR~ checks that every ~.org~ file in a directory comes back byte for byte after an open and save with no edit.

One test checks that every module the app imports is in the service worker's precache list, because nothing is cached at runtime and a missing module would stop the app starting offline.

*Code layout*: ~app.js~ is the entry point (about 1,400 lines): it imports everything, sets up the shared state, wires event listeners and runs ~bootstrap~. Features live in ~src-browser/~, one module per area. All runtime state is one object, ~S~, in ~app-state.js~, and the page's DOM elements are looked up once in ~dom.js~. The split is by file rather than decoupled (modules call each other, so the import graph has cycles), and browser modules need a DOM, so Node can't import them. ~test/module-structure.test.js~ and ~tools/check-scope.mjs~, a scope analysis that needs the acorn and eslint-scope parsers installed once (~npm install --prefix /tmp/acorn acorn eslint-scope~), keep the structure from decaying.

*Browser smoke test*: it covers what unit tests can't reach, since ~app.js~ is UI wiring:

#+BEGIN_SRC
node tools/smoke.mjs             # everything
node tools/smoke.mjs conflict    # only checks whose name contains "conflict"
SMOKE_SLICE=0:27 node tools/smoke.mjs    # only the first 27 checks; 27: runs the rest
#+END_SRC

It drives the real app in headless Chromium through flows that have broken before, against a built-in static server and a small in-memory WebDAV server. It is dev-only, adds nothing to ~package.json~, needs Playwright and a Chromium once (~npm install -g playwright && npx playwright install chromium~, or set ~CHROMIUM_PATH~), and exits non-zero on any failure.

~test/testing.org~ holds an older record of the testing approach and is no longer maintained.
