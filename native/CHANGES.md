# Native hardening (shell 0.7.11, for web v672 and later)

- **0.7.11.** `AttachmentsPlugin.list` lists the chosen folder itself (an empty path used to return nothing), returns folders as well as files, and gives each file's size and modified time. It still returns `names` (the files) for older web code, and adds `entries`: `{ name, dir, size, modified }`. `native-platform.js` turns them into `{ name, path, type, size, modified }`, which the web app's Files view shows and sorts by; a shell older than 0.7.11 still works, with names only. Not compiled here (no Android SDK).

- **0.7.10.** `MainActivity.java` removes `CapacitorHttpAndroidInterface` and `CapacitorCookiesAndroidInterface` after the bridge is built (the app uses neither plugin, and Capacitor's script only uses them when present), so the sandbox page for source blocks no longer gets them. On a WebView that cannot do the main-frame-only message listener (`WEB_MESSAGE_LISTENER`) the app shows "needs a newer Android System WebView" instead of running on the bridge every frame can reach. `build.gradle` adds `androidx.webkit` directly (for `WebViewFeature`). The workflow's actions are pinned to commit SHAs. Not compiled here (no Android SDK).

- **Size caps.** `Limits.java` (new). Every read, write, copy, view, save and pick takes an optional `maxBytes`; nothing goes above 100 MB. Over the cap, the call rejects with "too large: X is over the limit of Y" before the bytes move (size known), or while copying (size unknown). Partial copies are deleted.
- **Attachments.** Streaming base64 on read. `link` and `removeSource` accept only an address the picker handed out (`KeptPicks.java`, new) and, for `link`, only outside the picked tree. Paths with `..`, `.`, empty parts, backslashes or control characters are refused (`isPlainPath`).
- **File names.** `safeFileName` for cache copies, viewer files and Downloads names.
- **Backup.** `allowBackup="false"` plus `data_extraction_rules.xml` and `backup_rules.xml` (nothing is backed up or transferred).
- **FileProvider.** `file_paths.xml` shares only `cache/captures/` and `cache/opened/` (the external-storage root and the whole cache are no longer shared).
- **Release build.** `signing.gradle` signs the release type with the stable key; the workflow builds `assembleRelease` and now fails, naming the missing secrets, when the key secrets are absent or the key does not open (tick `allow_one_off` on a manual run for a throwaway debug APK). `lintVitalRelease` is skipped so an unrelated lint finding does not stop the build.
- **JS.** `native-platform.js`: `readBinary(path, {maxBytes})` (a number also works; over the limit it resolves `{tooLarge: true, bytes}` without data, and with no `maxBytes` the 100 MB cap rejects "too large: ..."), `writeBinary(path, base64, maxBytes)`, `localFiles.adapter.read(id, {prompt, maxBytes})`, `write(id, content, {maxBytes})`, `viewFile(blob, name, {maxBytes})`, `pickFile(kind, {keep, maxBytes})`, `saveFile(name, content, mime, {maxBytes})`. Other "too large:" rejections arrive as Errors (`tooLarge: true`, `bytes` when known). The native message is "too large:<bytes>: <sentence>".

Not compiled here (no Android SDK).
