#+TITLE: Diary file support in org-pwa: scope and design
#+STARTUP: overview

* Summary
Emacs's Org agenda can read the Emacs diary file when ~org-agenda-include-diary~ is ~t~. The file holds plain lines such as ~4/30  Results for April are due~, ~*/25  Monthly cycle~ or ~Friday  Back up files~, and sexp lines (~%%(diary-float 11 4 4) Thanksgiving~). org-pwa reads sexp lines already, in Org files, but has no diary file, so plain date lines show nothing.

This note scopes a feature that reads a diary file the way Emacs does: the same variables, the same date forms, the same rules for which lines match a day, and the same result in the agenda. It records how Emacs behaves (checked by running Emacs 29.3), what has to be built, how to prove it matches Emacs, and the decisions that are yours to make.

Status: steps 1 to 3 shipped in v565 and are proven against Emacs 29.3 on twelve sample diaries, in both row modes. Opening, adding and deleting entries (step 4) shipped with the Text view work described in [[file:text-editor-and-diary-design.org][text-editor-and-diary-design.org]]. Hebrew, Islamic and Bahá'í entries and holidays are not built; they have a design of their own.

Size: a medium project in four steps. The core (steps 1 and 2) is a parser and a matcher plus agenda integration. Everything is testable against Emacs, which is how the other diary features were checked.

* Goals and non-goals
** Goals
- A diary file named by the Emacs variable ~diary-file~, read when ~org-agenda-include-diary~ is ~t~.
- Plain date lines and sexp lines, in the date order of ~calendar-date-style~ (american, european or iso), with Emacs's own date forms.
- Entries show in the Agenda (day, week, month) under the category Diary, with a time of day when the entry has one.
- The same text of an entry as Emacs would show, including continuation lines.
- Behaviour proved against Emacs on a set of sample diary files, not just argued.
** Non-goals (for now)
- Non-Gregorian entries: Hebrew (~H~ prefix), Islamic (~I~), Bahá'í (~B~), and the other calendars.
- The Emacs calendar window, diary marks and faces, mailing the diary, and the appointment reminder (~appt~) setup. Timed entries will, however, feed the app's existing reminders if you want them to.
- Holidays beyond the US and Christian list already in the app.

* How Emacs does it (checked on Emacs 29.3)
The behaviour below is what the oracle runs showed; the rules are in ~diary-lib.el~ and ~org-agenda.el~.

** The file
- A plain text file (default ~~/diary~, variable ~diary-file~). No headings. Lines are read one at a time.
- An entry starts at the left edge of a line with a date. The rest of the line, and any following *indented* lines, are the entry text. A line that does not start with a date and is not indented is ignored (so notes and blank lines are harmless).
- A leading ~&~ (~diary-nonmarking-symbol~) makes an entry non-marking. It matters for the Emacs calendar window only; in the agenda the entry still shows (checked: ~&12/24  Non-marking entry~ appears on 24 December).
- A line starting ~%%(~ (~diary-sexp-entry-symbol~) is a sexp entry. It is the case the app already handles in Org files.
- Matching ignores case. Month names match in full or as a three-letter abbreviation with an optional dot (~apr.~, ~April~, ~APR~). Day names match the same way (~fri.~, ~Friday~).
- ~*~ stands for any value: ~*/25~ is the 25th of every month, ~4/*~ is every day in April.
- Leading zeros are allowed (~04/05~). A two-digit year matches a four-digit one when ~diary-abbreviated-year-flag~ is ~t~ (the default): ~4/20/27~ is 20 April 2027.
- A date line followed by no text at all on that line, and whose next line is not indented, is not an entry.

** The date forms
Which written shapes count as a date depends on ~calendar-date-style~. These are Emacs's own lists:

| Style | Shapes recognised |
|-------+-------------------|
| american | ~M/D~ · ~M/D/Y~ · ~Monthname D~ · ~Monthname D, Y~ · ~Dayname~ |
| european | ~D/M~ · ~D/M/Y~ · ~D Monthname~ · ~D Monthname Y~ · ~Dayname~ |
| iso | ~M-D~ (or ~M/D~) · ~Y-M-D~ (or ~Y/M/D~) · ~Monthname D~ · ~Y Monthname D~ · ~Dayname~ |

The shapes are tried in that order, and the lines are scanned in file order for each. A user may replace the list with the variable ~diary-date-forms~, which is why the matcher should be built from the forms, not hard-coded.

Written out, the lists are (Emacs's ~diary-american-date-forms~, ~diary-european-date-forms~ and ~diary-iso-date-forms~):

#+begin_example
american  (month "/" day "[^/0-9]") (month "/" day "/" year "[^0-9]")
          (monthname " *" day "[^,0-9]") (monthname " *" day ", *" year "[^0-9]") (dayname "\\W")
european  (day "/" month "[^/0-9]") (day "/" month "/" year "[^0-9]")
          (backup day " *" monthname "\\W+\\<\\([^*0-9]\\|\\([0-9]+[:aApP]\\)\\)")
          (day " *" monthname " *" year "[^0-9:aApP]") (dayname "\\W")
iso       (month "[-/]" day "[^-/0-9]") (year "[-/]" month "[-/]" day "[^0-9]")
          (monthname " *" day "[^-0-9]") (year " *" monthname " *" day "[^0-9]") (dayname "\\W")
#+end_example

Setting ~calendar-date-style~ with a plain ~setq~ does not change ~diary-date-forms~ in Emacs; ~calendar-set-date-style~ does. The app follows the second: the style picks the list, and ~diary-date-forms~ replaces it only when it is set.

Emacs reads the diary with its own syntax table, in which ~*~ and ~:~ are word characters. That decides what ~\W~ and ~\<~ in the forms mean, and it is why ~4 mar 10:30am Coffee~ keeps its ~10:~ in the European style. The matcher reproduces it.

The shapes carry their own punctuation rules. For example, american ~M/D~ must not be followed by another digit or ~/~, which is why ~4/30  text~ matches April 30 but ~4/30/27 text~ is a different shape.

** What the Org agenda does with the entries
For each day, Org asks the diary for that day's entries and shows each as an agenda line:
- Category ~Diary~.
- A time of day is taken from the start of the entry (~9:30am~, ~10:00-11:00~, ~14:00~), which puts the line in the time column and the time grid.
- Continuation lines are joined to the entry with ~; ~ (checked: ~10:00am Brunch~ with an indented ~at Mom's~ becomes ~10:00am Brunch; at Mom's~).
- *Holidays* appear too: a day with Christmas shows ~Christmas~ in the Diary lines. (Holidays come from ~calendar-holidays~, whose default includes more than the US and Christian lists.)
- The order within a day: sexp entries first (~diary-list-sexp-entries~), then each date form in turn, each in file order, unless ~diary-sort-entries~ is added to ~diary-list-entries-hook~, which sorts by time and then by text (an entry with no time sorts first).
- *Two quirks of Org's own display*: entries that do not start with a time are merged into the line before them with ~; ~, so two untimed entries on one day can show as one row; and a day with holidays prints the holiday and the first entry together. This is a side effect of how Org reads the diary's display buffer rather than a rule anyone wrote down.
- ~#include "other-file"~ lines are *not* followed unless ~diary-include-other-diary-files~ is added to ~diary-list-entries-hook~ (checked: an included entry did not show without it).

* What org-pwa has
- Sexp lines work in Org file bodies, in headings (~<%%(...)>~) and in the diary file, through one evaluator verified against Emacs.
- The diary file (~diary-file~, with ~org-agenda-include-diary~) is read from GitHub, WebDAV or a local file and shown in the Agenda under the category Diary, with the day's holidays, times of day, ~#include~ and sorting.
- Each Agenda row knows the file and lines it came from, so a tap can open the entry.
- A file that is not Org (the diary is the first) opens in Text view only, with coloring for the diary's syntax. Opening, adding and deleting entries, Check this line and the date picker are there.
- Not there: Hebrew, Islamic and Bahá'í dates, and the holidays beyond the US and Christian lists.

* Design
** Variables (Emacs's names, as Local or Global Variables)
| Variable | Default | Meaning |
|----------+---------+---------|
| ~org-agenda-include-diary~ | ~nil~ | ~t~ adds the diary to the Agenda (as Emacs does). |
| ~diary-file~ | unset | The file, in the app's file syntax: ~github:diary~, ~webdav:diary~ or ~local:diary~. |
| ~calendar-date-style~ | ~american~ | Already exists; now also sets the plain date forms, as ~calendar-set-date-style~ does. |
| ~diary-date-forms~ | from the style | Optional override, in Emacs's own syntax (a Lisp list of lists, read but not evaluated). |
| ~diary-show-holidays-flag~ | ~t~ | Whether the day's holidays are listed with its entries. |
| ~diary-abbreviated-year-flag~ | ~t~ | Two-digit years match. |
| ~diary-nonmarking-symbol~ | ~"&"~ | Entry prefix that is ignored. |
| ~diary-list-entries-hook~ | unset | Names ~diary-include-other-diary-files~ and ~diary-sort-entries~ turn on those two behaviours, as in Emacs. |

Every setting has an Emacs name except one: ~org-xx-diary-merge-rows~ (default ~nil~). By default each entry is its own row, with its continuation lines joined by ~; ~. Set to ~t~, the day is shown as Org shows it: an entry that is indented and does not start with a time is joined into the row before it, holidays and sexp text start rows of their own. Both modes are checked against Emacs.

** Parser
There is no separate parser: an entry is found on demand, for one day, by ~datedEntriesAt~, which returns the entry's lines, the lines of the file it occupies and the date form that matched. A date alone on a line is not an entry, and an entry may begin on the next, indented line. ~sexpEntriesAt~ does the same for ~%%(…)~ lines.

** Matcher
For a day, build the same regular expressions Emacs builds. The date forms are Lisp lists; each form is turned into a pattern with the day's month, day, year, month name and day name substituted (with the ~*~ and leading-zero alternatives), exactly as in ~diary-list-entries-2~. The pattern is an Emacs regexp, so the existing ~emacsRegexToJs~ converter does the work. Each form is searched over the whole text, as Emacs does, so a day costs one search per form. The word-syntax difference (~*~ and ~:~ as word characters) is applied when the pattern is converted.

Doing it this way, rather than writing a smarter parser, is deliberate: it reproduces Emacs's quirks (the "next character must not be a digit" rules, the backup form for ~30 apr~) without anyone having to rediscover them.

** Agenda integration
- The diary file is loaded like an agenda file, as text. When it is open in a tab the Agenda uses the open text, with unsaved edits; saving it reads the file again.
- Each match becomes an agenda item of the kind ~diary-sexp~, with category ~Diary~, the entry text with continuation lines joined by ~; ~, and a start time when Org would find one (~org-get-time-of-day~ reads the first time anywhere in the text: ~10:00am~, ~9pm~, ~9:30pm-10pm~; it ignores ~1130~ and ~7~).
- Sexp lines in the diary file go through the evaluator that exists.
- With ~org-agenda-include-diary~ ~t~ the day's holidays are added from the app's holiday list.
- The Agenda (day, week, month) uses it; the TODO view does not, matching Emacs.

** Where the settings go
In Settings, the four switches (~org-agenda-include-diary~, ~diary-show-holidays-flag~, ~diary-abbreviated-year-flag~, ~org-xx-diary-merge-rows~) are at the end of the Agenda section, and the three raw ones (~diary-file~, ~diary-list-entries-hook~, ~diary-date-forms~) at the end of Advanced (raw syntax). Nothing existing moved.

** Tests and proof
- A tool, ~tools/gen-diary-oracle.mjs~, runs ~org-get-entries-from-diary~ in Emacs on a set of sample diary files, for every day of a range, in all three date styles, and writes the expected lines to a fixture. A test then runs the same files through the app. This is the method used for the sexp functions and the filters.
- Sample files cover each date form, wildcards, abbreviations, leading zeros, two-digit years, continuation lines, timed entries, sexp entries, ~&~ lines, ~#include~ and the sort hook.
- Where the app deliberately differs (see decisions), the fixture records Emacs's answer and the test names the difference.

* Risks and open points
- *File format.* A diary is plain text, not Org. Files that are not named ~.org~ now open in Text view only, so the diary is edited as text.
- *iOS and ~local:~.* A local diary file inherits the limits of local files (read-only, permission prompts, and no persistent handle on iOS). A GitHub or WebDAV diary file avoids that.
- *Holidays and other calendars.* Emacs shows its full default holiday list in these lines, and reads ~H~, ~I~ and ~B~ date entries; the app has the US and Christian list and no other calendars. Planned as modules loaded when the diary or the holiday groups need them.
- *Performance.* Emacs scans the file once per day per date form. A month view of a 1,000-line diary is about 150,000 line tests; patterns are compiled once and lines are cheap, so this should be fast, but it is measured in step 1 before anything is built on it.
- *Time zones.* Not involved for plain entries.
- *Emacs's merge quirk.* See the first decision.

* Decisions (settled)
1. *Rows.* One row per entry by default; ~org-xx-diary-merge-rows~ gives Org's joined rows.
2. *Holidays.* Listed with the entries, as Emacs does, controlled by ~diary-show-holidays-flag~.
3. *Editing.* Not read-only after all: the diary opens in Text view, and entries can be added, deleted and checked.
4. *Settings.* At the end of Agenda and of Advanced (raw syntax), not in Contacts & Calendar.
5. *Hebrew and Islamic entries.* Show nothing for now; a separate design covers them.
