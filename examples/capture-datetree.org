#+TITLE: Capture into a date tree
#+STARTUP: showall

A cookbook for journals. Each section shows the file before, the template, and the file after org-capture files it. The results are what Emacs 29.3 (Org 9.6.15) produced, and a test holds the app to them. The template is written the way it goes in the Lisp init (=org-xx-lisp-init=), and in the Capture Templates setting as JSON.

* A new day tree
A file+olp+datetree target files under the year, the month and the day of the capture. Headings that are not there yet are made: the year, the month with its name, and the day with its weekday. Here the file is empty.

Captured on 2026-11-07 Saturday.

Template, in the Lisp init:
#+BEGIN_SRC emacs-lisp
(add-to-list 'org-capture-templates
  '("j" "Journal" entry (file+olp+datetree "journal.org") "* Walked the dog"))
#+END_SRC

The same template in Capture Templates:
#+BEGIN_SRC json
{
  "key": "j",
  "description": "Journal",
  "type": "entry",
  "file": "journal.org",
  "olp": [],
  "datetree": true,
  "template": "* Walked the dog"
}
#+END_SRC

Before, journal.org:
#+BEGIN_SRC org
,#+TITLE: Journal
#+END_SRC

After, journal.org:
#+BEGIN_SRC org
,#+TITLE: Journal
,* 2026
,** 2026-11 November
,*** 2026-11-07 Saturday
,**** Walked the dog
#+END_SRC

* A week tree
=:tree-type week= keeps the days of an ISO week under a heading for the week. 2024-12-30 is a Monday in the first week of 2025, so it goes under the year 2025.

Captured on 2024-12-30 Monday.

Template, in the Lisp init:
#+BEGIN_SRC emacs-lisp
(add-to-list 'org-capture-templates
  '("j" "Journal" entry (file+olp+datetree "journal.org") "* Walked the dog" :tree-type week))
#+END_SRC

The same template in Capture Templates:
#+BEGIN_SRC json
{
  "key": "j",
  "description": "Journal",
  "type": "entry",
  "file": "journal.org",
  "olp": [],
  "datetree": true,
  "treeType": "week",
  "template": "* Walked the dog"
}
#+END_SRC

,#+TITLE: Journal
#+END_SRC

After, journal.org:

,**** Walked the dog

* Where the app differs from Emacs
=:time-prompt t= (asking for the date) is not read, and neither is =file+olp+datetree= with =:tree-type= given as a function or a list of levels: those need Org 9.8, and a message says so when the Capture list opens. The app leaves the end of a file as it was, where Emacs adds a final newline to a file that lacked one.
