Settings that shape the rows of the Agenda: what comes before each heading, the order of the rows, a priority of your own, a Lisp function as a command, how many days show and where they start, finished entries, the log, stuck projects, and commands made of blocks with settings, headers and files of their own. This file is its own sample: the four entries just below are the ones every section lists, for Monday 15 March 2027. Put a setting in Settings → Advanced → *Lisp init*, open this file as an Agenda File, and compare the rows with the ones under each section. The rows are what Emacs 29.3 (Org 9.6.15) showed, and a test in this project checks that the app shows the same. The last section says where the two differ.

* TODO [#A] Alpha deploy :ops:

:PROPERTIES:

:WEIGHT: 3
:END:

:PROPERTIES:

* The default rows
With nothing set, a row is the category, the time, whether it is scheduled or due, then the heading. Rows go by time of day, then priority, then the order in the file.

#+begin_src emacs-lisp
(setq org-agenda-prefix-format '((agenda . "  %-12:c%?-12t% s")))
#+end_src

#+NAME: default
#+begin_example
  work:        9:00...... Scheduled:  TODO [#A] Alpha deploy :ops:
  work:       11:00...... TODO [#B] Delta call
  work:       Scheduled:  TODO Bravo review
  work:       Deadline:   NEXT [#C] Charlie cleanup :home:
#+end_example

* What comes before each heading
=org-agenda-prefix-format= is a format string per view. =%c= is the category (=%-8:c= pads it to 8 and adds the colon), =%t= the time, =%s= the scheduling word, =%e= the effort. A =?= makes the part disappear when it is empty.

#+begin_src emacs-lisp
(setq org-agenda-prefix-format '((agenda . "%-8:c %?-12t %e ")))
#+end_src

#+NAME: prefix-short
#+begin_example
work:     9:00......  2:00 TODO [#A] Alpha deploy :ops:
work:    11:00......   TODO [#B] Delta call
work:      TODO Bravo review
work:      NEXT [#C] Charlie cleanup :home:
#+end_example

* A Lisp form in the prefix
=%(form)= is evaluated for each row, with =category=, =time=, =level=, =effort= and =tag= set to that row's values; what it returns takes the place of the form.

#+begin_src emacs-lisp
(setq org-agenda-prefix-format '((agenda . "%(upcase category) %(concat \"<\" (substring category 0 1) \">\") ")))
#+end_src

#+NAME: prefix-lisp
#+begin_example
WORK <w> TODO [#A] Alpha deploy :ops:
WORK <w> TODO [#B] Delta call
WORK <w> TODO Bravo review
WORK <w> NEXT [#C] Charlie cleanup :home:
#+end_example

* A format that is a plain string
The value may also be one string, used for every view. Emacs reads it as a Lisp string, so =\"= is a quote mark and =\\= a backslash. The time is =%t=: a one-digit hour has a space before it.

#+begin_src emacs-lisp
(setq org-agenda-prefix-format "%-6c \"%t\"%s ")
#+end_src

#+NAME: prefix-string
#+begin_example
work   " 9:00......"Scheduled:  TODO [#A] Alpha deploy :ops:
work   "11:00......" TODO [#B] Delta call
work   ""Scheduled:  TODO Bravo review
work   ""Deadline:   NEXT [#C] Charlie cleanup :home:
#+end_example

* A form that fails
When a =%(form)= fails, the Agenda stops and shows the error in place of the rows.

#+begin_src emacs-lisp
(setq org-agenda-prefix-format '((agenda . "%(no-such-function category) %c")))
#+end_src

#+NAME: prefix-error
#+begin_example
Symbol's function definition is void: no-such-function
#+end_example

* A value that cannot be used
A value of the wrong kind stops the Agenda with a message. =org-deadline-warning-days= is a number of days; here it is the symbol =soon=.

#+begin_src emacs-lisp
(setq org-agenda-prefix-format '((agenda . "  %-12:c%?-12t% s")))
(setq org-deadline-warning-days 'soon)
#+end_src

#+NAME: unusable-value
#+begin_example
Wrong type argument: number-or-marker-p, soon
#+end_example

* The order of the rows
=org-agenda-sorting-strategy= lists the keys to sort by, per view. Here the highest priority comes first and the rest keep their order in the file.

#+begin_src emacs-lisp
(setq org-agenda-prefix-format '((agenda . "  %-12:c%?-12t% s")))
(setq org-agenda-sorting-strategy '((agenda priority-down category-keep)))
#+end_src

#+NAME: sort-priority
#+begin_example
  work:        9:00...... Scheduled:  TODO [#A] Alpha deploy :ops:
  work:       Scheduled:  TODO Bravo review
  work:       11:00...... TODO [#B] Delta call
  work:       Deadline:   NEXT [#C] Charlie cleanup :home:
#+end_example

* Sorting by your own rule
=user-defined-up= and =user-defined-down= sort by =org-agenda-cmp-user-defined=, a function of two agenda lines. It returns =-1= to put the first line first, =1= to put it second, or =nil= for no opinion. This one puts the rows tagged =ops= first.

#+begin_src emacs-lisp
(setq org-agenda-prefix-format '((agenda . "  %-12:c%?-12t% s")))
(setq org-agenda-sorting-strategy '((agenda user-defined-up)))
(setq org-agenda-cmp-user-defined (lambda (a b) (cond ((string-match-p ":ops:" a) -1) ((string-match-p ":ops:" b) 1))))
#+end_src

#+NAME: sort-user
#+begin_example
  work:        9:00...... Scheduled:  TODO [#A] Alpha deploy :ops:
  work:       Deadline:   NEXT [#C] Charlie cleanup :home:
  work:       Scheduled:  TODO Bravo review
  work:       11:00...... TODO [#B] Delta call
#+end_example

* A priority of your own
=org-priority-get-priority-function= gives the priority number of a heading, from its text, instead of the letter. It runs with the cursor on the heading, so it can read a property. Here the =WEIGHT= property is the number. A scheduled or due entry still adds its own part to the number, as it does to a letter's.

#+begin_src emacs-lisp
(setq org-agenda-prefix-format '((agenda . "  %-12:c%?-12t% s")))
(setq org-agenda-sorting-strategy '((agenda priority-down)))
(setq org-priority-get-priority-function (lambda (headline) (string-to-number (or (org-entry-get nil "WEIGHT") "0"))))
#+end_src

#+NAME: priority-function
#+begin_example
  work:        9:00...... Scheduled:  TODO [#A] Alpha deploy :ops:
  work:       Scheduled:  TODO Bravo review
  work:       Deadline:   NEXT [#C] Charlie cleanup :home:
  work:       11:00...... TODO [#B] Delta call
#+end_example

* Keyword search shows the heading only
A Keyword search finds an entry by its text, not only its heading. The query below is the word in the text of Bravo, written as a regular expression in braces. It finds Bravo, and the row shows the heading alone.

The query is ={bud[g]et}=.

#+NAME: search
#+begin_example

#+end_example

* Match shows the heading only
The Match query =ops|home= lists the entries with either tag.

The query is =ops|home=.

#+NAME: match
#+begin_example

#+end_example

* A function as a command
In =org-agenda-custom-commands=, a command whose type is a function calls it with the command's match string. What the function prints is the result; what it returns is not shown.

#+begin_src emacs-lisp
(setq org-agenda-custom-commands '(("x" "Mine" (lambda (match) (princ (format "Report for %s\n" match)) (princ "second line\n") "a result that is not shown") "ops")))
#+end_src

#+NAME: function-command
#+begin_example
Report for ops
second line
#+end_example

* The days shown: org-agenda-span
=org-agenda-span= is the number of days the Agenda shows: =day=, =week=, =month=, =year= (a symbol) or a number. A week starts on the day of =org-agenda-start-on-weekday= (1 is Monday; =nil= starts today). Each day has a heading, and the first day of a week carries the week number.

#+begin_src emacs-lisp
(setq org-agenda-span 'week)
(setq org-agenda-start-on-weekday 1)
#+end_src

* Where the days start: org-agenda-start-day
=org-agenda-start-day= is the first day shown: a date, or an offset from today such as ="+1d"=. With a number of days as the span, the Agenda begins there and does not look for a weekday.

#+begin_src emacs-lisp
(setq org-agenda-span 3)
(setq org-agenda-start-day "2027-03-17")
#+end_src

* Hiding finished entries
=org-agenda-skip-scheduled-if-done= leaves out an entry that is done even though it still has a scheduled date; =org-agenda-skip-deadline-if-done= does the same for deadlines. Emacs also lists the scheduled date of a done entry as a plain timestamp, which =org-agenda-skip-timestamp-if-done= leaves out. With both set, Ship release is no longer listed on Tuesday.

#+begin_src emacs-lisp
(setq org-agenda-span 'week)
(setq org-agenda-start-on-weekday 1)
(setq org-agenda-skip-scheduled-if-done t)
(setq org-agenda-skip-timestamp-if-done t)
#+end_src

* Stuck projects
=org-stuck-projects= says what a project is and what makes it not stuck: a matcher for the projects, TODO keywords or tags a next action carries, and a regular expression. A project with none of those under it is stuck. Website has a NEXT entry, Garden does not.

#+begin_src emacs-lisp
(setq org-stuck-projects '("+LEVEL=1+project" ("NEXT") nil ""))
#+end_src

#+NAME: stuck
#+begin_example
  work:       Garden :project:
#+end_example

* A stuck command with its own setting
A `stuck` command takes settings of its own after its description, and they apply to that command only. Here =org-stuck-projects= counts a project as stuck unless a child is NEXT or TODO, so Website, whose only child is NEXT, is stuck and Garden, with a TODO child, is not. The heading is Emacs's own.

#+begin_src emacs-lisp
(setq org-agenda-custom-commands
      '(("x" "Stuck" stuck "" ((org-stuck-projects '("+LEVEL=1+project" ("TODO") nil ""))))))
#+end_src

#+NAME: command-stuck
#+begin_example
List of stuck projects:
  work:       Website :project:
#+end_example

* An agenda command with its own settings
An `agenda` command can set =org-agenda-span=, =org-agenda-start-day=, =org-deadline-warning-days=, =org-agenda-prefix-format= and the rest for itself: they go over the variables while the command runs. This one shows three days from Tuesday. It opens as the text of the *Org Agenda* buffer, as Emacs makes it.

#+begin_src emacs-lisp
(setq org-agenda-custom-commands
      '(("x" "Three days" agenda "" ((org-agenda-span 3) (org-agenda-start-day "+1d")))))
#+end_src

#+NAME: command-agenda
#+begin_example
3 days-agenda (W11):
Tuesday    16 March 2027
  work:       DONE Ship release
Wednesday  17 March 2027
  work:       10:00...... Scheduled:  TODO Write report
Thursday   18 March 2027
#+end_example

* A composite command: blocks, headers and files
A command made of blocks shows each block under its own heading, with a line of `=` between blocks. The settings after the blocks are the whole command's and go over the variables for every block; a block's own settings come after that and go over those. =org-agenda-overriding-header= replaces a block's heading line, and =org-agenda-files= makes a block list those files only (here =other.org=). The agenda block shows its days, the todo block lists the TODO entries of the sample, and the last block lists the other file. In the app a file is written with its source, as =local:other.org=.

#+begin_src emacs-lisp
(setq org-agenda-custom-commands
      '(("x" "Day and lists"
         ((agenda "" ((org-agenda-span 'day) (org-agenda-overriding-header "Today")))
          (todo "NEXT" ((org-agenda-overriding-header "Next actions")))
          (tags-todo "garden" ((org-agenda-files '("other.org"))
                               (org-agenda-overriding-header "Garden, from the other file"))))
         ((org-agenda-prefix-format '((agenda . "  %-10c %?-12t") (todo . "  %-10c") (tags . "  %-10c")))))))
#+end_src

The file =other.org= is:

#+begin_src org
#+CATEGORY: home
* TODO Mow the lawn :garden:
SCHEDULED: <2027-03-16 Tue>
* TODO Call the plumber
#+end_src

#+NAME: command-block
#+begin_example
Today
Monday     15 March 2027 W11
  work       TODO Plan sprint

===============================================================================
Next actions
  work      NEXT Draft copy :project::

===============================================================================
Garden, from the other file
  home      TODO Mow the lawn :garden:
#+end_example

* Where the app differs from Emacs
Three things. With a value that cannot be used (the section above), Emacs stops with its own error text; the app says which variable holds the value and what it was, and skips what needed it, and a variable that is not set keeps its default. A file a command names with =org-agenda-files= is written with its source in the app (=local:other.org=, =github:...=, =webdav:...=), where Emacs takes a path. The lines Emacs puts under the heading of a single command ("Press ..." with its keys) are not shown, and the text of a command is not the interactive Agenda: it has no keys.
