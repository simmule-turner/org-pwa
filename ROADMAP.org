#+TITLE: org-pwa roadmap
#+STARTUP: overview

Where org-pwa still differs from Emacs org-mode, with a suggested priority. A is next, B follows, C waits for demand. Priorities rank how often the gap meets everyday use (agenda, diary, sync, capture), not effort. This is a plan, not a promise.

* Agenda and diary
** [#B] Refile and Replace into =local:= files from the web, and from GitHub or WebDAV documents
The Android app writes into =local:= agenda files while a local file is open. In a browser, and from a document on another backend, those files stay read-only: the browser asks for permission per file, and the other adapter doesn't know them. The diary file is read for the agenda in the same way; its rows are changed by opening it.
** [#B] More of =org-agenda-sorting-strategy= and =org-agenda-prefix-format=
Only the effort keys are sorted, and four prefix specs are known. The other keys (priority, time, category) and specs are what Emacs users carry in their configuration.
** [#B] =org-agenda-show-inherited-tags= values =always= and a list
Today it reads =t= or =nil=.
** [#B] =setq= and =defun= in the sexp evaluator
Lets a pasted Emacs diary entry run unchanged; today functions come from an Extensions script.
** [#C] Holidays for =org-class= beyond US and Christian
** [#C] Hebrew, Islamic and other non-Gregorian diary entries
