#+TITLE: org-pwa roadmap
#+STARTUP: overview

Where org-pwa still differs from Emacs org-mode, with a suggested priority. A is next, B follows, C waits for demand. Priorities rank how often the gap meets everyday use (agenda, diary, sync, capture), not effort. This is a plan, not a promise.

* Agenda and diary
** [#C] Refile and Replace into =local:= files from the web, and from GitHub or WebDAV documents
The Android app writes into =local:= agenda files while a local file is open. In a browser, and from a document on another backend, those files stay read-only: the browser asks for permission per file, and the other adapter doesn't know them. The diary file is read for the agenda in the same way; its rows are changed by opening it.
*** Design
- Org: nothing to match; refile writes to any file Emacs can reach. The gap is only that our target adapter is the open document's.
- Today: =writeToOtherFile= (buffers.js) writes through =activeDiskAdapter()=, the open document's backend, and opens the target as an unsaved tab buffer. =local:= entries are =readOnly= unless =localAgendaFilesWritable()= (Android folder and an open =filesystem= document).
- Change: (1) route a write by the target's scheme, not the open document's: =local:= goes to a local-file adapter, =github:= and =webdav:= to theirs. (2) Key each open session by (kind, fileId), so two files of the same name on different backends cannot meet. (3) In a browser, the first Refile or Replace into a =local:= file calls =requestPermission({mode:'readwrite'})= inside the tap, and remembers the handle. (4) Keep the transaction order: write the target first, remove the source only after it succeeded; on a failed write leave the source untouched and say which file refused.
- Edge cases: permission denied or revoked (keep read-only, show why); iOS and Firefox have no File System Access, so the entry stays read-only there and the panel says so; the target changed on disk since it was read (compare modified time, offer reload); the same file open in another tab.
- Tests: refile into each of the three backends with fake adapters; denied permission leaves both files unchanged; source removed only after target write; Android assertion in smoke stays.
- Questions: should a denied permission fall back to copying the subtree to the clipboard? Is a single "Allow writing" button in Settings (per file) better than asking at the tap?
- Effort: L (adapter routing is M; permission flow and session keys are the rest). Impact: M, mostly for people with a browser-only setup.
** [#C] The rest of =org-agenda-sorting-strategy= and the prefix
Not read yet: the =stats= and =user-defined= keys, the =tags= and =search= entries (the app has no view of those types), =%(function)= forms in =org-agenda-prefix-format=, and a Settings editor for the key list. When the variable is unset the rows keep the app's own order; Emacs's default (=habit-down time-up priority-down category-keep= for the Agenda, =priority-down category-keep= for TODO) would put priority first within a day.
** [#C] =setq= and =defun= in the sexp evaluator
Alone they add little: each diary entry is evaluated by itself, so a =defun= vanishes after it, and without loops =setq= is =let*= by another name. They matter together with the interpreter in [[#appendix-lisp][Appendix: a Lisp interpreter]], which also settles where shared definitions live.
** [#C] Holidays as Emacs's =holiday-*= lists: your own, and switching groups off
Today the app knows one fixed list, the US holidays of =holiday-general-holidays= plus the Christian ones (src/holidays.js). It feeds =org-class= (the symbol =holidays=), =calendar-check-holidays= and the holidays listed with the diary (=diary-show-holidays-flag=). There is no way to add a holiday, remove one, or turn a group off.
- Org and Emacs: the holidays are the variable =calendar-holidays=, built from the lists =holiday-general-holidays=, =holiday-local-holidays=, =holiday-other-holidays=, =holiday-christian-holidays=, =holiday-hebrew-holidays=, =holiday-islamic-holidays=, =holiday-bahai-holidays=, =holiday-oriental-holidays= and =holiday-solar-holidays=. Setting a list to =nil= switches that group off; a list holds forms such as =(holiday-fixed 10 31 "Halloween")=, =(holiday-float 11 4 4 "Thanksgiving")= (month, weekday with 0 = Sunday, the nth one, =-1= the last) and =(holiday-easter-etc 0 "Easter Sunday")=.
- Approach, in slices that each stand alone and need no Lisp interpreter:
  1. *A Lisp section in Settings (Advanced).* One place for Emacs configuration written in Lisp, the app's =init.el=: a text box where it is typed directly, and a list of files (=github:init.el=, =webdav:init-2.el=, =local:init-3.el=, written as =path:file; path:file=, as the other file lists are) loaded in order after the box, so a later file wins over an earlier one and over the box. It is read at start-up and again on the next refresh or reload, whichever comes first, and a *Reload* button on the section reads the box and the files at once. A form that fails is named in a message and skipped; the rest still load. The holiday lists are its first use: your =(setq holiday-local-holidays '(...))= goes here, exactly as written for Emacs. The section is the same one the appendix calls "shared definitions for the diary", so =defun= and the rest land in it later without a second place to configure.
  2. *Data first, interpreter later.* Until the interpreter exists the section understands =setq= (and =setq-default=) of the variables the app supports, with quoted data on the right, read by =src/lisp-read.js=. A holiday list is data of this kind, so a small evaluator for =holiday-fixed=, =holiday-float=, =holiday-easter-etc= and =holiday-sexp= turns it into dates. The built-in lists are written as the same data (the US and Christian ones first), so what the app ships and what you write are one mechanism. When the interpreter lands it takes over the same section and nothing the person wrote has to change.
  3. *=holiday-sexp= in the first version.* =(holiday-sexp SEXP STRING)= evaluates SEXP once a year with =year= bound; the result is a date, =(month day year)=, or nil, and STRING names it. It runs on the diary's sexp evaluator (=src/sexp-eval.js=) with =year= added, so it can use exactly the calendar functions that evaluator has; the rest of Emacs's =calendar-*= functions (for example =calendar-nth-named-day=) arrive with the stage 3 builtins, and a sexp that uses one that is missing is skipped with a message naming it. The holiday's name is a plain string in the first version; Emacs also accepts an expression there that uses =date=, which is added once it has been checked against Emacs.
  4. *Variables.* =holiday-local-holidays= and =holiday-other-holidays= hold your forms; each built-in group is read as =t= (Emacs's default) or =nil=. A group set to =nil= disappears from =org-class=, =calendar-check-holidays=, the diary and the Agenda. =calendar-holidays= itself may be set for full control.
  5. *No switches.* Groups are turned off in the Lisp section (=(setq holiday-hebrew-holidays nil)=), in the box or in a file, so there is one way and nothing to keep in step.
  6. *More groups*, cheapest first: the Hebrew, Islamic and Bahá'í calendars are date arithmetic and can be checked against Emacs exactly; the Chinese and solar groups need astronomy (solstices, moon phases, sunrise) and come last or not at all.
- Example of what the lists change: =%%(org-class 2026 9 1 2026 12 15 1 'holidays) Class meets= shows on every Monday from September 1 to December 15 except Mondays that are holidays. With the built-in lists those are Labor Day (September 7) and Columbus Day (October 12); a Monday holiday the person adds, such as one defined with =holiday-sexp=, is skipped too, and a group set to =nil= no longer causes a skip.
- Default: until a group exists in the app its variable has no effect, and the default stays what it is today (general and Christian). Emacs's full default adds the other groups, so the default widens as each lands, and the README says which groups are available.
- The check: for each group, each date of several years against =calendar-check-holidays= in Emacs 29.3, as for the diary sexps. The three forms get their own tests (the last weekday of a month, a floating holiday that falls on the fifth week, Easter offsets).
- Decided: the Lisp section is edited directly or read from files; a list of files after one box; changes are picked up on the next refresh, reload or start-up, and a *Reload* button reads them now.

* Appendix: a Lisp interpreter
:PROPERTIES:
:CUSTOM_ID: appendix-lisp
:END:

What it would take for small standalone programs to run, in the diary and in =emacs-lisp= Babel blocks. The diary evaluator stays as it is; the interpreter is a separate module (=src/elisp.js=), so nothing in the diary can regress. Each feature is marked *Lisp* (any Lisp has it) or *Emacs* (specific to Emacs Lisp, and what makes a program read as Emacs's).

** Stage 1: the language
| Feature | Kind | Why it is needed |
|---+---+---|
| Reader: symbols, ='x=, backquote and =,=, comments, floats, strings with escapes | Lisp (backquote and =?c= characters are Emacs-flavored) | Programs are text; today's reader handles numbers, strings and parentheses only |
| Lexical environments, =lambda=, =funcall=, =apply=, closures | Lisp | Functions as values |
| =defun=, =defvar=, =defconst=, =setq= | Lisp (=defvar= and =defconst= semantics are Emacs) | Named helpers and state |
| =while=, =dolist=, =dotimes= | =while= is Lisp; =dolist= and =dotimes= are Emacs (cl-style macros) | Loops; with =defun= they replace recursion |
| =cons=, =append=, =reverse=, =mapcar=, =push=, =nreverse=, =assoc=, =assq=, =delq=, =sort= | Lisp, except =push=, =assq= and =sort='s argument order, which are Emacs | Building and searching lists |
| =concat=, =substring=, =string=, =upcase=, =downcase=, =split-string=, =mapconcat=, =string-to-number=, =number-to-string= | Emacs (strings are an Emacs-Lisp data type with these names) | Text handling |
| =null=, =listp=, =stringp=, =numberp=, =symbolp=, =functionp= | Lisp | Type tests |
| =condition-case=, =error=, =signal=, =user-error= | Emacs (Common Lisp has a different system) | Errors that can be caught and read |
| =message=, =print=, =princ=, =prin1= | Emacs | Output, captured for a Babel block |
| =max-lisp-eval-depth= limit and a step budget | Emacs (the variable); the budget is this app's | Stops runaway programs with a message |

** Stage 2: Babel
| Feature | Kind | Notes |
|---+---+---|
| =emacs-lisp= source blocks run, result is the last value | Emacs | Printed with =prin1= rules, as Emacs prints it |
| =:var name=value= bound as variables | Org | Same as the =js= blocks |
| =:results=, =:wrap=, =:cache=, =:noweb= | Org | Shared with the =js= runner |
| Runs when =(emacs-lisp . t)= is in =org-babel-load-languages= | Org | That is already the default, so a stricter switch may be wanted |
| Worker sandbox, timeout, no I/O | App | Same sandbox as =js= blocks |

** Later: Emacs and Org specific
These need Emacs's own libraries and are not part of "small standalone programs":
- Buffer and Org functions: =org-map-entries=, =org-element-parse-buffer=, =org-entry-get=, =org-todo=.
- =format-time-string=, =decode-time=, =encode-time= and other time functions.
- =cl-lib= (=cl-loop=, =cl-defun=), =seq-*= and =string-*= libraries.
- Regular expressions the Emacs way (=string-match=, =re-search-forward=, match data).
- Files and network (=insert-file-contents=, =url-retrieve=): left out on purpose.

** Shared definitions for the diary
A section in Extensions for Lisp that runs once per session and defines functions that diary entries can call. This is what makes =defun= worth having in the diary.

** Order of work
1. The interpreter core (stage 1), as its own module, with tests against Emacs 29.3.
2. Move the diary evaluator (=src/sexp-eval.js=) onto it. The diary layer keeps the =date= binding, the diary and calendar functions as native builtins, and a tolerant mode in which a failing entry shows nothing, as today. The Emacs-checked sexp tests and the existing suite must pass unchanged. This replaces the hard-coded list of line forms with one reader, and gives diary entries real errors, =defun=, =setq= and loops.
3. The =calendar-*=, =holiday-fixed=, =holiday-float= and =holiday-easter-etc= functions as builtins, under Emacs's names.
4. Holidays as an editable =calendar-holidays= list, which also covers =org-class= beyond US and Christian holidays.
5. =emacs-lisp= source blocks in Babel (stage 2).
6. Shared definitions for the diary.

What stays in JavaScript: the calendar grid and its layout (UI, redrawn often), and the agenda's per-day effort total and =+N?= count (computed while drawing, with no Org equivalent). A hook the interpreter can call may be added to the latter later.

Emacs's own =calendar.el=, =holidays.el= and =solar.el= are not run: they need macros, =cl-lib=, =defcustom=, =require= and buffer functions. The library is written for this interpreter, under Emacs's function names.
