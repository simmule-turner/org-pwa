#+TITLE: org-pwa roadmap
#+STARTUP: overview

Where org-pwa still differs from Emacs org-mode, with a suggested priority. A is next, B follows, C waits for demand. Priorities rank how often the gap meets everyday use (agenda, diary, sync, capture), not effort. This is a plan, not a promise.

* Agenda and diary
** [#C] Refile and Replace into =local:= files from the web, and from GitHub or WebDAV documents
The Android app writes into =local:= agenda files while a local file is open. In a browser, and from a document on another backend, those files stay read-only: the browser asks for permission per file, and the other adapter doesn't know them. The diary file is read for the agenda in the same way; its rows are changed by opening it.
*** Design
- Org: nothing to match; refile writes to any file Emacs can reach. The gap is only that our target adapter is the open document's.
- Today: =writeToOtherFile= (buffers.js) writes through =activeDiskAdapter()=, the open document's backend, and opens the target as an unsaved tab buffer. =local:= entries are =readOnly= unless =localAgendaFilesWritable()= (Android folder and an open =filesystem= document).
- Change: (1) route a write by the target's scheme, not the open document's: =local:= goes to a local-file adapter, =github:= and =webdav:= to theirs. (2) Key each open session by (kind, fileId), so two files of the same name on different backends cannot meet. (3) In a browser, the first Refile or Replace into a =local:= file calls =requestPermission({mode:'readwrite'})= inside the tap, and remembers the handle. (4) Keep the transaction order: write the target first, remove the source only after it succeeded; on a failed write leave the source untouched and say which file refused.
- Edge cases: permission denied or revoked (keep read-only, show why); iOS and Firefox have no File System Access, so the entry stays read-only there and the panel says so; the target changed on disk since it was read (compare modified time, offer reload); the same file open in another tab.
- Tests: refile into each of the three backends with fake adapters; denied permission leaves both files unchanged; source removed only after target write; Android assertion in smoke stays.
- Questions: should a denied permission fall back to copying the subtree to the clipboard? Is a single "Allow writing" button in Settings (per file) better than asking at the tap?
- Effort: L (adapter routing is M; permission flow and session keys are the rest). Impact: M, mostly for people with a browser-only setup.
** [#C] More calendars in the diary
=diary-coptic-date=, =diary-ethiopic-date= and =diary-mayan-date= are plain arithmetic (S). =diary-persian-date= and =diary-french-date= need the equinox calculation, which the Chinese calendar's solar-term code now supplies (M). Hebrew, Islamic, Bahá'í, Chinese, Julian, ISO and astronomical day numbers are done.

** [#C] Clock issue faces and the *Org Agenda* text
=org-agenda-clock-consistency-checks= takes a face per kind of issue (=:default-face=, =:long-face=, =:short-face=, =:overlap-face=, =:gap-face=, =:no-end-time-face=); the Agenda view draws every issue white on dark red. Emacs's issue lines are overlays, so the =*Org Agenda*= text has none.
- Effort: S. Impact: S.

** [#C] MathJax markup and =#+HTML_MATHJAX= in HTML export
Emacs writes MathJax configuration and typesets math with MathJax; the app typesets with KaTeX, so the =#+HTML_MATHJAX:= options (path, scale, font, align, autonumber, linebreaks) have no effect. Org's =test-ox-html.el= is 43 tests of exactly these options.
- Benefit: HTML math as Emacs writes it, the options honored, and a wider LaTeX subset (more environments and packages than KaTeX).
- Cost, download: the release zip is 7.3 MB. MathJax 3 with its fonts is 1.2 MB of script plus 0.4 MB of fonts (CHTML output), or 2.1 MB of script alone (SVG output), against 0.55 MB for KaTeX with its fonts: +1.0 MB (+14%) or +1.5 MB (+21%) in the zip. Compressed on the wire the difference is about +0.3 MB. At 10 Mbit/s that is 1 s more for the zip (0.3 s on the wire); at 2 Mbit/s, 4 s (1.3 s).
- Cost, speed (320 formulas, one desktop core): KaTeX 68 ms, MathJax 390 ms (SVG) to 450 ms (CHTML), about 6 times slower per formula (0.2 ms against 1.3 ms); loading the library takes 18 ms against 70 ms. A phone is slower than this by a few times, so a document with 100 formulas costs roughly 20 ms with KaTeX and 130 ms or more with MathJax, then several times that on a phone.
- Cost, work: MathJax's modern API is asynchronous while the preview and the ODT export (formulas become MathML through KaTeX) call KaTeX synchronously; keeping both engines doubles the quirks to test, and moving all to MathJax needs the math fixtures regenerated.
- Cheaper option: keep KaTeX for the editor and ODT, honor the =#+HTML_MATHJAX:= keywords, and write Emacs's MathJax markup in exported HTML that loads MathJax when the page is opened online (the exported page then needs the network to typeset math).
- Effort: L. Impact: S.

* Org Crypt
** [#C] Decrypt an entry when it is revealed (=org-fold-reveal-start-hook=)
Emacs decrypts an encrypted entry when a command reveals it (a search hit, =org-reveal=, a jump from the agenda). Here the commands *Decrypt entry* and *Decrypt all crypt entries* do it; the reveal paths (search results, agenda jumps, links) would call the same decrypt after asking for the passphrase, which needs a passphrase prompt that does not interrupt a jump on a phone.
- Effort: M. Impact: S.

** [#C] Encrypt to =epa-file-encrypt-to=
When no key matches =org-crypt-key=, Emacs uses the recipients in the file-local variable =epa-file-encrypt-to= before falling back to a passphrase.
- Effort: S. Impact: S.

* Security
Left from the security reviews. Each is small, none lets a document run code without the "Run code?" prompt.
** [#C] Dev dependency advisory
=minimatch= (GHSA-g3hv-75wg-m249, denial of service) comes in through eslint, including the latest eslint 10; dev-only, no runtime code. Update when eslint releases a fix.
- Effort: S. Impact: S.

* Info and manuals
** [#C] Texinfo exporter
Export to =.texi= (nodes, menus, =@multitable=, =@footnote=) as the LaTeX exporter does, checked against Emacs's ox-texinfo. The hard part is node and menu generation. Worth doing if you write GNU-style manuals.
- Effort: L. Impact: S.
** [#C] Info reader leftovers
Differences from Emacs that remain: search does not look through the tag table's list of subfiles or the pseudo-nodes (=*TOC*=, =*History*= and the directory are screens here, not nodes), and Info-mode keys are not shown as palette hints because the palette test requires every hint to be a god-mode chord.
- Effort: S. Impact: S.

* Outline and editing commands
** [#C] Inline-task Tab folding
=org-inlinetask-toggle-visibility= (Tab on a task): a task folds to its first line, hiding its text and END line. It needs a fold state for a heading that has no children in the outline model. M-up and M-down also stop at plain paragraphs here, where Emacs drags past them.
- Effort: S. Impact: S.
** [#C] Top-level promotion
=org-allow-promoting-top-level-subtree= (promoting a level-1 heading currently refuses). Dragging a heading to move it still changes its level by one star under =org-odd-levels-only=.
- Effort: M. Impact: S.
** [#C] Sort locale, and indentation details
Locale collation for the alphabetic sort (it compares by character code, as the C locale does). Under =org-adapt-indentation= =headline-data= Emacs indents a log note one column further than this app does. =zsh=, =ksh=, =csh=, =htm=, =xhtml= and =svg= source is not colored.
- Effort: S. Impact: S.
** [#C] =org-entry-properties= details
The =pom= argument (the Lisp environment has no buffer positions to name an entry by) and the =CLOCKSUM= property (Emacs has it only after a clock sum has run in the buffer).
- Effort: S. Impact: S.
** [#C] Settings control for =org-blank-before-new-entry=
The variable is read from Global Variables (all three values work for headings and list items); a control needs a Settings pattern for alist values (two choices, one for headings and one for list items).
- Effort: S. Impact: S.
** [#C] Archive extras and blocking
BLOCKER and TRIGGER properties (org-edna and org-depend territory, not Org core), =org-toggle-ordered-property= (=C-c C-x o=), =org-toggle-archive-tag= (=C-c C-x a=) and direct archive on =C-c C-x C-s=.
- Effort: S. Impact: S.
** [#C] =org-num= and =org-protocol=
=org-num-mode= shows outline numbers beside headings; =org-protocol= needs operating-system integration, so it is only worth doing for a share-target flow on Android.
- Effort: M. Impact: S.

* Lists, parser and editor model
** [#C] Drawers and dynamic blocks as containers
The editor keeps the contents of a drawer (=:NAME:= ... =:END:=) or a dynamic block (=#+begin:= ... =#+end:=) as flat lines: the marker lines show as paragraph text and a source block inside =:LOGBOOK:= is not found. Make them parsed container nodes holding their paragraphs, tables and lists, as org-element does.
Checked against Emacs in v708: export, table formulas (including a second or detached =#+TBLFM:=) and Babel inside drawers and dynamic blocks already give Emacs's results, so the gain is only in the editor: drawer markers drawn as drawers, blocks in =:LOGBOOK:= that run, and a base for folding or commands on one drawer.
Cost: about 30 modules read these lines as flat paragraphs (search, query-replace, targets, link resolution, checkboxes, table commands); each must keep finding and editing text inside a drawer, and a miss fails silently. Do it as its own change, with before and after checks on search, replace and tables in drawers.
- Effort: L. Impact: S.
** [#C] table.el tables
The editor shows one verbatim paragraph and the exporters write it as written. Render it as a table-like block and convert it as Emacs's table package does.
- Effort: M. Impact: S.
** [#C] List leftovers
=org-list-send-item=, the join space when a link spans lines, and the three known list-command groups (sorting inside a drawer or example block, =C-u C-c C-c= over a subtree with a double-blank gap, =M-S-right= on a first item with a cookie).
- Effort: S. Impact: S.

* Dates and durations
** [#C] Timestamp commands without a text cursor
=S-up= and =S-down= on a timestamp and the =C-c .= family need a text cursor (Text view or the Date tool). Edit details has a "Move the date" stepper for SCHEDULED, DEADLINE and a plain timestamp; a timestamp in the middle of body text still needs the cursor, and the CLOCK-line variant of =C-S-up= is palette-only.
- Effort: S. Impact: S.
** [#C] Settings controls for date and duration variables
=org-duration-format= (a Lisp value, catalog-only), =org-clone-delete-id= (not exposed).
- Effort: S. Impact: S.

* Babel
** [#B] Detangle and jump
=org-babel-detangle= and =org-babel-tangle-jump-to-org= (tangled files carry =[[file:...]]= comment links back to the Org source).
- Effort: M. Impact: S.
** [#C] Babel leftovers

- Effort: M. Impact: S.

* Export
** [#C] More export variables
=org-export-select-tags=, =org-export-exclude-tags=, =org-export-creator-string=, =org-export-date-timestamp-format=; snippet shortcuts inside =#+TITLE:= and similar keywords.
- Effort: S. Impact: S.
** [#C] =#+INCLUDE= leftovers
Footnote relabeling, relative-link rewriting, =:coding= and URLs; missing files and failed searches are skipped where Emacs errors.
- Effort: M. Impact: S.
** [#C] =#+BIND:=, a Lisp backend API and org-cite processors
=#+BIND:= runs Lisp from a document, so it needs your approval before it is built. A backend API (define and derive your own exporter) and the org-cite processors beyond basic, bibtex, biblatex, csl and natbib are large and the app has its own extension mechanism.
- Effort: L. Impact: S.
** [#C] MathJax and ox-publish
KaTeX stands in for MathJax by decision; ox-publish needs a project model.
- Effort: L. Impact: S.

* Org lint
** [#C] Report buffer keys
=org-lint--show-source= (=TAB= and =C-j=) needs a second window; show the source in a sheet instead. =tabulated-list-sort= with a prefix of -1 (restore the original order) is not offered. A tap selects a report and a second tap jumps; the Line column's header sits in the buffer text rather than a header line.
- Effort: S. Impact: S.
** [#C] Parser objects the checkers need
The parser does not model inline tasks, radio links, timestamps, entities, LaTeX fragments, sub and superscripts or statistics cookies, so the checkers that use them are not covered. =wrong-header-value= skips Lisp-evaluated values; cite processors are fixed; loaded Babel languages default to emacs-lisp.
- Effort: M. Impact: S.

* Emacs mode
A separate mode, kept until the Text view is no longer needed, that looks and feels like Emacs: the Text view's textarea stays (so phones, IME and the device keyboard keep working) with Emacs's keys, kill ring, mark and look on top. Each stage is compared with Emacs 29.3 where it can be.
** [#B] Emacs mode: more keys
=M-y= (kill ring cycling), =C-x h= (mark the buffer), =C-x C-o=, =M-SPC=, =C-v= and =M-v=, =M-<= and =M-> with a prefix, a prefix for =C-t=, =M-t=, =C-x C-x=, =M-\\= and =M-m=, =C-?= (redo), undo within the region, =C-s= and =C-r= search, and the =C-c= prefix. Undoing a re-leveled =C-y= takes one step where Emacs takes several. Each is compared with Emacs 29.3 as the rest are.
- Effort: M. Impact: M.
** [#B] Emacs mode: minibuffer and buffers
Messages carry Emacs's words and go to a =*Messages*= buffer, =M-x= completes in the minibuffer (the panel gets =M-x= and =C-c= then), and =C-x b=, =C-x k=, =C-x C-b= switch, kill and list the open files (the tabs).
- Effort: M. Impact: M.
** [#B] Emacs mode: Org commands at the caret
=Tab= and =S-Tab= cycle visibility in the text, then the commands that act at point (=org-return=, =org-open-line=, =org-drag-element-*=, =S-up= and =S-down= on a timestamp, =C-c C-c= in context, =M-left= and =M-right= on the element at point). Supersedes "Cursor-text commands".
- Effort: M. Impact: M.
** [#C] Emacs mode: faces and window
Emacs's Org faces (=org-level-1= to =8=, =org-todo=, =org-done=, =org-table=, =org-link=), =org-ellipsis=, and optionally split windows (=C-x 2=, =C-x 3=, =C-x 0=, =C-x 1=).
- Effort: M. Impact: S.
* Probably not worth doing
** [#D] Unlikely extras from the Org manual
Four features from the compact Org guide that this app can do without; each is listed so you can decide whether any is worth a release.
- *Publishing* (=org-publish-project-alist=, =C-c C-e P=): builds a whole site from several files, with a project list, base directory, extensions, a publishing function and a timestamp cache that skips unchanged files. It makes sense when Emacs is the site generator and the files sit on a disk. Here the files are on GitHub or WebDAV and the browser cannot write a directory tree, so it would mean a zip of the result or a push to a branch. Worth it only if you publish a site from this app.
- *Agenda to appointments* (=org-agenda-to-appt=): the app already has appt.js for reminders of today's timed items while the app is open. What Emacs adds is the same list pushed into the =appt= daemon for a notification at warning times even when no agenda is open. A web page cannot run in the background, so what remains is a push or calendar-export route, which iCalendar export covers.
- *Pretty entities and LaTeX preview* (=C-c C-x \=, =org-latex-preview=): shows =\alpha= as the Greek letter and renders formulas as images. Entities and inline math already render in the outline through the page's own math layout; what is left is the toggle, the =org-pretty-entities= setting and a dvipng-style image for every fragment, which a browser does not need.
- *Time-stamp overlays* (=org-toggle-time-stamp-overlays=): swaps the stamp text for a short form in the outline. The app already shows stamps in their own style and format; a second look adds a setting and little else.
